## Integration — the audit's real yield

Per-phase verification cannot see cross-phase seams, and this is where it paid. Phase 50
archived `lv_icp_tier` and deleted WF1; phases 46–49 were all built while both existed.

**Confirmed wired:** two-engine parity (rebuild produced an empty git diff across all 8
workflow files), the hardware-vendor OR predicate present identically in both engines, the
`lv_anti_icp_flag_num` mirror derived once and serialized in the sole owning engine, the
on-demand recompute lane, and no production workflow writing `lv_icp_tier`.

**Found broken and fixed this audit** (commit `0e351e1`): four operator-facing scripts still
confirmed writes against the archived property. Because an archived HubSpot property returns
its frozen last value rather than erroring, each would have kept printing verdicts while
comparing dead data — `rescore_population.py` would have reported "settled" almost instantly
and rendered an identical tier census for every future run.

**Found and deferred:** seven further scripts read the property at lower severity, classified
in WINDOWS.md id 18 rather than blanket-renamed.

genuinely dangerous integration defect was found and fixed during this audit.

while `open_count > 0` when `workflow.windows_enforce` is on. Ids 9–12 and 14 are correctly
permanent; ids 17 and 18 are genuinely fixable and should be closed rather than waived.
