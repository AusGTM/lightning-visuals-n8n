## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| "Pre-existing / out of scope" asserted without checking | A subagent reported a failing test as a pre-existing, unrelated failure while sealing 57-05. `git log -S` showed **this phase wrote it one day earlier** (`3b3fcfb`). It would have sealed a phase with a red suite under a false label. | blocking | Before accepting any "pre-existing" claim, run `git log -S "<symbol>" -- <file>`. The claim is about history, so check history — never infer it from "this commit didn't touch the file". |
| A count check standing in for a membership check | Cycle 3's HIGH finding, introduced by this session's own cycle-2 fix: `split_for_allowance` cut work and grant scope on two independent orderings, so an interleaved id/domain batch could authorise different records than it dispatched. The consistency test passed because **both sides had one element**. | advisory | When two collections must describe the same thing, assert on MEMBERS, not cardinality — and pick a fixture where the wrong answer has the right count. |
| A read-back that looks for the wrong shape of evidence | Verifying the workflow deploy, a scan for stored `allow*`/`armed` booleans found none and nearly became "no write-safety flags found". These workflows gate writes through Code nodes reading a request-scoped allowlist; there are no stored booleans to find. Absence of the wrong evidence read as safety. | advisory | State what the evidence should look like BEFORE looking, and if you find nothing, first ask whether you were looking for the right shape. |
| Freezing a "now" claim into a literal | A test written 2026-08-31 hardcoded that date for rows whose entire premise was being "newer than the cutoff". It passed the day it was written and failed every day after. Fixed in `f072e09`. | advisory | Any fixture asserting a relationship to the present must COMPUTE the timestamp (`datetime.now(timezone.utc)`), never write it down. |
| A bare PUT read as a live deploy | `deploy_n8n_workflows.py:25` states activation is a separate runbook step. A PUT updates STORED content; the running workflow keeps executing the old definition until bounced. | advisory | After any workflow deploy, bounce (deactivate → activate) and re-read. A read-back before the bounce proves stored, never running. |
