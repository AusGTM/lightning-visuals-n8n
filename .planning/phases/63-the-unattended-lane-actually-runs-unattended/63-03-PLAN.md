<objective>
Build and run the offline replay that decides whether the cheaper judge model is adequate on the
`confidence_band`-only class (D-63-06), and record the `reasons[]` distribution the throughput todo
asks for as a by-product of doing so (D-63-07).

Purpose: `Judge Call` costs 16.1s of a 34.2s wall clock. The proposed saving is to adjudicate with
Haiku 4.5 when `confidence_band` is the ONLY reason and keep Sonnet 5 for everything veto-shaped.
That claim needs evidence before it ships, and the evidence has to be free of credits and n8n
executions because a single bulk run already halves the Lusha balance. Replaying stored judge
inputs through both models costs Anthropic tokens and nothing else.

The alternative — shipping behind a disagreement-trip guard — was explicitly rejected in D-63-06:
it establishes adequacy by assertion, the exact shape that cost Phase 62 a full gap-closure plan.

Output: `scripts/replay_judge_models.py`, its unit tests, and a committed verdict artifact that
63-04's checkpoint reads.

**Tracer note (TRACER_MODE):** Task 1 is 63-B's tracer — corpus extraction, both model calls, the
comparison and the report written end to end for a single input, with the model call injected so
the whole path is exercisable offline. Task 2 widens it to the real corpus. 63-A's tracer is 63-01
Task 1; the two halves are deliberately independent and neither `depends_on` the other.

**This plan does not change the workflow.** It writes no line of `scripts/build_cloud_workflows.py`
and regenerates no `n8n/wf_*.json`. That is 63-04's job, and only if this plan's verdict is SHIP —
which is what "the replay comes before the constant change" means in wave order.
</objective>

  <action>
Write `scripts/replay_judge_models.py` with a pure, offline-testable core and a thin live shell.

**Corpus extraction.** `extract_corpus(execution_ids=None, limit=...)` walks n8n executions via the
readers in `scripts/enrichment_cost_ledger.py` (`_list_executions`, `_get_execution` with
`includeData=true`, `_node_output_items`) and pulls, from each execution's `runData`, the output
items of the node named `Build Judge Request` (companies lane) and of `Build Contact Judge Request`
(contacts lane). Keep only items whose `judge_request_body` is non-null. For each kept item record:
a stable `input_id` of `"{execution_id}:{item_index}"`, the `lane` (`companies` or `contacts`), the
item's `judge_reasons` array, the `judge_request_body`, and a sha256 of the canonically-serialised
body. Only GET verbs; no POST, PUT, PATCH or DELETE anywhere in this module.

Extraction must also return the `reasons[]` distribution — a count per distinct reason and a count
per distinct sorted reason-set — because D-63-07 makes that a by-product of this work rather than
its own task. Report per-lane totals separately so a zero on either lane is an observed zero.

Write the raw corpus to a gitignored working directory (default `.judge-replay-corpus/`, add that
one line to `.gitignore`). The raw bodies stay there and never enter a committed artifact.

**Selection.** `confidence_band_only(corpus)` returns the subset whose `judge_reasons` is exactly
one element equal to `"confidence_band"`. This is the class D-63-05 would route, and the only class
this replay is evidence about.

**Comparison.** `build_report(inputs, call_model, model_a, model_b, min_corpus)` is pure and takes
`call_model(model, request_body) -> dict | None` injected, so every test runs with no network. For
each input, in ascending `input_id` order (execution id numeric, then item index numeric), call
both models, parse each response into the required verdict keys read from
`config/escalation_policy.yaml`, and classify:

- `agree` — same `decision`, and same `chosen_value` for the same `chosen_field` after a
  normalisation that lowercases and strips strings and maps the usual truthy/falsy spellings to
  booleans.
- `immaterial` — the above match but `confidence`, `reason`, `evidence_summary` or `evidence_url`
  differ. Recorded, never counted against the lever.
- `material` — `decision` differs, OR the normalised `chosen_value` differs, OR exactly one of the
  two responses is unparseable/absent while the other is usable.
- `both_unparseable` — neither model produced a usable verdict; counted as an executed assertion
  but never as an agreement.

Verdict rules, fixed here and not to be renegotiated once the numbers are visible:

- `HARNESS_FAILURE`, exit non-zero — zero inputs compared, or every model call raised. A run that
  checked nothing must never report success.
- `DROP`, exit 0 — one or more `material` classifications, OR the confidence_band-only corpus is
  smaller than `min_corpus` (default 10) with reason `insufficient_corpus`.
- `SHIP`, exit 0 — at least `min_corpus` inputs compared and zero `material` classifications.

Model ids come from `CONFIG_FLAG_DEFAULTS`: model A is `CONFIG_FLAG_DEFAULTS["ANTHROPIC_JUDGE_MODEL"]`
and model B is `CONFIG_FLAG_DEFAULTS.get("ANTHROPIC_JUDGE_MODEL_CHEAP", "claude-haiku-4-5")`. The
fallback exists only because this plan runs before 63-04 adds that key; once 63-04 lands, the key is
present and the fallback stops being reachable. Note in the module docstring that importing
`build_cloud_workflows` regenerates `n8n/code/*.generated.js` as a module-level side effect and that
this is deterministic from the YAML — a diff there is pre-existing drift worth surfacing, not
something this harness caused.

**Report.** `_write_report` follows `run_scoring_parity._write_report`: a JSON artifact under the
phase directory. Every per-input row carries `input_id`, `lane`, `body_sha256`, the classification,
and each model's `decision` and normalised `chosen_value`. It must NOT carry the request body, the
company name, the evidence URLs or the model prose.

`main(argv=None) -> int` exposes `--extract` (corpus only, prints the distribution),
`--replay` (compare and write the verdict), `--limit`, `--min-corpus` and `--corpus-dir`. Guard the
live path with an explicit precondition check for `ANTHROPIC_API_KEY` and, for extraction, for
`N8N_URL` / `N8N_API_KEY`, refusing with a named message before any call — the guarded-precondition
shape `run_scoring_parity.main` already uses.

Write `tests/test_replay_judge_models.py` driving `build_report` with a stubbed `call_model` over
