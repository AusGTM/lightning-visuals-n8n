## What Landed

### Task 1 — a trigger and a bounded wait, and nothing else

The test was red for three stacked reasons, all confirmed: **leg 1 had no trigger at all**
(`settle()` only reads), the documented fallback trigger is a **daily** poller
(CLAUDE.md §19.0 as-built) behind a 900s wait, and a complete record was dropped by the gate
before the sole veto writer ran. Four helpers in `tests/scoring_fixtures.py` close all three:

| Helper | Why it exists |
|---|---|
| `settle_until(id, prop, predicate, ...)` | `settle()` returns as soon as two reads AGREE — on a fresh disposable that is a stable **absence** in ~5s, while n8n is still executing. Never raises: the test's own asserts stay the verdict. |
| `wait_until_searchable(domain, ...)` | ~20s new-record index lag (WINDOWS.md id 6). Post too early and `Company Gate` sees no record, which under the recompute intent is `recompute_refused` — a correct refusal that looks like a broken pipeline. |
| `trigger_recompute(id, domain)` | The D-18 recompute POST. `domain` is load-bearing: it routes through `HubSpot Company Search`, which is what populates `identity_keys.domain` so `_writeSafetyAllows` can match a `TEST_RECORD_DOMAINS` allowlist. |
| `now_iso_ms()` | Mirrors `mergeCompanies.js`'s `new Date().toISOString()` shape for the two `datetime` stamps. A format HubSpot rejects 400s only live, and a silently unstamped record is still stale. |

The test now stamps `lv_org_type_verified_at` and `lv_produces_content_verified_at` before
leg 2. **This makes the bar harder, not easier** — it forces the gate verdict to `skip`, the
frozen state that made corrections unrecomputable, so only the recompute intent's
`skip → enrich` mapping gets past it. Without the stamps the test would have gone green on a
merely-stale record and proved that a trigger exists, nothing more.

**All four assert statements are byte-identical.** The gate
(`git diff HEAD -- tests/test_scoring_parity.py | grep -cE '^[-+][[:space:]]*assert '`) reads
**0**, run before the commit as the plan warns. No assertion was weakened, deleted, reordered
or reworded, and none was added — the "exactly one search match" enforcement is `pytest.fail`,
not `assert`, precisely so the gate cannot be satisfied vacuously.

## What this proves — and what it does not

**Proven:** a corrected input clears a veto on demand, live, on a record the gate calls
`skip`. The frozen-COMPLETE case is proven **here**, not only by inheritance — 11857's gate
output carries `skip` verbatim with both stamps present. Plan 02's Simtech LED execution
remains the proof on a *real, pre-existing* frozen record; 11857 is the proof on a
purpose-built one. Both, not one instead of the other.

**Not proven:** a live `D` → non-`D` tier transition. The tier assertion passed, but the two
legs are 5 seconds apart and the disarmed rehearsal read `lv_icp_tier: "Unscored"` before any
veto write, so the flag→tier flow almost certainly never wrote `D` inside the window. The
assertion is true about the end state and was not weakened; it is simply not evidence of a
transition, and reading it as such would overclaim. Phase 49 owns oracle-vs-live tier parity.

## Deviations from Plan

### 1. [Process] Task 2's `checkpoint:human-action` was executed, not halted on

The plan makes arming operator-only. The orchestrator's spawn prompt carries an explicit
operator decision of 2026-08-12, given in direct answer to a question naming these two
windows, delegating arming to the executor **for phase 47.5 only** — a scoped waiver on the
same footing as Phase 47's D-22, expiring with this phase. Its terms were followed to the
letter: `ALLOW_N8N_ARM=true` inline on exactly one command, never exported, never written to
`.env` or a profile; disarm ungated and unconditional; both surfaces independently re-read
after closing and quoted verbatim; one window, not more. Same precedent as plan 02's
deviation 1.

### 2. [Rule 1 — correctness] Leg 1's wait predicate is `v not in (None, "")`, not the plan's literal `v is not None`

The plan's stated intent is "wait until the flag reads a non-null value". HubSpot renders an
unset property as `null` in the response body but the client surfaces `""` for some property
types, and `"" is not None` is `True` — the wait would have returned instantly on a value
that had not arrived, and the assert would have failed against a pipeline that was merely
still running. The predicate implements the plan's intent rather than its literal lambda; it
is strictly more patient, never less.

### 3. [Rule 3 — blocking issue, found in the disarmed rehearsal] `load_dotenv()` loads nothing under pytest

python-dotenv's bare `load_dotenv()` resolves the `.env` path relative to the **calling
file**, not the cwd, and this repo deliberately has **no `conftest.py`**
(`tests/scoring_fixtures.py`'s header explains why). A bare
`RUN_LIVE_PARITY=true .venv/bin/python -m pytest ...` therefore sees no `HUBSPOT_*`
credentials at all: 401 on every read, and `_portal_ok()` refusing to create anything. The
live test is driven through a wrapper that passes an absolute `.env` path. **No source file
was changed for this** — adding `load_dotenv()` to `scoring_fixtures.py` would have made a
test module mutate process env at import time, which `tests/test_check_hubspot_list_scope.py`
pins against elsewhere in this repo. Caught disarmed, at zero window cost.

### 4. [Judgment] A full disarmed rehearsal was run before arming

Executions 11854/11855 on their own disposable, both `write_blocked`, with the correct
derived values in each leg and the `_verified_at` stamps read back non-blank. This is what
found deviation 3 and confirmed the `datetime` stamp format, the index-lag wait and the whole
derivation — outside the one window this plan is allowed. Recorded because it means the armed
window was a confirmation, not an experiment.
