## The defect

`Company Gate` emits `action: "skip"` for any company whose enrichment inputs are all
present, fresh and valid. `Normalize + Score Company` then drops every skipped row on its
very first line:

```js
const rows = $('Company Gate').all().filter((it) => it.json.action !== "skip");
```

With zero rows, the branch ends there. Every node downstream — including
**`Decide Company Action`, the only node that writes `lv_anti_icp_flag` and
`lv_anti_icp_reason`** — never executes.

### The consequence, stated plainly

**A company with complete inputs can never have its veto recomputed by any on-demand
trigger.** Veto recomputation is only ever reachable as a side effect of enrichment. Once
a record is complete, whatever veto state it happens to carry is frozen — correct or not.

This is the inverse of the behaviour anyone would assume: the *better* a record's data is,
the *less* able the system is to fix its scoring.

### Live evidence

| Execution | Record | Gate action | Gate reason | Nodes run | Decide ran? |
| --- | --- | --- | --- | --- | --- |
| `11846` | Simtech LED `18047161864` | `skip` | "all required fields present, fresh and valid" | 19, ends at `Normalize + Score Company` (0 items out) | **no** |
| `11845` | Pinjarra Park `17696004613` | `enrich` | "missing: lv_org_type" | 36, ends at `Respond to Webhook` | yes |

Simtech was the single pinned record whose web research produced a *valid* `lv_org_type`
enum (`hardware_vendor`). Writing that value correctly is precisely what made the record
complete, and completeness is what locked its veto. Every other pinned record was missing
`lv_org_type`, enriched normally, and recomputed fine.

Its resulting state — the thing Phase 47 exists to eliminate, left standing:

```
lv_country_region_normalized  "AU"
lv_anti_icp_flag              "true"
lv_anti_icp_reason            "Non-ANZ geography"     <- contradicts the region beside it
```

Duration is a cheap tell: `11846` ran 2.4s against 10–37s for records that reached
`Decide`. A short execution on this workflow means the chain died early.

## Why this is not merely a Phase 47 leftover

1. **Phase 47 made every one of its 17 records complete.** They are all now in exactly the
   state that cannot be recomputed. If any of their vetoes is later found wrong, today
   there is no trigger that fixes it.
2. **Phase 48 fills `lv_org_type` for 18 more companies** — its whole purpose. Every record
   it completes inherits the same frozen-veto property. Phase 48 therefore *enlarges* the
   population this defect applies to.
3. **Phase 49 re-scores the full population.** A re-score that cannot reach `Decide` for
   complete records will silently leave their veto fields at whatever they already held,
   while their scores and tiers move underneath. That divergence would be invisible.
4. The workaround Phase 47 used — blanking `lv_org_type` to force the gate to enrich —
   deliberately degrades data to trigger a recompute. It works, and it is not something
   any scheduled job should ever be asked to do.

## What a fix has to achieve

Stated as outcomes, not as an implementation — the planner picks the mechanism.

- A veto recompute is reachable for a record whose inputs are **complete**, without
  degrading, blanking, or otherwise falsifying that record's data first.
- The recompute path is reachable **on demand** (the D-18 webhook POST shape Phase 47
  used is the natural candidate) and does not depend on a provider call, a research call,
  or an Anthropic call — recomputing a veto from properties already on the record costs
  nothing and should stay free.
- `Decide Company Action` remains the single writer of `lv_anti_icp_flag` /
  `lv_anti_icp_reason`. Do not add a second writer; that would split the veto's authority
  in two and is the more expensive bug to fix later.
- A skipped record is **observable**. Today the skip is silent: `status: "success"`, no
  node error, nothing written. This is the same silent-success class already recorded in
  `47-BLOCKED.md` for the Claude Web Research node, and in
  `.planning/todos/pending/2026-08-12-n8n-swallows-anthropic-credit-failure.md`. Consider
  addressing them together — they share a root shape: *a branch ends quietly and the
  caller cannot tell*.
- Regression coverage lands in `tests/n8n/` against the gate + normalize pair, pinning
  that a complete record still reaches the decide step. Run with
  `node --test tests/n8n/*.test.mjs` (glob form; the directory form is broken on node 24).

## There is already a test waiting for this fix

`tests/test_scoring_parity.py::test_veto_clear_after_correction` (`@live`, skipped by
default) has been red since Phase 40-07. This defect is why.

Its fixture patches `lv_country_region_normalized = "AU"` onto a record that already has
`lv_org_type`, `lv_produces_content` and `lv_revenue_band` set — so the record is
**complete**, the gate skips it, and the flag it asserts on is never rewritten. Its own
comment already circles the shape of the problem ("the flag is owned and cleared by the n8n
pipeline… correcting the input alone isn't enough") and falls back to
`lv_enrichment_requested` + the SJ-3 poller, which is now daily and hits the same gate
anyway.

**Use it as this phase's acceptance test.** When a complete record's veto can be recomputed
on demand, that test passes with its assertions untouched — which is the honest bar. Do not
adjust the test to fit the fix.
