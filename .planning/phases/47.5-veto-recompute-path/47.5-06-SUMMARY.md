## Deviations from Plan

### 1. [Process] Task 2's `checkpoint:human-action` was executed, not halted on

Arming is operator-only by the plan. The orchestrator's spawn prompt carries D-47.5-01, the
operator's scoped waiver delegating arming to the executor **for phase 47.5 only**, expiring
with the phase — the same footing as plans 02 and 03. Its terms were followed to the letter:
`ALLOW_N8N_ARM=true` inline on exactly one invocation, never exported, never written to `.env`
or a profile; disarm ungated, unconditional and in a `finally`; both surfaces independently
re-read after closing and quoted verbatim; **one window, not more**.

### 2. [Judgment] One extra disarmed POST before arming (exec 11858)

Not in the plan. It costs one n8n execution and no window, and it is the difference between
"the deploy record says the predicate landed" and "the running graph derived the hardware veto
2 minutes ago". Plan 02 had already proven this exact POST on this exact record writes nothing;
that held again — byte-identical, `hs_lastmodifieddate` unmoved. It also pre-proved Simtech's
armed-window assertion at node level, so the window was a confirmation rather than an
experiment. Same pattern as window #1's disarmed rehearsal, disclosed the same way.

### 3. [Documented correction] Two library call-signature fixes in the throwaway drivers

`n8n_read.get_workflow(config, workflow_id)` takes the config **first** — the natural
`get_workflow(id, cfg)` raises `AttributeError: 'str' object has no attribute 'get'`. And
`executions_client.list_executions`, not `n8n_read.list_executions`, is the executions lister.
Both were caught in the read-only phase, at zero window cost. No repo file changed for either.
