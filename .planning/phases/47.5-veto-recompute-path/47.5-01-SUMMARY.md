# Phase 47.5 Plan 01: Veto Recompute Path Summary

**A company whose enrichment inputs are complete can now have its veto recomputed on demand, at zero provider/research/Anthropic cost, without degrading its data first — and a skipped company stops returning a silent 200.**

## Performance

- **Duration:** ~50 min
- **Tasks:** 3 of 3
- **Commits:** 5 (RED/GREEN pairs for tasks 1 and 3, one guard commit for task 2)

## What Landed

### Task 1 — the request-level recompute lane (tracer, TDD)

Four coordinated edits in `scripts/build_cloud_workflows.py`, then a rebuild:

1. **`ENRICH_PARSE_EVENT_CLOUD`** gains `recompute: event.recompute === true`, placed **after** the `...event` spread. The companies branch has `entry_strip_markers=False`, so a caller-supplied raw row property is not stripped there and would otherwise shadow the normalization. Strict `=== true` — the string `"true"`, `1` and absence all normalize to `false`, which is the fail-closed direction and costs nothing.
2. **`ENRICH_CO_GATE`** resolves the intent once per execution from the root node and applies exactly two mappings under it: `skip → enrich` (so Decide's enrich IF fires the PATCH) and `create → recompute_refused` with a rewritten `gate.reason`. `enrich` is untouched.
3. **Two new IF nodes** on a free row so no existing node position moved: `IF Company Recompute` (`$('Parse HubSpot Event').first().json.recompute === true`) and `IF Company Skip` (`$json.action === "skip"` — bare `$json` is correct here and only here, because the immediate upstream is a Code node with no HTTP hop between).
4. **Connections**: `Company Gate → IF Company Recompute`; true → `Decide Company Action` (one edge), false → `IF Company Skip`; skip true → `Build Response`, false → `Build Company Requests`. The direct `Company Gate → Build Company Requests` edge is gone.

Decide's veto derivation was **not touched**. With `row.merge` absent, `properties` is `{}` and the three `??` fall through to `existingRecord` — which is exactly why a merge-free lane works, and why the lane never enters the D-20 `_verified_at` clobber race.

`tests/n8n/companyRecomputeLaneFlow.test.mjs` (new, 6 tests) drives the committed workflow's real `jsCode` across `Parse HubSpot Event → Company Gate → IF Company Recompute → Decide Company Action`, **and evaluates both IF nodes' real `leftValue` expressions** against the same faked context. An IF node carries no `jsCode`; without that the test would have assumed the routing it exists to pin.

### Task 2 — structural guards

Four new assertions in `tests/test_cloud_companies_branch.py`: both new nodes present and BFS-reachable; the five edges asserted **by target, not by count**; the recompute lane is a single edge with no intermediate node; and a **positive count gate** proving each veto field is assigned exactly once across every node's `jsCode`, by `Decide Company Action`.

The count gate is **dot-anchored** (`\.lv_anti_icp_flag\s*=(?!=)`). A naive scan reads **2** in Decide alone — its 2026-08-10 blank-region debug comment quotes `lv_anti_icp_flag="true"` in prose. Measured before writing the assertion, not assumed.

A fifth test pins the two anti-patterns the research found in source: the predicate must be `.first()` (never `.item`), and the intent must never be a `mode` value.

### Task 3 — operator helpers

`build_webhook_event` gains `recompute` / `domain` keywords, each added to the event **only when set**, so the default body stays byte-shape identical for every existing caller. `post_webhook_event` threads both through and replaces the hardcoded 30-second read timeout with `timeout: float = 300`.

`june_run_arm.py --domains` exposes `arm_for_dispatch`'s existing `record_domains` parameter, which this wrapper had hidden by passing `[]` unconditionally. The empty-allowlist refusal now fires only when ids **and** domains are both empty. `allow_create` stays false; `disarm()` untouched.

## Deviations from Plan

### 1. [Rule 3 — blocking issue] `ENRICH_CO_GATE` is shared by two workflows with no `Parse HubSpot Event` node

- **Found during:** Task 1, immediately after the first rebuild.
- **Issue:** The plan's `read_first` covered only the enrichment-cloud emission. `ENRICH_CO_GATE` is in fact shared by **three** workflows: `wf_enrichment_cloud`'s `Company Gate`, `wf_enrichment_local_live`'s `Company Gate`, and `wf_scheduled_maintenance_cloud`'s `SJ-2 Company Gate`. Only the first has a `Parse HubSpot Event` node. n8n throws on `$()` for a node that does not exist in the current workflow, so the plan's literal `$('Parse HubSpot Event').first().json.recompute === true` would have thrown on **every row** of the SJ-2 daily maintenance sweep and the local-live variant. Verified by listing node names in both built files.
- **Fix:** Hoisted the read out of the per-row map into a `RECOMPUTE_REQUESTED` constant guarded by the **same** `try/catch` idiom `ENRICH_NORMALIZE_SCORE_CO`'s `nodeAll()` already uses in this repo. Failing to `false` is the fail-closed direction: those two workflows keep exactly the behaviour they have today.
- **Not a weakening:** the request-level `.first()` semantics the plan requires are preserved verbatim, and `tests/test_cloud_companies_branch.py` pins both the expression and the absence of `.item`.
- **Files:** `scripts/build_cloud_workflows.py`, `n8n/wf_enrichment_local_live.json`, `n8n/wf_scheduled_maintenance_cloud.json`
- **Commit:** `ae13d2c`

### 2. [Rule 1 — pre-existing guard, extended not relaxed] `BUILD_RESPONSE_SOURCES`

- **Found during:** Task 1's full-suite run.
- **Issue:** `tests/test_remaining_credits_response.py::test_build_response_is_reachable_from_every_terminal_branch` asserts the **exact** inbound edge set of `Build Response`. `IF Company Skip → Build Response` is a genuine new terminal, so it failed.
- **Fix:** Added `("IF Company Skip", 0)` to the expected set, with a comment naming RECOMP-02 and noting it is the direct companies mirror of the contacts branch's long-standing `("Skip (NoOp)", 0)`. The assertion remains exact equality — the guard was extended, never relaxed to a subset check.
- **Commit:** `ae13d2c`
