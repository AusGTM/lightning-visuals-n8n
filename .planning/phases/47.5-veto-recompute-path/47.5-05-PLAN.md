(Supertech Electronics `15274105699`, true, Tier D). `lv_org_type == "hardware_vendor"` holds
for **2** — Supertech and Simtech LED `18047161864`, whose boolean is null and which
therefore sits at **Tier B**. That is the only divergence in the portal today.

Why the boolean is empty is mechanism, not accident. The research contract instructs the
model to answer null for both vendor flags unless a cited source supports them; a true on
either forces judge escalation; and if the judge does not run or does not confirm, the
fail-safe demotes the value back to null. Merge then requires 85 confidence on top. The
pipeline is designed to suppress this field. `lv_org_type` faces none of that and is what the
pipeline reliably lands.

`lv_is_gambling_operator` does **not** have the same problem today: both
`gambling_operator` records carry the boolean, zero diverge, and gambling is a graduated
deduction rather than a veto — with `graduated_deductions` currently empty, that deduction is
zero. The answer still needs recording so the next reader does not re-derive it.

Note that under either shape Supertech stays vetoed: its `lv_org_type` is also
`hardware_vendor`. The choice is about which field is authoritative going forward, not about
un-vetoing anything.
