<objective>
Convert `lv_org_type` from free text to a real HubSpot enumeration — the phase's one-way
door — with the rollback path written and committed first, a pre-flight gate that refuses to
run while any live record would be harmed, and an independent read-back proving what landed.

Purpose: every write of this property since Phase 13 is already forced through the taxonomy
normalizer, so the vocabulary is enforced in code but not in the schema. Closing that gap
makes HubSpot reject a bad value instead of silently storing it, which is what makes the
field trustworthy for the armed canary in Phase 22. It also makes a mistake here expensive to
undo, which is why the rollback is authored before the migration exists.

Output: a rollback runbook, a gated migration script with offline-tested refusals, a
reversibility decision gate, and an operator-packaged armed run with independent verification.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Migration script → live HubSpot property schema (armed) | The one-way door. A wrong option set, a wrong target, or a conversion run against records holding stray values is unrecoverable by code revert. |
| Runbook document → migration script's arm gate | The document is load-bearing executable policy, not prose: the script refuses to arm without its markers. A careless edit to the doc disarms or falsely satisfies the gate. |
| Inventory artifact → pre-flight gate | A stale or truncated artifact would let the migration run against records it should have blocked on. |
| Agent session → armed HubSpot schema write | Project policy: agents build and dry-run; arming is operator-only. |
