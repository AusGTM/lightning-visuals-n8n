<objective>
Make the on-demand enrichment webhook caller-controlled and cost-safe by adding a
per-request provider-selection gate, hardened at the input layer. The webhook payload gains
a `providers` node via an explicit contract (bare event array => enrich nothing; envelope
`{providers, events}` => caller-injected selection); a new pure module resolves it; the
`Parse HubSpot Event` node threads the resolved set onto every row; the object-type router
gains an explicit `unsupported` outcome that terminates before any provider gate; the contacts
dispatch collapses the create+enrich double-feed into one `action != skip` lane; and BOTH the
contacts and companies provider waterfalls are restructured so each provider HTTP node sits
behind its own `IF <provider> Enabled` gate WITH A BYPASS lane, emitted by ONE shared builder
helper. A disabled provider is skipped (its node never executes) while the row spine always
continues through the bypass to `Normalize + Score`; any arbitrary enabled subset runs.
Adapters live in one side-effect-free registry (`scripts/provider_registry.py`).

Purpose: This is the pre-live burn gate. The topology change is the riskiest,
most-foundational piece of Phase 16.1 — it must land and be test-proven before the
credit-reporting and schedule-safety layers (Plan 02) build on it. The reviews-driven input
hardening (A1 single-execution, A2 unsupported routing, A4 payload contract, A3 side-effect-free
registry) closes the credit-burn and mis-parse holes three cross-AI reviewers flagged. The
gated waterfall also closes a latent identity bug via node-name identity reads.

Output: two new modules (`providerSelection.js`, `scripts/provider_registry.py`), a single-source
`PROVIDER_REGISTRY`, one shared `_provider_gate_bypass_chain(...)` helper emitting BOTH gated
(bypass-convergence) waterfalls symmetrically, a documented + in-graph contacts research->judge
seam (no research/judge nodes built here), and three offline tests — all proven with zero live
network calls; the builder rebuild is deterministic and the full offline suite stays green.
</objective>
