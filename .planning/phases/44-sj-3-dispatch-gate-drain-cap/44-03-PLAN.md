Ship Plans 01 and 02 in one build -> deploy -> bounce, then prove the three behaviours on the
live backend: a gate-closed tick costs exactly one execution (GATE-01), reports its named
outcome (GATE-02), and drains a seeded stuck record (DRAIN-01).

A1 — that n8n's `executeWorkflow` "each" mode genuinely produces zero live sub-executions when

live execution of `_hs_update_set_property`'s output on a node this repo has never run; given the
BUG 10 / 11 / 13 / 18 history of native HubSpot node operations silently doing nothing while
reporting success, the write must be judged from runData plus a HubSpot read-back, never from a
200.
