<objective>
Close gap G2 (D-72-01 / D-72-06, review CR-01): `build_enrichment_local_live()` fetches the
matched record's existing properties through two hand-maintained constants,
`HS_SEARCH_BODY_EXPR` (contacts, ~L2866) and `HS_CO_SEARCH_BODY_EXPR` (companies, ~L3010).
Phase 72 widened only their cloud siblings. Both lanes share the SAME merge engine
(`ENRICH_MERGE` / `ENRICH_MERGE_CO`, one constant each, used by both builders), and that engine
now offers `lv_phone_2`/`lv_mobilephone_2` (contacts) and `state`/`hs_state_code`/`phone`/
`lv_phone_2` (companies) as candidates. Every one is `fill_blank_only` +
`protect_if_current_present: true`, and a field the fetch list omits reads `undefined`, which
`_isBlank()` cannot distinguish from genuinely blank — so the non-clobber guard becomes a permit
to overwrite a real human-entered value.

**Decided, not missed:** the two literal lists are widened and pinned by a derived test, rather
than unified into one shared Python constant with the cloud CSVs. The four lists genuinely differ
in BOTH directions (local-live companies fetches `lv_icp_tier`/`lv_icp_fit_score`/
`lv_anti_icp_flag`, which the cloud CSV does not; the cloud CSVs fetch `hs_object_id`, which
local-live does not), so a single list would silently change the cloud lane's fetch too. The
repo's own comments above both constants already record derivation as a real refactor out of
scope, with the `fieldProducerMatrix.test.mjs` fetch-gate assertion as the drift guard — Task 1
adds the assertion that guard was missing.

Purpose: a real, credential-bound lane can currently overwrite a phone, state or overflow value
it never fetched to check.
Output: both local-live fetch constants widened, a derived drift guard that goes RED today, and
the regenerated `wf_enrichment_local_live.json`.
</objective>
