## BUG 12 — `Set Data Quality + Gap Flag` discards the entire row

`Decide Action` emitted `{"object_type": "contacts", "hs_object_id": null, "gap_flag": false,
"properties": {}}` — no `action` key at all — so `IF Enrich` received **0 items** and `HubSpot Update`
never ran.

Mechanism, established from the built artifact and the execution together:

- Connection chain is `Merge Winners → Set Data Quality + Gap Flag → Decide Action`.
- `Set Data Quality + Gap Flag` is `n8n-nodes-base.set` typeVersion `3.4` with `"options": {}`.
  `includeOtherFields` is unset, and it **defaults to false** in Set v3.x, so the node emits only its
  two assigned fields.
- Its live output, quoted: keys are exactly `['data_quality', 'gap_flag']`. `merge`, `existingRecord`,
  `object_id` and `scored` are all gone.
- `Decide Action` computes `const hs_object_id = (row.existingRecord && row.existingRecord.hs_object_id) || null;`
  → `null`, and `_buildContactPatch(merge)` with `merge` undefined → `{}`.
- `_writeSafetyAllows("enrich", null, null)` therefore returns false no matter what the allowlist says.

**The contacts write path is structurally incapable of writing to any record, under any flag
combination.** The companies lane has no equivalent Set node, which is why `Decide Company Action`
received a full row and produced a real `write_blocked` verdict with the correct `hs_object_id`.

Not a regression from today: execution **8** (2026-07-28, before any change in this session) shows the
identical `Decide Action` output — `hs_object_id: null`, `properties: {}`, `IF Enrich` empty,
`HubSpot Update` absent. It was invisible because writes were disabled and the webhook returned a
plausible 200.

Not patched in flight, per the plan's halt protocol. The fix is one builder change —
`options: {includeOtherFields: true}` on that node — and belongs in its own plan with a red test that
asserts `Decide Action` receives `existingRecord`/`merge`, plus a sweep for any other Set node in a
row-carrying position.
