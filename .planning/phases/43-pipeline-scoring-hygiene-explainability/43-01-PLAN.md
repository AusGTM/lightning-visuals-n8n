<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| n8n Code node -> HubSpot CRM v3 PATCH | Untyped candidate values (provider JSON, Claude research JSON) cross into a write body |
| HubSpot Search API EQ filter -> operator review queue | The queue's contents are derived entirely from what the write side stored |
| Builder source -> generated n8n JSON | Every runtime behavior here is baked at build time; a hand-edit bypasses all tests |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-43-01 | Tampering | The coercion fix itself | high | mitigate | The site table in `<boolean_writer_inventory>` is the acceptance surface: each row asserted individually. A fix that lands at 5 of 6 broken rows leaves the defect live while the phase reports closed. |
| T-43-02 | Repudiation | `lv_enrichment_needs_review` write path | high | mitigate | The write "succeeds" but nothing observable changes — the record is flagged and invisible. Task 2's live-gated EQ test (run in 43-04) is the only proof the reader actually sees the write. |
| T-43-03 | Tampering | Comment text at fix sites | medium | mitigate | A comment restating the broken literal makes the negative grep self-invalidating. Explicitly prohibited in all three task actions; acceptance criteria grep with comment lines filtered where the file is comment-heavy. |
| T-43-04 | Denial of Service | `mergeCompanies.js` dead-path proof | medium | mitigate | Driving the veto path in a fixture to "prove" hardening would resurrect a deliberately dead path. D-10 forbids it; Task 3's criteria assert the test body contains no call to the function. |
| T-43-05 | Elevation of Privilege | Generated JSON write-safety constants | high | mitigate | Regeneration rebakes `ALLOW_HUBSPOT_*` to disarmed defaults. Task 2's criteria re-run the arming grep expecting 0. No deploy occurs in this plan (43-05 owns it, gated). |
| T-43-06 | Tampering | Hand-edited generated JSON | medium | accept | D-11 forbids it and the builder overwrites any hand edit on next regeneration; the existing suite catches drift. No new control needed. |
</threat_model>
