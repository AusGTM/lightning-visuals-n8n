<objective>
Build the read-back that closes the armed window. The deploy script's exit code proves a request was
accepted, never that the live artifact is what was intended — the lesson BUG 26 taught this repo at
the cost of a whole phase's verification. This plan produces one command that reads the deployed
enrichment workflow and states, for both write-decision nodes, whether writes are armed, what the
allowlist actually contains, and whether the create flag is still disabled.

Purpose: roadmap criterion 4 ("the run closes disarmed and audited: read-back shows every write flag
disabled and the allowlist cleared") is only meaningful if something mechanically checks all eight
literals rather than an operator eyeballing a JSON blob at the end of a long window. It is also the
same check that must pass BEFORE firing, to prove the arm actually landed on both lanes.

Output: a read-only verifier with explicit armed and disarmed expectations, offline tests for every
refusal, and a live baseline run proving the current deployment reads clean today.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Verifier → n8n Cloud API | Read-only GET of a workflow definition, authenticated with the n8n API key; the definition contains the write-safety configuration under audit. |
| Verifier output → SUMMARY / runbook evidence | Whatever is printed becomes committed evidence; node bodies contain URLs and expressions that should not be pasted wholesale. |
| Live deployment ← deploy script | Out of scope for this plan: this plan only reads. Arming remains operator-only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-06 | Spoofing | A verifier that passes a half-disarmed deployment | critical | mitigate | Both write-decision nodes are checked independently and every one of the four constants must satisfy the expectation on both; the behaviour table pins the half-disarmed case as a failure. |
| T-22-07 | Tampering | A stale allowlist surviving a disarm and re-enabling writes on a later run | high | mitigate | Disarmed expectation fails on any non-empty allowlist constant, not only on an enabled write flag. |
| T-22-08 | Elevation of Privilege | The canary arming the create flag beyond its scope | high | mitigate | Armed expectation fails when the create flag reads enabled, so an over-armed deployment cannot be certified ready to fire. |
| T-22-09 | Information Disclosure | Node bodies or credentials pasted into committed evidence | medium | mitigate | Output is restricted to node names, constant names and parsed literals; an acceptance criterion checks the node body is read but never printed. |
| T-22-10 | Repudiation | The verifier drifting from the overlay's actual flag set | medium | mitigate | The checked set is imported from the overlay spec and asserted equal to it by test. |
</threat_model>
