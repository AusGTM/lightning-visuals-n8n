<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| executor → n8n Cloud API | a deploy call would mutate five running workflows; the executor must never cross it |
| repo working tree → deploy script | the script reads whatever bodies are in n8n/ at the moment it runs, so a stale checkout is a deployable artifact |
| git history → live instance | the rollback trusts a commit SHA to name the bodies that will overwrite production |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-70-30 | Tampering | working-tree n8n/ left holding pre-70 bodies after a failed task | high | mitigate | every checkout is bracketed by a restore in the same command sequence, and both Task 1 and Task 2 verify with a clean `git status --porcelain -- n8n/` |
| T-70-31 | Elevation of Privilege | deploy script invoked with the two write-gate variables by the executor | critical | mitigate | the executor runs the script only in its default dry-run mode; the armed invocation exists only as text in the operator runbook and in the Gate 4 section |
| T-70-32 | Spoofing | rollback performed against a mis-remembered or rewritten SHA | high | mitigate | Task 1 pins the SHA and the five node counts in a test that reads from git history, and the runbook repeats the counts as a post-deploy read-back |
| T-70-33 | Tampering | the rollback bundle turns out to contain an armed build | critical | mitigate | Task 1 asserts every write-flag and allowlist declaration in the pinned bodies reads its disarmed literal before the bundle is ever named as deployable |
| T-70-34 | Repudiation | a deploy without a bounce leaves the running graph different from the stored one, and a read-back reports the stored body | medium | mitigate | the runbook makes the bounce mandatory and orders the read-back after it |
| T-70-SC | Tampering | npm/pip/cargo installs | high | mitigate | no package installs in this plan; if one becomes necessary the package-legitimacy gate and a blocking human checkpoint apply |
</threat_model>
