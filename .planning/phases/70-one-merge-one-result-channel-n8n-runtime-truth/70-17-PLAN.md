<objective>
Make the v1 execution order survive every path that can rewrite a live workflow, and make every
read-back in this repo report and enforce it.

Purpose: D-70-29. Plan 70-16 puts the v1 execution order in the committed JSON, but a setting
that a later PUT silently drops is worse than no setting at all — the graph would revert to the
legacy order that produced every Gate 8 symptom (executions 12349-12353) while every offline
test stayed green. Two code paths can PUT a live workflow: `scripts/deploy_n8n_workflows.py`
(the deploy) and `operator-claude-plugin/scripts/n8n_control.py` (the arming and disarming
rewrites). Both already forward the settings object; neither fact is currently pinned by a test,
and neither read-back reports the value. This plan pins both and adds the reporting.

Output: a settings-preservation pin on each PUT path, an execution-order column in the bounce
read-back that fails the run on a non-v1 reading, and a proof-driver verdict that answers false
when the live instance is not on v1.
</objective>
