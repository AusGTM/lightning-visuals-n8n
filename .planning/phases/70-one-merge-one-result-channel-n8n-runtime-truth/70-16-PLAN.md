<objective>
Flip every generated n8n workflow onto n8n's v1 execution order from one shared generator
constant, make a non-v1 body a generation-time refusal, and stop the offline walker from
pretending it models the legacy engine.

Purpose: G-70-6 (blocker). On Gate 8 (executions 12349-12353, disarmed) `HubSpot Update`
executed with no real input item and PATCHed an empty id; `IF List Expanded` emitted a refusal
on an empty list lane; gated sentinels delivered markers on inputs whose sentinel emitted zero
items; `Enrichment Gate Merge` fired twice and dropped every real row. One source-cited engine
rule explains all of it: with the execution-order setting absent, n8n's LEGACY path
(`packages/core/src/execution-engine/workflow-execute.ts`, `addNodeToBeExecuted`, the
`addEmptyItem` branch) pushes every node on an empty branch onto the execution stack carrying
ONE empty item so a waiting Merge can finish. That single item is the shape of every Gate 8
symptom. The setting was absent on every live body throughout — nobody chose legacy, it was
inherited. D-70-28 rules the flip.

Output: eight regenerated bodies on the v1 execution order, a generation-time refusal that keeps
them there, and a walker that states the v1 contract instead of a legacy model it can no longer
justify (D-70-30).

**Interpretation note, stated in the open so the operator can override it.** D-70-30 lists three
v1 rules. This plan implements exactly ONE of them — (a) a node fed zero items does not run,
which the walker already models. It deliberately does NOT implement (b) the end-of-run drain of
a waiting Merge at `requiredInputs`, and it does NOT change (c) the walker's treatment of a
zero-item output as a delivery. Reason: (b) and (c) are not independently implementable — a
faithful drain must decide whether a zero-item arrival counts toward `inputsWithData`, which is
precisely what D-70-30 calls UNOBSERVED. Implementing them offline would replace one unobserved
model with another, which D-70-19 forbids. Freezing the walker's Merge semantics also means Gate
11 isolates ONE variable: the flip. Both rules are RECORDED in the walker's comments as
not-modelled / unobserved rather than silently omitted.
</objective>
