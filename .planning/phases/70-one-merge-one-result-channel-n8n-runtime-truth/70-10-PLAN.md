shared Merge input — and prove it on the ingest lane end to end.

Purpose: the fix belongs in one helper, not at fifty sites. `_add_starved_lane_sentinel` created

ingest lane is the tracer because it is the lane execution 12203 failed on and the smallest lane
that carries every shape: a fan-in Merge, a positional carry Merge, a two-output write gate, and a
sentinel that must bypass rather than pad.

Output: the operator's mechanism decision, a gated sentinel mechanism in the builder, a
regenerated ingest lane whose armed mixed-verdict batch is correct offline, and a structural
contract test that fails on any future shared or unfed Merge input.
</objective>

Change the mechanism in the generator, then regenerate and prove it on the ingest lane.

In `_add_starved_lane_sentinel`, insert a gate node between the sentinel's condition node and its
targets: the condition node keeps its current contract of returning either an empty array or one
marker, and the new gate node is what actually feeds the targets. Because a node fed zero items
never runs, the empty case now makes no delivery at all, which is the whole point. Stamp the
marker with a reserved key at the gate so a marker is never mistakable for a real row, and give
the helper one shared name for that key so every consumer filters the same literal. One gate node
per sentinel, fanning to all of that sentinel's targets — not one per target; the global sentinels
fan across many inputs and many merges.

Update `wire_gate_refusal_lane`'s mirror walk in the same change. It locates a sentinel by its
outgoing edge to a merge input, and after this change a sentinel's outgoing edge points at its
gate. Follow the gate, or the refusal lane silently loses the mirrored coverage that keeps its
input fed when the write gate never runs.

Add the carry-Merge bypass. Where a sentinel today feeds both inputs of a positional carry Merge,
it must instead deliver to the node that carry Merge feeds. A marker on both inputs of a
positional Merge pairs into one fabricated row; a marker on the consumer's append input is inert
and is dropped at the response builder. Express this as a parameter of the sentinel call site or a
small helper — not as a hand-wired special case in the ingest builder, since the enrichment lane
in the next plan has the same shape.

Add a pass-through node between every routing IF branch and any Merge input it feeds, on the
ingest lane. Whether an IF's empty branch delivers to a Merge is not something this repo has
observed, and the design must not depend on either answer; a Code or NoOp pass-through makes every
Merge producer obey the single rule that has been observed.

Regenerate every workflow with the builder — never by hand — and re-pin any node count the suites
assert, recording the new counts in the summary as an expected consequence.

Turn the ingest suites green, starting with the armed mixed-verdict case in `writeGateShape`,
