<objective>
One result channel on the client: every row comes from the settled execution, correlated by the
run's own id, and nothing is inferred from an ack.

Purpose: the backend now answers with an ack. Every caller that used to read row outcomes out of
that body must read them from runData instead, or it reports on a channel that no longer carries
data. The mechanism already exists and is proven live — this plan promotes it to the only path and
closes the three ledger and preview defects that the two-channel design was hiding.

Output: a client whose per-row truth has exactly one source, a ledger that records only writes, a
preview whose verdict matches what dispatch will actually send, and repo scripts that read the
same channel.
</objective>
