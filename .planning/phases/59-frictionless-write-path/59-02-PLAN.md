<objective>
D-59-04: add a root `tests/conftest.py` autouse fixture that strips `ANTHROPIC_API_KEY` and
`HUBSPOT_PRIVATE_APP_TOKEN` from `os.environ` for the duration of every test under `tests/`,
and prove BOTH branches — stripped by default, present when deliberately opted in.

Purpose: commit `89c9871` recorded a live incident where a stray `load_dotenv()` at test
collection time put real credentials into the environment of a routine test run.
`src/web_research.py:126` constructs `Anthropic()` with no explicit key and no local
`if not api_key:` guard — it relies entirely on `USE_MOCK_WEB_RESEARCH` defaulting to `"true"`,
which is exactly the condition that incident broke. Stripping the credential converts the
dangerous case (a silent billable call) into a loud one (`AnthropicError` at construction).

Output: one new conftest, one probe module, one test file. No plugin files, no production code.

<planner_assumptions>
**RECORDED DEVIATION FROM CONTEXT.md's LETTER, HONOURING ITS INTENT.**

`59-CONTEXT.md` D-59-04 says the fixture strips the two variables *"unless a test is
`@live`-marked"*. Implementing that literally is not possible in this repo and would break
working tests. Three facts, each verified live during research and re-checkable from this plan:

1. **There is no registered pytest marker named `live` anywhere in this repository.** No
   `pytest.ini`, no `pyproject.toml`, no `setup.cfg` `[pytest]` block exists at all
   (`find . -iname pytest.ini -o -iname pyproject.toml -o -iname setup.cfg` outside `.venv`
   returns nothing).
2. **The only "live" concept in the repo is a Python VARIABLE, not a marker.** Both
   `tests/test_scoring_parity.py:51-54` and `tests/test_review_flag_eq_filter.py:28-31` define
   a local name `live = pytest.mark.skipif(os.getenv("RUN_LIVE_PARITY") != "true", ...)`. The
   mark actually applied to those tests is `skipif`. A fixture calling
   `request.node.get_closest_marker("live")` would never find a match, and would therefore
   take its default branch unconditionally — either always stripping or never stripping,
   neither of which is the intent.
   `tests/test_scoring_parity.py:48-50` documents this env-var-over-marker choice as
   deliberate (D-11 / 40-RESEARCH.md A3), so it is a standing convention, not an oversight.
3. **pytest runs autouse fixtures for a test whose `skipif` evaluates to "do not skip"** —
   reproduced live during research. So an unconditional strip breaks
   `RUN_LIVE_PARITY=true .venv/bin/python -m pytest tests/test_scoring_parity.py` the moment
   anyone actually runs it, with a confusing auth error rather than an obvious one.

**Therefore the fixture gates on `os.getenv("RUN_LIVE_PARITY") != "true"` — the identical
condition the two existing live tests already use — not on a marker.** This is the same intent
CONTEXT.md expressed (credentials present only for a deliberately opted-in live run), expressed
in the mechanism this repo actually has. This paragraph is the record; the same reasoning must
appear in the conftest's own module docstring so a future reader does not "fix" it back.

Also recorded: the spec-less probe fallback did not run for this phase (no requirement IDs to
probe from), so no probe-derived predicates exist; `must_haves` are derived from D-59-04.

**Deliberately NOT included** (RESEARCH Open Question 2, answered): the fixture does NOT also
guard `USE_MOCK_WEB_RESEARCH` / `DRY_RUN` / `USE_MOCK_PROVIDERS`. Stripping the credential
already makes a `USE_MOCK_WEB_RESEARCH=false` leak fail loudly at client construction rather
than succeed silently and bill. Widening the fixture's reach beyond CONTEXT.md's stated scope
is a possible hardening follow-up, not this phase's scope.
</planner_assumptions>

`("ANTHROPIC_API_KEY", "HUBSPOT_PRIVATE_APP_TOKEN")` — the two variables CONTEXT.md names, and

`monkeypatch.delenv(name, raising=False)` for each name in `GUARDED_CREDENTIAL_VARS`.
`raising=False` is required — an unset variable is the common case, not an error. Use
`monkeypatch` rather than mutating `os.environ` directly so the strip is undone at teardown.

**`tests/_credential_guard_probe.py`** — new, deliberately NOT named `test_*.py`.

`GUARDED_CREDENTIAL_VARS` and `live_run_opted_in` from `conftest` so the probe cannot drift
from the fixture it is probing. Assertion messages name which branch failed.

**`tests/test_conftest_credential_guard.py`** — new, the real test file.
