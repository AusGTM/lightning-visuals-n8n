<objective>
Close gap 3 of `59-VERIFICATION.md`: `written_records.WrittenRecordsError` is not one of the
three exception types `dispatch_plan`'s loop catches, so it propagates and can abort an armed,
in-progress dispatch. On the unattended path it crashes `scheduled_arm.py` with an unhandled
traceback, discarding the accumulated results for a batch that may already have written real
HubSpot records — while that file's own comment asserts this cannot happen.

Purpose: D-59-10 rules that a records-write failure must never stop a dispatch. The trade-off
the ruling names explicitly is that a run can now finish with an incomplete written-records
list, and that condition must be surfaced loudly rather than swallowed — an artifact that is
silently short reads as a complete account of what was written, which is worse than one that is
absent.

Output: the loop catches it and continues; the incomplete condition is loud in three places; the
stale comment is corrected in the same commit.
</objective>
