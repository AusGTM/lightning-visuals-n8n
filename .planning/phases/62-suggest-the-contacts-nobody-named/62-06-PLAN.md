<objective>
Close the one gap blocking Phase 62's goal: the per-company cap — the mechanism the whole
suggestion round relies on to keep stage-2 provider spend inside what the operator agreed to
pay — is applied by a single unvalidated Python slice, and the "a cap above the grant's priced
cap is refused" rule exists only as SKILL.md prose for an LLM orchestrator to follow.

Purpose: make the phase's own stated cost-safety invariant — *a round may spend LESS than the
priced per-company cap; it may never spend more* (D-62-12, SUGGEST-05) — true in code rather
than in documentation. The production path is an LLM orchestrator threading a number it asked
the operator for, so "the cap arrives as None" is a plausible failure of the actual mechanism.

Output: `suggest_contacts.CapRefused` + `suggest_contacts.agreed_cap()`, a hard guard inside
`synthesise_rows()`, regression tests for the two live-reproduced bad inputs, and the SKILL.md
sequence + census + composition test that pin the new call so it cannot decay back to prose.
</objective>

## Design notes (read before Task 1)

**Why the guard goes inside `synthesise_rows` and not in a wrapper.** It is the SOLE function
that applies the cap (62-01-PLAN.md's own contract: "emits at most `per_company_cap` records").
A guard in one caller leaves every sibling caller broken; a guard at the application site covers
all of them. All four existing call sites in the repo pass an int literal
(`per_company_cap=2` / `=3`), so the raise breaks no existing test.

**Why `agreed_cap` lives in `suggest_contacts.py`, not `write_grant.py`.** `suggest_contacts.py`
is pure by construction — no HTTP client, no I/O — and `test_suggest_contacts_module_is_pure_no_http_client`
plus the autouse `no_network` fixture depend on that. `write_grant.py` pulls in transport code.
`agreed_cap` reads a plain dict, so it needs **no `import write_grant`** at all. The end-to-end
test that feeds a REAL envelope's figures into `agreed_cap` therefore lives in
`test_write_grant_suggestion.py`, which already has the `_envelope()` / `HEADROOM` helpers that
build an envelope with no transport.

**The deliberate asymmetry — do not "harmonize" these two validations.**

| Site | Accepts | Why |
|---|---|---|
| `synthesise_rows` guard | any int `>= 0` (0 is legal: zero rows is spending less) | backstop against a malformed value reaching the slice |
| `agreed_cap` | int `1..priced_cap` inclusive | an operator's CHOSEN cap; mirrors `envelope()`'s own `suggestion_cap > 0` validation |

`bool` is not an int for either — `isinstance(True, int)` is True in Python, and
`write_grant.envelope()`'s existing `suggestion_cap` check already excludes bools explicitly.
Follow that same shape.

**Refuse, never default.** `write_grant.envelope()` falls back to `PRICED_CAP` on a bad
`suggestion_cap` — that is correct at GRANT-OPEN time (no round is running; nothing is spent).
At SPEND time the opposite is correct: silently falling back would spend against a cap the
operator never saw. Both new refusals raise.

**Not in this plan, and why (scope fence, judged on merit):**
- **WR-02** (`scripts/role_vocabulary.py` has no test coverage of its pure functions) — a
  repo-root, offline, admin-run inventory script. Untouched by this gap's truth, and the
  verifier itself recorded that shipping it untested matches repo convention
  (`inventory_org_type_values.py` likewise). Leave for a later phase.
- **WR-03** (no Haiku JSON retry/repair per CLAUDE.md §26.3) — same file, same offline admin
  script; it crashes with a traceback rather than spending anything. Neither touches the cap
  invariant, and folding either in widens a deliberately small cost-safety diff. Leave for a
  later phase.
