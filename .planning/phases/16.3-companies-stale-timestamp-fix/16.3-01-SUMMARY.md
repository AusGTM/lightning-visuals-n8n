## Companies Research-Fold Conclusion (Task 2, step 3 — by inspection)

`build_cloud_workflows.py:2216`, inside the `ENRICH_MERGE_CO` wrapper:

```js
finalMerge = {
  canonicalPatch: { ...merged.canonicalPatch, ...researchMerged.canonicalPatch },
  provenance: { ...merged.provenance, ...researchMerged.provenance },
  cacheKeys: { ...merged.cacheKeys, ...researchMerged.cacheKeys },
  decisions: [...merged.decisions, ...researchMerged.decisions],

```

Conclusion: this line only ever **shallow-spreads** `cacheKeys` objects already produced by two `mergeCompanies()` calls (`merged` — the firmographic/waterfall call, and `researchMerged` — the Claude web-research fold). It never synthesizes, re-derives, or writes a cache-key datetime itself. Because both `merged.cacheKeys` and `researchMerged.cacheKeys` now come from the fixed `mergeCompanies()` (promote-gated), the wrapper's spread can only ever carry stamps for promoted fields. **The companies research-fold path inherits the fix for free — no builder edit was needed or made.**

This is verified end-to-end by `tests/n8n/mergeCompanyStaleTimestamp.test.mjs`'s row, which drives its `lv_org_type` value through exactly this `researchMerged` → `finalMerge.cacheKeys` spread (the firmographic `merged.cacheKeys` is empty in that test's row, since `scored.best` is empty) — the GREEN assertion passing after Task 2 is direct proof this spread path is clean.
