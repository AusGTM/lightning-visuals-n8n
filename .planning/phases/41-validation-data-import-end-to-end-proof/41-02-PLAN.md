<objective>
Build the three pieces of live-run instrumentation the phase needs and does not have: a pre-flight
resolver that turns 66 five-week-old HubSpot ids into a verified write allowlist, an automated
provenance assertion inside the existing parity harness, and a tested pair of unpaired
arm/disarm commands implementing D-06's whole-run arming style.

transports and is only ever *run* by the operator in Plans 03 and 04. This plan exists so that when
the operator does run them, the commands are artifacts with tests behind them rather than
improvised one-liners.

unimplemented; D-06's arming style has no existing call path (every exposed arm in the repo binds
arm to dispatch to disarm in one bounded cycle).

three.

<design_decisions_resolved_here>
**F3 — D-06's arm-once-for-the-whole-run has no existing CLI.** RESOLVED: Task 3 builds two thin
repo-side wrappers, `scripts/june_run_arm.py` and a `--disarm` mode on the same file, that call
`n8n_arming.arm_for_dispatch()` and `n8n_arming.disarm()` directly rather than through
`n8n_arming.armed_window`. Every safety check stays where it already lives — inside those two
library functions — because the wrappers add no transport, no JSON mutation and no allowlist
construction beyond joining the resolved id list. `scripts/scheduled_arm.py` is read as a
reference for the idiom and is not invoked: it implements the bounded per-cycle window D-06
explicitly rejected.

The wrappers live in this repo's `scripts/`, not in `operator-claude-plugin/scripts/` —
`.planning/REQUIREMENTS.md`'s Out of Scope table puts plugin changes outside this milestone. The
plugin modules are imported by path, the same way `tests/test_chunk_ceiling_contract.py` already
imports them.

**Parity population definition (D-11).** RESOLVED here so Plan 04 does not have to improvise. A
record parked entirely to `needs_review` promotes no scoring inputs, so its `lv_icp_fit_score`
formula has null terms and blanks entirely (the Phase 40-04 live finding), while the oracle
returns 0 — a structural, guaranteed `real_finding` FAIL that says nothing about engine
correctness. The parity sample for D-11 is therefore the **landed** subset: the resolved ids whose
`lv_icp_fit_score` is present. Parked records are reported under D-12 in the run report, not driven
through the parity FAIL path. Sample selection is already external to the harness
(`PARITY_SAMPLE_IDS`), so this costs no code — but it must be stated, and Task 2's resolver output
plus the provenance fields make the split mechanical.

**Provenance assertion must not break the standing sweep.** `scripts/run_scoring_parity.py` also
runs unattended over records this phase never touches, which legitimately have no provenance. The
assertion is therefore recorded always and enforced only under `PARITY_REQUIRE_PROVENANCE=true`,
which Plan 04's DATA-01 proof run sets and the standing sweep does not.
</design_decisions_resolved_here>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator shell -> deployed n8n workflow | `june_run_arm.py` mutates write-safety constants inside a live production workflow |
| live HubSpot portal -> local report files | resolver and parity output are committed to the repo and must never carry credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-41-06 | Elevation of Privilege | `june_run_arm.py` arm mode | high | mitigate | The kill switch, charset validation and fail-closed re-scan all stay inside `n8n_arming`; the wrapper adds no bypass and a test asserts zero HTTP calls when `ALLOW_N8N_ARM` is absent |
| T-41-07 | Denial of Service | disarm blocked by the same kill switch | high | mitigate | Disarm mode is deliberately not gated on `ALLOW_N8N_ARM`; a test asserts it succeeds without it, so an armed backend can never be stranded |
| T-41-08 | Elevation of Privilege | over-broad write allowlist | high | mitigate | Arm mode passes `record_domains=[]` and `allow_create=False`, so the allowlist is exactly the resolved id set and no domain or create path widens it; an empty `--ids` is refused because an empty allowlist denies everything and would misread as a successful arm |
| T-41-09 | Information Disclosure | credentials leaking into committed reports | medium | mitigate | Resolver and parity reports record ids, outcomes and property values only; `scripts/resolve_june_ids.py` prints no headers, and a grep gate asserts it imports no write primitive |
| T-41-10 | Tampering | resolver silently dropping a record | medium | mitigate | `ambiguous` and `unmatched` are distinct recorded outcomes with their own report entries; the zero-records-examined false-green guard exits non-zero |
| T-41-SC | Tampering | package-manager installs | low | accept | This plan installs no npm/pip/cargo package |
</threat_model>
