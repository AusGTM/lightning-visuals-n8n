| Boundary | Description |
|----------|-------------|
| scheduleTrigger -> HubSpot Search | predicate values are static property names / Code-node-computed epoch millis — no raw user input |
| review approve checkbox -> apply node | a human-flipped HubSpot property drives a canonical write |
| dedupe sweep classify -> review-flag write | sweep output must not itself mutate HubSpot |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-16-02-01 | Tampering | SJ predicate keying on a derived ICP output (Approach-C breach) | high | mitigate | sjPredicates.test.mjs asserts every SJ filter references only lv_org_type / lv_produces_content / their verified-at cache keys / the two control properties — never a derived output |
| T-16-02-02 | Tampering | review-apply reintroduces a derived ICP output field | high | mitigate | reviewApply reuses mergeCompanies canonicalPatch shape; reviewLoop.test.mjs positive + negative cases assert no derived output can enter the patch |
| T-16-02-03 | Tampering | dedupe sweep writes HubSpot directly (bypassing classify-only contract) | medium | mitigate | dedupeSweepWiring.test.mjs asserts the sweep node's params carry no HubSpot URL; flags written by a downstream node only |
| T-16-02-04 | Information Disclosure | operator expects a flat evidence-URL column that no longer exists post-Phase-15 | medium | accept | Evidence lives inside lv_enrichment_review_candidate_json / lv_enrichment_provenance; documented in the operator runbook (16-RESEARCH Deliverable 5) |
