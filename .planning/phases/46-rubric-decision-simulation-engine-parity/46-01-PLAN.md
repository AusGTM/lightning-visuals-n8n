<objective>
Establish the ground truth this phase's remaining work branches on, and prove the simulation
machinery end-to-end on one record before any weight is committed anywhere.

Purpose: two contested facts gate everything downstream. (1) CONTEXT.md D-11 asserts three
scoring engines carry org-type weights; RESEARCH.md's grep found two. The phase is materially
smaller if the n8n leg carries no weight table, but that must be proven and written down, not
assumed. (2) The simulation is the only unproven machinery in this phase — the HubSpot flow edit
is Phase-40-proven on these exact branches, but "score 66 live records twice under two weight
tables in one process" has never been done here.

Output: `46-ENGINE-INVENTORY.md` (the reconciliation, with evidence), a permanent absence-guard
test for the n8n leg, a blank-org_type default-branch guard for the HubSpot flow, an additive
`cfg` override on `compute_icp_score`, and `scripts/simulate_rubric_weights.py` proven to produce
a correct before/after row for one record.

**Deliberate ordering deviation — read this before questioning the tracer's scope.** TRACER_MODE
is on and the orchestrator suggested the tracer be "one weight changed end-to-end: config →
oracle → HubSpot flow → parity green → simulation". This plan's tracer deliberately stops short
of `config/icp_scoring.yaml` and the flow archives, for two reasons that are not stylistic:

1. **RUBRIC-02 says the operator sees the re-tier simulation *before* the weights are committed.**
   A wave-1 config commit inverts that requirement.
2. **The parity red window opens at the config commit, not at the live PUT** (46-RESEARCH.md
   Pitfall 4a: "`config/icp_scoring.yaml` already carries the new value the instant it's
   committed"). `scripts/run_scoring_parity.py` samples real companies, so committing a weight in
   wave 1 turns the standing sweep red for the whole phase plus Phase 47/48/49 — on a decision the
   operator has not yet signed off (D-05) and may override.

The weight commit therefore lives in Plan 04, gated behind Plan 03's blocking sign-off checkpoint.
The tracer here is the simulation slice: it touches every layer the *simulation* crosses (live
read fixture → oracle with an in-memory rubric → before/after row → report line) and it attacks
the phase's actual unproven path.
</objective>

<assumption_delta_decision>
**Noun now primary:** *the rubric* — the org-type weight table, whose canonical representation is
`config/icp_scoring.yaml`.

**Transition:** the rubric used to be read as "a config value in one place". This phase treats it
as one logical rubric with N physical representations (Python oracle, HubSpot Automation v4 flow
`4626124224`, and — per CONTEXT.md D-11, disputed by RESEARCH.md — possibly an n8n JS port). The
org-type weight table has lost its monopoly as a single source of truth.

**Decision: `promote`.** `config/icp_scoring.yaml` is promoted to the rubric of record. Every
other engine's weight table is demoted to a *derived representation* whose only permitted
relationship to the canonical one is "proven equal by test" — never independently maintained.
Rationale: the split-brain failure v0.7 already paid for once is what happens when two
representations are both treated as primary; naming one canonical and making every other one a
test-guarded mirror is the shape that cannot silently diverge.

**Not `add-alongside`:** adding the HubSpot flow as a second co-equal source of truth is exactly
the failure mode RUBRIC-03 exists to prevent.

**Companion invariant (advisory, implemented by this plan + Plan 04):** every org-type weight in
`config/icp_scoring.yaml` has an equal-valued counterpart in every other engine that scores org
type, and any engine that scores nothing carries a permanent proof of that absence.
`tests/test_flow_rubric_conformance.py::test_org_type_flow_matches_rubric` already encodes the
first half (self-updating off the config). `tests/test_n8n_org_type_absence.py` (Task 1) encodes
the second half. Together they go red the instant a future phase reintroduces the split.
</assumption_delta_decision>
