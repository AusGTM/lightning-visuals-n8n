<objective>
Close the last structural gap between the Cloud enrichment webhook and a GENUINE HubSpot
private-app event. Today `ENRICH_PARSE_EVENT_CLOUD` spreads the raw event (`...event`,
build_cloud_workflows.py:3037-3044) so `Build Identity` / `Build Company Identity` can read
`email`/`domain` off a synthetic direct-field test payload; a real event carries none of those
fields, so on the live path both identity builders produce an empty identity and every downstream
lookup, provider call and merge runs against nothing.

Purpose: this is the blocker in front of every meaningful Track-B live verification — including the
bd682a2 research-lane row-loss fix, which shipped into the companies chain and has still never run
under real conditions. It cannot be verified until a real event can drive a real run.

Output: an additive fetch-by-id lane on BOTH branches — `Build (Company) Identity -> IF (Company)
Bare Event -> HubSpot (Company) Fetch By Id -> Adapt (Company) Fetch By Id -> Enrichment Gate /
Company Gate` — with the existing direct-field/caller-envelope lane left byte-for-byte untouched,
plus the new functional/e2e harness that proves it from a raw webhook body through compiled node
bodies.
</objective>
