research/judge node factories by a `target` config (default = companies, byte-identical) so ONE
factory set serves both object types, and additively port the `evidence`/`confidenceByField`
evidence-URL gate onto `mergeContacts` so the contact research fold (Plan 02) has somewhere to
persist evidence + per-field judge confidence. Prove the load-bearing invariant FIRST with a
frozen-snapshot guard test: every companies Code node's emitted jsCode is byte-for-byte unchanged.

concatenates each JS module's full text into the companies Code node, so the only way to reuse the
factories without breaking companies is to (a) parameterize the PYTHON factories with a
companies-defaulting `target`, and (b) keep all field-bound JS in NEW sibling modules the contact
nodes co-inline (Plan 02), never editing judge.js/webResearch.js/scoreEnrichment.js/mergeCompanies.js.
This plan builds and PROVES (a) + the mergeContacts port, so Plan 02 can wire contacts on a substrate
whose byte-identity is guarded, not hoped for. The byte-identity guard is the architectural
proof-of-safety that gates everything downstream — it lands and is proven before any contact node
exists. (This is a refactor-first phase: the vertical contact capability lands in Plan 02; the
foundation must be byte-identical-proven before that slice, so the leading task is a guarded
refactor rather than a vertical tracer.)

Output: parameterized factories + COMPANIES_TARGET/CONTACTS_TARGET configs in
build_cloud_workflows.py, an additive mergeContacts evidence/confidence port, a companies-byte-identity
snapshot guard, and a mergeContacts additive-port test — all offline, deterministic rebuild, green suite.
