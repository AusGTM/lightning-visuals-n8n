<objective>
Two contained fixes on the backend, both one-value changes with a test each.

F-E1: approving a held company whose candidate carries an array value (`lv_content_type:
['unknown']`) sends the raw array to HubSpot and the whole approve 400s — execution `12502`,
the only Stage E failure of attempt 2. The root cause is `normalizeEnumValue`'s documented
container-preserving contract ("array in -> array out"): `reviewApply()` assigns that array
straight into `canonicalPatch`. One line, at the one place both review consumers pass through.

F-A3r: the 250 ms ingest-search throttle left no headroom — 1 residual 429 in 144 searches on a
48-row send, because HubSpot's search budget is account-wide and shared with the scheduled jobs.
D-73-15 sets 400 ms.

Purpose: Stage E must pass in attempt 3 where it failed in attempt 2, and Stage A must show zero
rate-limit errors. Output: two fixed lanes, two new tests, one regenerated tree.
</objective>
