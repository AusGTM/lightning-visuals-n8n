before saying yes, the five ways a grant ends, revocation that bites at the next chunk, and the two
defences 53-CONTEXT.md asked the planner to surface rather than assume.

is disclosure, not constraint. D-53-03 and D-53-04 each accept a real risk and each propose one cheap

bound on how far a run may march while the disarm state is unknown. Both are built here.

`record_send_outcome`, the guardrail-A preflight that fills 53-01's seam, and
`tests/test_write_grant_guardrails.py`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Previous session's leftover state → this session's grant | A session that died armed leaves a live record-scoped allowlist; guardrail A is the only thing that looks |
| Send outcome → grant state | The disarm verdict decides whether the run may continue; a misread verdict is an unbounded march of writes |
| Rate table and balances → the operator's yes | The envelope is what consent is given against; an over-confident figure buys consent to something else |
| Config allowance key → the projected-executions line | An absent or wrong allowance must degrade one line, never fabricate headroom |

<flagged_assumptions>
- **The projected execution count is a projection, not a measurement.** One webhook execution per
  chunk plus one sub-execution per record follows from the enrichment workflow having no batching
  node, which is documented in `max_records_per_chunk`'s own provenance note, but nobody has counted
  executions for a multi-chunk grant end to end. It is labelled as projected in the returned dict and
  should be measured in Phase 54, where the cost model is being corrected anyway.
- **Guardrail A cannot see a lane the grant does not name.** It reads only the grant's own lane
  workflow. A backend armed on a lane outside this grant stays unnoticed. Widening it to every workflow
  the API key can see is a one-line change against `n8n_read.list_workflows` and was left out because
  a refusal citing an unrelated workflow would train the operator to override it. Flagged rather than
  silently scoped.
- **"Ceiling breach" is a close reason with no producer in this phase.** Nothing in Phase 53
  measures spend as it happens, so the reason exists and is testable but is only reached by a caller
  that supplies it. Phase 57 is what makes it fire on its own. Named here so its emptiness is
  deliberate rather than a missed wire.
</flagged_assumptions>
