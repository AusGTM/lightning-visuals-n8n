authorised, in a form that can be re-run immediately before the cutover itself.

is independent read-only reconnaissance against the *old* property, not an expansion of the

pointed at `lv_icp_tier` breaks at that moment. This is the artifact that makes that blast radius
knowable rather than assumed.

    - `find_references(blob, property_name)` -> the list of JSON paths at which `property_name`
      appears anywhere in a nested list/dict structure. Cases: a filter branch naming the property
      -> one path; a name that merely *contains* the property name as a prefix of a longer name
      (`lv_icp_tier_derived`) -> NOT a match for `lv_icp_tier`, so the sweep does not report the
      new property as a dependent on the old one; an unrelated blob -> empty.
    - `render_sweep_markdown(list_findings, flow_findings, scanned_counts, checked_at)` ->
      deterministic markdown, sorted by object type then id; renders an explicit zero-findings
      statement carrying the scanned counts when both finding lists are empty; always emits the
      manual-UI section with its own unchecked placeholder.
  </behavior>
  <action>
Create `scripts/sweep_tier_dependents.py` — **D-13**'s scripted, re-runnable, read-only dependent
enumeration. It issues GET calls only; it must contain no `requests.post`, `requests.patch` or
`requests.delete` call site anywhere, mirroring `scripts/check_schema_drift.py`'s own GET-only
self-description.

Scripted half: enumerate company lists via the Lists API (paginated, following
`scripts/check_hubspot_list_scope.py`'s call shape) and retrieve each list's filter-branch
definition; enumerate flows via `GET /automation/v4/flows` (following
`scripts/fetch_hubspot_flow.py`'s convention) and retrieve each flow body. Walk each returned
structure with `find_references` looking for `lv_icp_tier`, matching on exact property-name tokens
so that `lv_icp_tier_derived` is never reported as a dependent of `lv_icp_tier`. Record for each
hit: object type, id, name, and the JSON path at which the reference sits.

API-blind half: **D-12** names two dependent classes the operator already knows of — sales lists
or saved views filtered by tier, and reports or dashboards grouping by tier — and instructs that
they be treated as confirmed-to-exist rather than as the complete list. Saved views and
reports/dashboards have no documented public HubSpot API (RESEARCH Q3), so the renderer always
emits a dedicated manual-check section carrying an explicit unchecked placeholder and a
`checked_at` slot, so a sweep whose manual half has not been done is visibly incomplete rather
than silently passing as clean.

Write the report to `--out`, defaulting to
`.planning/phases/50-derived-tier-property/50-DEPENDENTS-SWEEP.md`. Re-runnable means a fresh
report every invocation, derived live — never diffed against a cached prior run as the source of
truth. Apply `_assert_no_secrets` to the rendered text before writing. Carry the repo's
dotenv-wrapper invocation with the `sys.argv` pre-seed shape in the docstring, since `.env` is
Read/Bash permission-blocked.

Create `tests/test_sweep_tier_dependents.py` pinning both pure functions offline with fixture
blobs — no network, no credentials. Include the prefix case (a blob naming only the derived
property yields no `lv_icp_tier` finding), the zero-findings case, and a byte-identical re-render
case.
