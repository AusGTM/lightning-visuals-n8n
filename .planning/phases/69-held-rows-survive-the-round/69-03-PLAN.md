<objective>
Build the standalone drain: a skill the operator can invoke any time to work the decline
backlog, with four actions and no fifth. `defer`, `delete` and `export` never leave the
plugin's own filesystem; `send` re-enters the existing write path verbatim and gets no
exemption from any gate a normal send clears.

Purpose: D-69-08's durable surface. A backlog deferred across several rounds has to be
reachable without running a round to get at it.

Output: one new skill directory, one new store function (`export_rows`), one new test module,
the disclosure-audit registration, and the inline end-of-round pointer in `suggest-contacts`.

**Stated decision — the drain skill does not join the four Phase 67/68 prose dicts.**
`test_autonomy_switch_prose.py`, `test_mandatory_report_call_sites.py`,
`test_implicit_approval_contract.py` and `test_interrupt_semantics.py` each iterate a fixed
dict of the four batch skills that open a grant and dispatch. This skill does neither: its
`send` hands the rows to `enrich-before-ingest/SKILL.md` steps 5 and 7, which is where the
`write` autonomy read, `write_grant.plan_grant`, `watch.pre_spend_pause` and the D-67-09
disclosure already live and are already pinned. Joining those dicts would require a SECOND
copy of every one of those literals in a second file — the exact drift the re-entry exists to
prevent. What is pinned instead, in this plan's own test module: the drain skill contains none
of those symbols, it names the two steps it re-enters by number, and a composition test drives
a stored entry through the real gate functions with a stub transport so the gates are proven
to run rather than merely claimed.
</objective>
