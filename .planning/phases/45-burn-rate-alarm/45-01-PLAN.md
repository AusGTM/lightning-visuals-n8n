<objective>
Give the sweep an execution burn-rate alarm, and give every sweep condition a
time-bounded execution lookback instead of a fixed 100-row page.

Purpose: the 2026-08-09 runaway (253 executions/hour, flat, ~182,000/month against a
2,500/month plan) was caught by a human reading a billing page at 80% of the bill.
Nothing in the system said so. This plan makes the system say so — honestly, sampling a
rate over the span it could actually see, never claiming a monthly total n8n makes
unknowable (ALARM-01..04, D-01/D-02/D-03/D-05/D-06/D-07).

The same windowed read is what LOOK-01's folded todo needs (D-08): a fixed 100-row page
makes a fixed failure re-notify for hours or days after its cause is resolved.

Output: `executions_in_window` in `n8n_read`, a widened `sweep_read.gather`, a
`check_burn_rate` condition, three `error_table` rows, three new plugin config keys, and
a new plugin test module.

**`n8n_read.executions_in_window(config, transport=requests.get, now=None,
window_hours=DEFAULT_EXECUTION_WINDOW_HOURS)`.** Leave `recent_executions` and
`EXECUTIONS_PAGE_LIMIT` untouched — `status.py:159` still calls it and this plan does not

Walk pages of `GET {base}/api/v1/executions` through the existing `_get_json` helper,
first page with params `{"limit": EXECUTIONS_WINDOW_PAGE_LIMIT}`, each subsequent page
with `{"limit": EXECUTIONS_WINDOW_PAGE_LIMIT, "cursor": <the previous body's
nextCursor>}`. Pass the cursor as an opaque query-parameter value only; never
interpolate it into the URL path. Stop when any of: `nextCursor` is falsy or absent; the
page's oldest item is older than the cutoff; `MAX_EXECUTION_PAGES` pages have been read;
a page after the first returns None.

THE CURSOR MECHANIC IS THE ONE UNVERIFIED PIECE — nothing in this repo paginates this
API. Design so that a cursor that does not work costs accuracy of SPAN, never accuracy of
RATE: if only the first page is ever read, the rate over that page's own observed span is
still true, and the notice states the shorter span. Do not add a fallback that guesses at
a longer span.

Return None when and only when the FIRST page read fails. Otherwise return a dict with
keys `items`, `window_hours`, `count_in_window`, `observed_span_hours`,
`oldest_started_at`, `covers_full_window`, `truncated_by_page_cap`.

Retention contract (this is load-bearing — a naive `startedAt >= cutoff` filter would
blind `check_stuck` to its own headline case):
- `items` retains EVERY in-flight item unconditionally (status in the existing
  `IN_FLIGHT_STATUSES` frozenset), never age-filtered. An in-flight run is current state,
  not stale history.
- `items` retains a terminal item when its `stoppedAt` is at or after the cutoff, falling
  back to `startedAt` when `stoppedAt` is missing or unparseable. A failure ages out by
  when it ENDED, which is what LOOK-01 actually wants.
- `count_in_window` counts items whose `startedAt` is at or after the cutoff — that and
  only that is the billing-rate numerator, because n8n bills an execution when it starts.
  An in-flight run started 30 hours ago is retained in `items` but does NOT count here.
- Boundary: at-or-after the cutoff is INSIDE. Compute the cutoff as `now` minus
  `window_hours`; reuse `elapsed_minutes` for age rather than reimplementing timestamp
  parsing, and treat its None (unparseable) as "not in window" for counting while still
  retaining an in-flight item.
- `covers_full_window` is true when the walk saw at least one item whose `startedAt` is
  strictly older than the cutoff — that is the proof retained history reaches back at
  least the whole window.
- `truncated_by_page_cap` is true when the walk stopped at `MAX_EXECUTION_PAGES` or on a
  failed later page while `covers_full_window` was still false.
- `observed_span_hours` is `window_hours` when `covers_full_window`, else `now` minus the
  oldest parseable `startedAt` seen anywhere in the walk, floored at
  `MIN_OBSERVED_SPAN_HOURS`; when no parseable `startedAt` was seen at all it is
  `window_hours` (with zero counted executions the rate is zero either way).

State the walk's own blind spot in the docstring rather than inheriting it silently: an
in-flight run both older than the window and deeper than the page walk stays invisible —
the same limitation the fixed 100-row page already had, now written down.
