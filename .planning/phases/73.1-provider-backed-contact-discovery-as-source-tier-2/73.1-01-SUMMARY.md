# Phase 73.1 Plan 01: Re-tier source allowlist to v2 Summary

rank 3, industry/media moved to held rank 4 -- four tier constants pinned by one parity
test, the held-reason prose split truthfully by rank, and a one-person-not-two dedupe
fold that keeps a rank-3/4 corroboration from ever upgrading a row's effective rank.**

## Accomplishments

- Re-tiered `operator-claude-plugin/config/source_allowlist.yaml` to
  `lv-source-allowlist-v2`: LinkedIn relisted at rank 3, the racing/industry entry at
  rank 4, rank 2 permanently absent (adapter-stamped only). `search_fallback.py`'s
  `KNOWN_TIERS`/`LISTED_TIERS` and `suggest_contacts.py`'s `SEARCH_SOURCE_TIERS` updated
  to match, pinned together by a new `test_source_tier_parity.py` (6 tests, all deriving

  silent about the company's own record of them, and explicit that this rank flipped
  from sendable by the 2026-09-18 ruling); rank 4 keeps the pre-existing third-party
  wording with the now-false "not this company's own site or LinkedIn" clause removed.
  The fail-closed unreadable-rank branch's own text was also fixed (said "tier",
  D-10b bans the word from anything operator-visible).
- Added `suggest_contacts.DISCOVERY_LOCATOR_BY_PROVIDER` (zoominfo/apollo/lusha
  synthetic locators) and an optional `provider` keyword on `synthesise_rows` (honoured
  only alongside `source_tier`, so every existing ladder call site stays byte-identical).
- Added `suggest_contacts.dedupe_discovered()`: folds records naming the same person
  (keyed on `linkedin_url` when both carry one, else casefolded
  `firstname+lastname+company`) into one, keeping the lowest-ranked hit's own
  provenance/locator/jobtitle and recording every other hit as
  `provenance["corroboration"]` -- which never changes the survivor's own `source_tier`.
