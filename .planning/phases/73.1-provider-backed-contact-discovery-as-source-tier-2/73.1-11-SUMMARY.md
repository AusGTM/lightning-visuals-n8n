## Decisions Made

- Discovery lane's token gate mints unconditionally every execution, reading no cross-run cache — this lane runs exactly one execution per round (D-08), so the cache the enrich lane keeps buys at most one free mint in exchange for the whole stale/rejected-token failure class. The enrich lane's own gate and cache are untouched.
- Task 2's offline replay proved `prior_token_invalidated_by_later_mint=true`. Filed a `kind: design` todo for the enrich lane's cache tradeoff rather than changing it — the plan's own explicit scope boundary, and the enrich lane's leaf already self-heals on its next 401.
- [Rule 1 deviation] Execution 12670 returned `400`, a status the plan's branch table did not enumerate. Resolved by the plan's own objective reasoning ("a malformed query string yields 400, not 401") — applied the 401-branch's prescribed fix anyway, confirmed correct by execution 12671's 200. See "Deviations from Plan" below.
- Diagnosed the 400 entirely offline (zero live cost) via a direct Python replay before spending a second live execution, rather than guessing or spending a live send to gather the same evidence.
- `extractErrorDetail(e)` reads only named JSON:API fields (`code`/`title`/`detail`/`source.pointer`), never the raw response body — mirroring this repo's create-error-path rule that a raw error body can echo the outbound request's own Authorization header.
