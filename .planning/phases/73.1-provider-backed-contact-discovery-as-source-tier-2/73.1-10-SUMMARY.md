## Decisions Made
- `titlesForFamilies` treats an unrecognised label as a no-op rather than throwing — the plugin (`role_classify.chosen_families`) is the only label validator; duplicating that check in the lane would be a second, driftable copy of the same rule (also the mitigation for threat T-73.1-10-01).
- Empty/absent `role_families` deliberately falls back to every member in map order, preserving the pre-D-11a behaviour for any caller (e.g. an older plugin build, or a request that omits the field) rather than filtering to nothing.
- Reused `tests/n8n/columnMapIdentityParity.test.mjs`'s Python-oracle idiom (`execFileSync(.venv/bin/python, ['-c', '...yaml...'])`) instead of writing a second, driftable JS YAML reader — the plan explicitly asked to check that sibling first.
