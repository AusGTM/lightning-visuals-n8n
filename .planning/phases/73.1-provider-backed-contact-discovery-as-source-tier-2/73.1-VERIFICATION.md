**CR-01** (`73.1-REVIEW.md`): the D-11 fix itself — the discovery lane's now-unconditional,
cache-free ZoomInfo mint — composes with two facts already documented elsewhere in this

since the D-11 fix landed has exercised 2+ gap companies with a genuinely cold cache (executions
`12670`/`12671` were both single-gap-company sends).

**Fix status:** offline-fixed and offline-tested (`executeOnce: true` on the "ZoomInfo Search
Mint" node + `combineAll` broadcast of the single minted token to every carried row — both
confirmed present in `n8n/wf_suggest_discovery_cloud.json` and pinned by a dedicated
`suggestDiscoveryLane.test.mjs` test in this session's own test run). Deployed and bounced live
disarmed 2026-09-19 (orchestrator deploy record in `73.1-REVIEW-FIX.md`; live node counts
33/98/287/55/43/26 match committed, re-confirmed independently in this session by reading the
committed JSON directly).

**Why this is not marked FAILED:** D-11/D-11a's own live evidence (execution `12671`) stands
independently and is not undermined by CR-01 — CR-01 is a defect in a round shape (2+ gap
companies) that was never the scenario D-11/D-11a's live proof exercised. **Why this is not
marked VERIFIED:** the fix's correctness depends on two n8n engine behaviors —

Merge's `combineAll` cartesian broadcast — that this codebase's own platform-facts table
(CLAUDE.md §13.0.3) tags `[documented]` only, never `[observed live]`, for this exact node/mode
combination. This is the state-transition class the verification process routes to
⚠️ PRESENT_BEHAVIOR_UNVERIFIED: present in the code, wired into the graph, offline-tested — but
the specific behavior (does the real engine actually broadcast one token to every row without
re-invalidating any of them) has not been exercised by a live multi-company round. See Human
Verification below.
