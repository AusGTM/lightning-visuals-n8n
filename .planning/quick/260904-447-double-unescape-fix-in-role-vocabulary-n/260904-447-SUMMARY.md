# Quick Task 260904-447: Double-unescape fix in role vocabulary + reject the derived vocabulary — Summary

One-liner: bounded fixed-point `html.unescape` loop (not a single pass) fixes a live selection
miss on double-encoded portal titles at both the derivation and match-time seams, and the
operator's REJECT ruling on adopting the portal-wide derived vocabulary is now a LOCKED decision
record.

## What was built

**Root cause:** the HubSpot portal stores DOUBLE-encoded HTML entities
(`Finance &amp;amp; Admin Officer`). Both `scripts/role_vocabulary.py::_normalize_title`
(derivation seam) and `operator-claude-plugin/scripts/role_classify.py::_tokenize` (match seam)
called `html.unescape` exactly once, leaving one layer of encoding (`&amp;`) behind. At the
match seam this was not cosmetic — the orphaned `amp` token wedged into the middle of a
contiguous token run defeated `_contains_run`, so `classify_title('Finance &amp;amp; Admin
Officer', shipped_families)` returned `None` even though `Finance and Admin Officer` is a real
shipped member of the `Treasurer` family.

**Task 1** — `scripts/role_vocabulary.py`: added `MAX_UNESCAPE_PASSES = 5` and replaced the
single `html.unescape()` call in `_normalize_title` with a bounded fixed-point loop (`for _ in
range(MAX_UNESCAPE_PASSES): decoded = html.unescape(text); break if decoded == text; else
text = decoded`), applied before the existing whitespace-collapse. Docstring extended in place;
the existing D-3 both-sides-of-the-seam rationale preserved verbatim.

**Task 2** — `operator-claude-plugin/scripts/role_classify.py`: same constant and same loop
shape applied inside `_tokenize`, ahead of `.casefold()`. No change to `classify_title`,
`_contains_run`, `load_families`, or `chosen_families`. A cross-tree drift test
(`test_both_trees_unescape_to_the_same_bounded_fixed_point`, in the root suite) pins
`role_vocabulary.MAX_UNESCAPE_PASSES == role_classify.MAX_UNESCAPE_PASSES` and asserts both fully
decode the same double-encoded input — the mechanism that makes the deliberate two-tree
duplication safe rather than driftable.

**Task 3** — doc-only. Created
`.planning/decisions/2026-09-04-derived-role-vocabulary-rejected.md` (Status: LOCKED) recording
the operator's REJECT ruling on adopting the portal-wide derived vocabulary, with the measured
acceptance-run numbers reproduced verbatim (8 corporate-only derived families, zero governance
families, 200/2,044 distinct titles / 1,855/3,771 titled contacts = 49% head coverage). Added a
pointer comment (no new printed line) at `scripts/role_vocabulary.py::_print_drop_list`, the seam
printing the `cp {derived} {shipped}` line a future reader would act on, naming the decision
record by path.
