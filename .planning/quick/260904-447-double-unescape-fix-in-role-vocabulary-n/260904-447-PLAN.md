<root_cause>
The portal stores double-encoded entities. Both normalisers call `html.unescape` exactly
once, so one layer survives. Verified at planning time, offline, no live call:

```
input             : 'Finance &amp;amp; Admin Officer'
one pass          : 'Finance &amp; Admin Officer'
two passes        : 'Finance & Admin Officer'
tokens double-enc : ('finance', 'and', 'amp', 'admin', 'officer')
tokens member     : ('finance', 'and', 'admin', 'officer')
```

The surviving `&` correctly becomes ` and `; the orphaned `amp;` becomes the junk token
`amp`, wedged into the MIDDLE of the run. `_contains_run` requires the member's four tokens
to appear contiguously, so it returns False. `Finance and Admin Officer` is a real shipped
member of the `Treasurer` family (`operator-claude-plugin/config/role_vocabulary.yaml`), so
this is a live selection miss on a real family, empirically confirmed, not inferred.

Per this project's standing rule — fix it once, where all callers route through, not in each
caller — the fix is the same bounded fixed-point unescape applied at BOTH seams:

1. `scripts/role_vocabulary.py::_normalize_title` — derivation side (repo tree).
2. `operator-claude-plugin/scripts/role_classify.py::_tokenize` — match side (plugin tree).
</root_cause>
