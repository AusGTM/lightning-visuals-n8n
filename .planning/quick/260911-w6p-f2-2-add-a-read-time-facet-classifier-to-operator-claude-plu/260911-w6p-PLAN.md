Add to `held_queue.py`: `VERB_CREATE = "create"`, `VERB_SKIP = "skip"`, `VERB_RETRY =
"retry"`, `VERB_DROP = "drop"`, `ALL_VERBS` (frozenset of the four), `SETTLED_VERBS =
frozenset({VERB_CREATE, VERB_SKIP, VERB_DROP})`, and `STATUS_FIELD = "status"`.

`status` is an OPTIONAL fifth key on an entry: `{"verb": <one of ALL_VERBS>, "at": <UTC
isoformat>, "run_id": <the run that recorded it>}`. Absent means undecided, which is what
every entry the queue holds today is.

Three functions:

  - `entry_verb(entry)` -> the verb string or `None`; tolerant of a non-dict entry and a
    non-dict `status`, so a reader never has to guard the shape itself.
  - `is_settled(entry)` -> `entry_verb(entry) in SETTLED_VERBS`. `retry` is deliberately
    NOT settled: it is the operator asking to look again, the same disposition
    `rows_to_resume` already gives `unchecked`.
  - `open_entries(entries)` -> the subset with no settled verb. One comprehension over
    `is_settled`, so w6q's table and any later report call ONE filter instead of each
    growing its own.
  - `record_verb(row_id, verb, run_id, path=None)` -> load, stamp, save, and return the
    updated `{row_id: entry}` map. Refuses — raising `HeldQueueError`, writing nothing —
    a verb outside `ALL_VERBS`, a `row_id` the loaded queue does not hold, and a `run_id`
    that trips the existing `_looks_forbidden`. The run id in the saved document is the
    one passed in, so the file keeps naming the run that LAST TOUCHED it rather than the
    run that first held the rows. Record that in one docstring line: it is safe today
    because `held_queue.classify_read()` has exactly one caller
    (`run_report.py:995`) and it passes no `expected_run_id`, so nothing compares the
    document's run id to an expected one — a future caller that does must read this line
    first.

None of the four verbs deletes an entry. The memory IS the protection: an entry that
disappeared on `create` would be re-held identically by the next run that meets the same
row.

Extend BOTH validation points, mirroring exactly how `hold_code` is already handled on
each side — `save()` raises `HeldQueueError` (validate every entry before anything is
written, so a refusal leaves the previous queue intact) and `_validated_entries` returns

missing `status` is valid; a present one must be a dict whose `verb` is in `ALL_VERBS`.

`run_id` is checked by name at `record_verb`.
