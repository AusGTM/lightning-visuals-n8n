# Quick Task 260904-39r: Role Vocabulary Derivation Fix Summary

Fixed `scripts/role_vocabulary.py` so it can derive an evidenced role vocabulary from a
non-sparse portal without crashing on a truncated Haiku response, closing gap **G-62-5**
in `.planning/phases/62-suggest-the-contacts-nobody-named/62-UAT.md`.

## What Was Built

**Task 1 — named truncation guard, tolerant parse.** `cluster_titles` now checks
`msg.stop_reason == "max_tokens"` before touching the response text and raises a new
`RoleVocabularyDerivationError` naming the stop reason, the number of titles sent, and
the `max_tokens` ceiling. A complete-but-unparseable response gets exactly one repair
retry (CLAUDE.md §26.3), reusing `src.web_research._extract_json` rather than a second
fence-stripping parser. `max_tokens` raised 2000 → 8000.

**Task 2 — rank-then-cluster head, normalise once.** `build_portal_vocabulary` now ranks
ALL distinct titles by recurrence first (`head_titles`, cheap, no model call) and sends
only the top `HEAD_N = 200` to `cluster_titles` — this is the actual fix for the live
failure (2,045 titles / 16,079 input tokens). `_normalize_title` (html.unescape +
whitespace collapse) is applied once inside `sweep_all_jobtitles` at count time, and
identically to each family member `rank_top_families` reads back before its exact
`in counts` check — closing the whole silent-drop class the UAT's `&amp;` case exposed, not
just that one instance. A conservative junk filter (fewer than 2 alphabetic characters)
drops phone numbers while deliberately keeping short real labels like `AV`. `--head N`
added to the CLI, defaulting to `HEAD_N`. `build_portal_vocabulary` prints a measured
coverage line (head size / distinct total, contacts covered / titled contacts) rather than
assuming 200 was enough.

**Task 3 — derived output path, drop-list warning, dry-run stays write-free.**
`_write_cache`'s default target moved from the shipped `role_vocabulary.yaml` to a new
sibling, `role_vocabulary.derived.yaml` — `role_classify.DEFAULT_VOCABULARY_PATH` still
names the shipped file exactly, so the plugin never reads a derived run. A successful
non-dry-run write prints which shipped family labels are absent from the derived output
plus the exact `cp` command to adopt it. `VOCABULARY_VERSION` bumped `v1` → `v2`.
`.gitignore` gained the derived path (a run artifact, never a deliverable).
