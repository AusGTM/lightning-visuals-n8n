# Quick Task 260904-5a8: companies match.reason names domain/name resolution, not contacts vocab — Summary

One false sentence fixed, one diagnosis note written. A companies row's response used to
report `match.reason: "no searchable identity — the row has no email, object id, or
name+company pair"` — contacts vocabulary about a row with a perfectly good domain, because
it fell through `summarizeMatch`'s generic `lane === "none"` fallthrough (`row.lane` is
always `undefined` on the companies branch). It previously misdirected an investigation
toward a claimed `Merge Company` row-drop that does not exist.

## Premise corrections (C1–C3), re-verified this session with file:line evidence

- **C1 — `laneOf` is never called on the companies branch.** Only `Build Identity`
  (contacts) stamps `lane` (`scripts/build_cloud_workflows.py:1278`, unchanged).
  `Build Company Identity` (`build_cloud_workflows.py:2124-2141`) stamps `identity_keys`
  and no `lane`. Confirmed by walking `Decide Company Action`'s built jsCode: before this
  fix it called `summarizeMatch({ lane: row.lane })`, and `row.lane` is structurally
  `undefined` for every company row. **No `laneOf` change was made.**
- **C2 — `lane` is a live routing key on the contacts branch** (`IF Has Email`,
  `IF Name Searchable`, `IF Linkedin Searchable`, `Adapt Search`, `Adapt Fetch By Id`,
  `Adapt Name Search`, `Adapt Linkedin Search`). The new `"company"` value is a
  **call-site literal only** — passed directly at `scripts/build_cloud_workflows.py`'s
  `ENRICH_DECIDE_CO_CLOUD` `match:` line, never assigned to any row's `.lane` field — so
  it structurally cannot reach any of those seven `lane ===` tests. Verified live:
  `wf_enrichment_cloud.json`'s only remaining `summarizeMatch({ lane: row.lane })` caller
  is `Decide Action` (the contacts twin); `Decide Company Action` now carries
  `summarizeMatch({ lane: "company" })` exclusively (checked via the plan's own
  node-scan `<verify>` command, output: `ok ['Decide Action']` for the `row.lane` list,
  and a companies-literal scan returning `['Decide Company Action']`).
- **C3 — contacts rows do carry `identity_keys.domain`** (`build_cloud_workflows.py:1263`,
  unchanged, not touched by this plan). No lane was renamed or added to any row; this fact
  is recorded as-is per the plan and required no follow-up code.

**Consequence held:** no `laneOf` edit, no lane value added to any row. The fix is exactly
one new `summarizeMatch` arm in `n8n/code/matchProposal.js` plus one call-site literal
change in `scripts/build_cloud_workflows.py`.
