# Phase 16.1 Plan 02: Credit Reporting + Schedule Safety Summary

**Single-item credit branch (one usage call per provider per run, not per row) feeding an honest `remaining_credits` webhook response, a read-only `check_provider_credits.py` CLI, and an explicitly inactive scheduled-maintenance workflow with a deploy-never-activates guard.**

## Accomplishments

- A dedicated single-item `Credit Request` branch forks off `Parse HubSpot Event` (never the multi-row terminal/enrichment flow) so each provider's usage/credit check fires **at most once per run** — closing the live-observed Lusha 5 req/min 429-under-per-row-firing failure mode (reviews C1).
- Per-provider `IF <provider> Credit Requested` gates feed credential-bound credit HTTP nodes: Lusha `GET /v3/account/usage`, Apollo `POST usage_stats` (both `httpHeaderAuth`), and a ZoomInfo split shape — a distinctly-named `ZoomInfo Usage Mint` (credential-bound Basic Auth) followed by a secret-free `ZoomInfo Usage` Code node GET with the live-required `Accept: application/vnd.api+json` header.
- The webhook moved from `responseMode: lastNode` to `responseNode` + a new `Respond to Webhook` node fed by `Build Response`, a convergence reachable from every enrichment terminal (5 real terminal nodes + the 2 previously dead-ended `IF Enrich`/`IF Company Enrich` false lanes + the unsupported-object-type terminal). `Build Response` reads each credit node by name via the guarded `nodeAll` idiom and assembles `remaining_credits: [{provider, credits}]` for exactly `providers_requested` (none → `[]`).
- Response semantics are documented **honestly** — per-batch first-arrival (parity with the prior `lastNode` behavior), not hard determinism across a mixed batch — in both `Build Response`'s own jsCode comment and an in-graph sticky note (reviews C3). The true 0-event/empty-body case and exact multi-terminal arrival ordering are recorded as Track B execution-level items.
- New `scripts/check_provider_credits.py`: a read-only CLI mirroring `provision_n8n_credentials.py`'s idiom (`_has_<provider>()` gates, "skipped (no provider creds)" + exit 0 with zero requests), importing `PROVIDER_REGISTRY` from the side-effect-free `scripts.provider_registry` (never `build_cloud_workflows`, whose import writes codegen files — reviews A3). Re-implements the three null-safe credit extractors in Python; every failure path (4xx/5xx/timeout/malformed/ZoomInfo mint-fail) degrades to `credits: null` without raising, and no secret value is ever printed.
- `scripts/deploy_n8n_workflows.py`'s `NODE_CREDENTIAL_MAP` gains entries for the three new credit nodes, reusing the already-provisioned `LV Lusha`/`LV Apollo`/`LV ZoomInfo` credentials (reviews C2) — the secret-free `ZoomInfo Usage` GET needs no binding.
- `build_scheduled_maintenance_cloud()` now emits an explicit `"active": false`, with a precisely-worded sticky note and code comment: the functional guarantee is deploy never POSTing to `/activate` (inactive-on-create only) — an already-active workflow is **not** deactivated on update, stated honestly rather than overclaimed (reviews A5).
