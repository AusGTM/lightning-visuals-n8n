# Phase 16.1 Plan 01: Provider-Selection Cost Gate Summary

**Per-request `providers` webhook field is now the live burn gate on BOTH waterfalls — a disabled provider's HTTP node never executes, an unsupported object type never reaches a provider, and a mixed create/enrich batch no longer double-fires the gate chain — all proven offline via a shared bypass-convergence builder helper (the Phase 16.2 reuse seam).**

## Accomplishments
- `n8n/code/providerSelection.js`: pure `resolveEnabledProviders`/`parseWebhookBody`/`extractCredits`, node-tested (22 cases) — the "all"/"none"/blank/absent/array resolution, the A4 envelope-vs-bare-array payload contract, and the three null-safe credit extractors forward-provisioned for Plan 02.
- `scripts/provider_registry.py`: side-effect-free single-source `PROVIDER_REGISTRY`/`PROVIDER_NAMES`, importable without triggering `build_cloud_workflows.py`'s taxonomy/escalation codegen writes (reviews A3).
- `Parse HubSpot Event` now resolves `providers` via the explicit contract and threads `provider_enabled`/`providers_requested` onto every emitted row.
- A new `IF Object Type Supported` gate (reviews A2) terminates any object type other than `companies`/`contacts` at a no-op node before `Route By Object Type` (left structurally unchanged) ever runs — closing the malformed-event credit-burn hole.
- A single `IF Provider Processing Needed` (`action != "skip"`) dispatch lane replaces the old Route Action switch's create+enrich double-feed (reviews A1), so the gate chain and `Normalize + Score` fire exactly once per batch.
- Both the contacts and companies provider waterfalls are gated behind `IF <provider> Enabled` / bypass-convergence, emitted by the ONE new shared `_provider_gate_bypass_chain(...)` helper (CONTEXT Locked Decision 8) — a disabled provider's node never executes; every gate's bypass lane rejoins so `Normalize + Score(+ Company)` always fires, even with zero providers enabled.
- Every provider request body and every gate condition now reads identity/`provider_enabled` BY NODE NAME (`$('Enrichment Gate')`/`$('Build Company Requests')`/`$('Parse HubSpot Event')`), closing a latent identity-loss bug where a provider positioned after another provider's HTTP node would see that provider's response as `$json` instead of the row.
- The contacts branch carries a documented + in-graph Phase 16.2 seam (builder comment + sticky note) at `Normalize + Score -> Merge Winners`, naming it the contacts research→judge mirror insertion point — no research/judge runtime node is built here.
- The companies `Lusha Company` POST-to-static-URL / live `GET /v2/company?domain=` mismatch is flagged in-source as a Track B validation item (reviews LOW-5), not corrected in this offline-only phase.
