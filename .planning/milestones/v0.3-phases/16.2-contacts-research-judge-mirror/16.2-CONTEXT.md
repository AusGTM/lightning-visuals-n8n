## Reasoned Decisions (defaults for the planner; the cross-AI review should challenge these)

1. **Target fields = `jobtitle` + `seniority`** (the web-verifiable role signals). Persona_group and lv_linkedin_url are candidates but secondary. **EXCLUDE `phone`/`mobilephone`/`email`** — provider-only, not reliably web-researchable, and PII-sensitive (CLAUDE.md §16 "do not save unnecessary raw personal data"). This keeps contact web-research to public role facts.

2. **Reuse the node factories by PARAMETERIZING them, not forking company-bound copies.** Refactor `_enrich_research_gate_js`/`_enrich_build_request`/`_enrich_judge_gate`/`_enrich_build_judge_request`/validate/apply to accept a target (contacts|companies) that selects the field set, prompt, escalation reasons, and verdict application. The companies branch must remain byte-identical in its emitted output (parameterization is a pure refactor for companies — guard with the determinism/frozen tests). This IS the "one set of building blocks" the user asked for.

3. **Contact research prompt** asks public sources for the person's CURRENT role/title/seniority at their company (LinkedIn, company team/about pages) — NOT company ICP questions. Prefer unknown over guessing; require an evidence URL; same free-text-JSON single-HTTP-call pattern as companies (D3), never a forced tool_use.

4. **Judge (escalation) triggers for contacts**: provider-vs-research conflict on jobtitle/seniority, a stale jobtitle refresh (jobtitle is `stale_refreshable`), or a hard provider miss the research fills. Reuse the SAME kill-switch + cost cap (`ALLOW_SONNET_ESCALATION` default off, `MAX_SONNET_VALIDATIONS_PER_RUN`) and the never-throw verdict handling.

5. **Cost-safety inherits 16.1**: research runs only when `ALLOW_WEB_RESEARCH` is on (default OFF) AND a gap is detected; judge only when `ALLOW_SONNET_ESCALATION` is on (default OFF) AND a trigger fires. `providers: none` → no provider data → research (if enabled) fills from scratch, mirroring companies. No new global switches (16.1 Decision 1 stands).

6. **Insertion point = the 16.1 seam**: contacts `Normalize + Score → [Research Trigger Gate → IF Research Needed → Build Research Request → Claude Web Research → Validate Research Output → Judge Gate → IF Needs Judge → Build Judge Request → Judge Call → Apply Judge Verdict] → Merge Winners`. Do not re-plumb the provider fan-out.

7. **PII constraint**: persist only the verified field value + evidence URL + provenance; do not stash raw scraped personal data (CLAUDE.md §16).
