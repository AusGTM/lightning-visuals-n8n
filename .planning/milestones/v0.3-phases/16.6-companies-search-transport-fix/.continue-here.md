## Hard-won lessons — read before any live work

1. **An offline-green suite says nothing about the transport layer.** Ten live-only bugs this
   session, every one passing a full suite and deploying clean.
2. **Never judge a live run by the webhook's HTTP 200.** Canary run 1 returned a perfectly plausible
   `{"action":"skip"}` 200 while the fetch was silently 400ing. Inspect the execution API
   node-by-node, every time.
3. **n8n swallows node errors when `onError: continueRegularOutput` is set.** Temporarily clearing
   it on one node, re-firing, and reading the execution is the diagnostic that worked repeatedly —
   then restore it (a redeploy from source does that).
4. **With all three providers enabled the contacts research gate CANNOT fire** — providers supply
   `seniority`, closing the `provider_gap`. Reaching research needs ZERO providers plus a bare event
   array. "Enable everything" is not the most thorough test.
5. **Do NOT use `gsd-tools state.advance-plan` / `state.update-progress`** — they corrupt STATE.md
   here (observed: `16.3-01` → `17.3-01`). Hand-edit.
6. `tests/n8n/mergeContacts.test.mjs` has a known millisecond-boundary flake — re-run to confirm,
   never "fix" it.
