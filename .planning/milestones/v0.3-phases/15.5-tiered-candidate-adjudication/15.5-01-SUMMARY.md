# Phase 15.5: Tiered Candidate Adjudication Summary

**Research candidates are scored by the same unmodified A/R/G/T engine the provider waterfall uses, gain a `recencyDate` sourced from Anthropic's `page_age`, and are self-confirmation-guarded against re-agreeing with the pipeline's own earlier guess — the judge now gets the full ranked set and grounding it never had, while the size/firmographic tier boundary and the recency-never-gates invariant are both proven structurally, not by convention.**

## Accomplishments

- **Wave-0 gaps closed first, exactly as the plan required.** `mergeCompanies.js` — a module that has survived four phases with zero direct unit tests — got its first-ever test file (10 tests, zero production change, Task 1's own commit). `MAX_SONNET_VALIDATIONS_PER_RUN`'s enforcement was extracted from an untested inline counter into a pure, exported `applyCostCap(rows, maxPerRun)`, asserted numerically at 15-into-10 and at a zero budget (Task 2).
- **`recencyDate` now comes from a real signal.** `extractPageAgeByField` + `normalizeUrlForMatch` (`n8n/code/webResearch.js`) recover Anthropic's `page_age` from the raw `web_search_tool_result` blocks the HTTP node already returns — the exact array `researchCandidateFromHttpItem` already read but silently discarded (Task 3). Match rate is now observable via `recency_source_by_field` ("page_age" | "unmatched").
- **The core of the phase: `scoreResearchCandidates` (Task 4).** Every judge-eligible research field is scored against a "prior on file" candidate, built from the existing HubSpot record + its Phase-15 provenance blob, using the SAME unmodified `scoreCandidates` engine. **The self-confirmation guard (D1)** is the primary structural decision, not a filter bolted on afterward: a prior with no provenance entry (legacy) or a `human`/`manual` source is independent and joins the research candidate in one scoring call (real agreement); every other source — including every source this pipeline itself writes — scores in a SEPARATE call, alone, so agreement can never be manufactured from the pipeline agreeing with its own earlier guess. Unrecognized sources fail CLOSED.
- **The judge is grounded, not just evidenced (Task 5).** `buildJudgeRequestBody` gained one `scoring` key, restricted to the same judge-eligible field list the existing `data` key already uses (JG-2 held by construction — no numeric firmographic value can appear because no such field is ever in the list). The prompt now explicitly tells the judge that `prior_on_file` is not independent corroboration and that recency is ordering information, never a rejection reason.
- **D2 proven arithmetically, not just declared.** `mergeCompanies` gained an additive `opts.confidenceByField` carrying the JUDGE VERDICT's own 0-100-scale confidence (never the A/R/G/T composite). A DELIBERATE-BREAK test wires the composite directly into the gate and shows a previously-promoted field collapse — proving RESEARCH.md's literal TA-8 recommendation was rejected for cause, not style.
- **Spec + traceability closed (Task 6).** `docs/WEB-RESEARCH-SPEC.md` §8.5 authors TA-1..TA-8 with a Requirements→Test map whose every named test was run and verified to exist before being written down.

## Decisions Made

- **D1 (self-confirmation guard):** independence is determined by provenance `source` only — no entry (legacy) or `human`/`manual` is independent; everything else, including every pipeline-owned source, is not, and unrecognized strings fail closed. Rationale: without this, re-researching a company lets the model agree with its own earlier (possibly wrong) classification and manufacture confidence invisibly, exactly where detection is hardest.
- **D2 (LOCKED, rejects RESEARCH.md's literal TA-8):** the composite score never feeds `mergeCompanies`' promotion gate. Verified arithmetically: G=0 (the common single-candidate case), A=0.88, R=1.0, T=0.78 → composite 0.674 → 67, below both `lv_org_type`'s 80 and `lv_produces_content`'s 85 thresholds. `opts.confidenceByField` instead carries the judge verdict's own per-field confidence.
- **D3:** `scoreResearchCandidates` folds into the existing Judge Gate node — zero new nodes, zero new connections, zero new HTTP calls; RO-2's existing graph-ancestry + jsCode-absence test covers the fold unchanged (with one added assertion pinning the cap's location).
- **D4:** `scoreCandidates` gains one additive `ranked` key; existing `best`/`winners` callers are unaffected (byte-identical, regression-proven).
