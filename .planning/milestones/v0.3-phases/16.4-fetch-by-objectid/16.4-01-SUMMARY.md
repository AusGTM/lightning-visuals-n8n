## Accomplishments
- Today's `ENRICH_PARSE_EVENT_CLOUD` shim (spreading the raw event so a direct-field test payload's email/domain reach `Build Identity`) is no longer the only path forward: a genuine HubSpot event carrying only `objectId`/`objectType` now drives a fetch that backfills `identity_keys` from the real record.
- Both branches carry a credential-bound, CRM-v3-search-based fetch-by-id node (`HubSpot Fetch By Id` / `HubSpot Company Fetch By Id`), reusing the existing `_hs_search_node()` helper verbatim — never the node's single-record retrieval operation (confirmed unusable per RESEARCH: sunset v1/legacy-v2 endpoints, non-flat `{value,timestamp}` shape).

- A 0-result search on a known `hs_object_id` fails closed via the existing `lookup_failed` → create-to-skip override — zero new failure vocabulary.
- New e2e harness (`tests/n8n/bareEventChainFlow.test.mjs`) is the first test in this repo to drive a payload from the raw webhook body through `Parse HubSpot Event`, proving both chains end-to-end to a patch payload targeting the real fetched record id.
- Existing lanes (`HubSpot Search`, `HubSpot Company Search`, `Route By Object Type`) are untouched byte-for-byte; the frozen companies research/judge fixture (7 pinned node bodies) is unmoved.

## Decisions Made
- Fetch by native `n8n-nodes-base.hubspot` `search` filtered on `hs_object_id EQ` (RESEARCH-confirmed; the node's single-record retrieval operation is unusable).
- Gate sits AFTER the identity builders, not before `Route By Object Type` — preserves the pinned edge assertion in `tests/test_cloud_write_path.py` and reuses `identity_keys` the builders already compute.
- Two branch-specific node sets rather than one object-type-conditional node, consistent with every other stage in this file.
- `backfillIdentityKeys` never overwrites a caller-supplied value; companies `domain` is defensively re-cleaned through the same `cleanDomain()` as `ENRICH_BUILD_CO_IDENTITY`.
