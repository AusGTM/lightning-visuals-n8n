## Accomplishments
- `enable_baked_flags(workflow, flags)` added to `scripts/deploy_n8n_workflows.py`, directly below `bind_credentials()`, in its exact shape: pure, deep-copying (`json.loads(json.dumps(...))`), never mutates the input, fails closed via a post-rewrite serialized re-scan with a looser (whitespace-tolerant) regex than the exact-literal replace step — catching spacing/numeric drift the replace itself cannot match.
- `_OVERLAYABLE_FLAGS = frozenset({"ALLOW_WEB_RESEARCH", "ALLOW_SONNET_ESCALATION"})` — a closed two-name set enforced by `ValueError`, never imported from `build_cloud_workflows` (which runs codegen at import time).
- `_requested_overlay_flags()` reads `ENABLE_BAKED_FLAGS` (comma-separated), deliberately distinct from the `.env`-resident `ALLOW_WEB_RESEARCH`/`ALLOW_SONNET_ESCALATION` names — proven inert by a dedicated test (`test_ambient_env_names_have_zero_effect_on_the_captured_put_body`).
- `main()` wired to apply the overlay above the write gate, printing a per-flag rewrite plan and refusing (zero HTTP calls) if any requested flag matches zero declarations across the whole deploy set.
- `tests/test_enabled_build_invariants.py`: the committed build stays disabled (non-vacuously), Criterion 5 holds on the ENABLED build (imports the architecture guard's own regex rather than retyping it), the enabled-vs-committed diff touches only the four flag lines, write-safety constants and both cost caps are unchanged on the enabled build, and `_OVERLAYABLE_FLAGS` is pinned as a strict subset of `CONFIG_FLAG_DEFAULTS`.
- `tests/n8n/enabledResearchLaneFlow.test.mjs`: a second, independent JS reimplementation of the exact-literal rewrite drives the enabled node bodies through both research-then-judge lanes end-to-end, from a raw bare-event webhook body, with a disabled control proving the overlay is the cause.

## Decisions Made
- Deploy-time overlay (CONTEXT's leading candidate) confirmed as-is against the code — no alternative mechanism was needed or considered further; see `<design_decision>` in the plan for the full tradeoff analysis, unchanged by execution.
- `ENABLE_BAKED_FLAGS` chosen as the operator flag name specifically because this repo's `.env` already defines `ALLOW_WEB_RESEARCH`/`ALLOW_SONNET_ESCALATION` for the Python harness lane — a same-name overlay would have armed production on a routine deploy from a developer machine with that `.env` sourced.
- The offline oracle's escalation trigger for companies is `produces_content_false` rather than `org_type_conflict`, because the same fixture that makes the research gate fire (a blank existing `lv_org_type`) structurally prevents `org_type_conflict` from ever firing (`computeEscalation` requires an existing KNOWN org type to compare against). This is documented inline in the test file so a future reader is not surprised.
