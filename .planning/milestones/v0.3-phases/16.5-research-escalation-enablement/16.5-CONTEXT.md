## The central design decision

**Rejected: flipping `CONFIG_FLAG_DEFAULTS` to `"true"`.** It would make every subsequent build ship LLM-spending paths on by default, and any routine rebuild-and-commit would silently arm production. The committed artifact must stay safe.

**Rejected: reading the ambient environment at build time** (e.g. `os.getenv("ALLOW_WEB_RESEARCH")` inside `_flag_const`). It makes the committed JSON depend on whoever last ran the builder, destroying the deterministic-rebuild invariant this repo has enforced all session and inviting an enabled workflow into git by accident.

**Leading candidate: a deploy-time overlay.** A pure function over a workflow dict — the same shape as `bind_credentials()` in `scripts/deploy_n8n_workflows.py` — applied in flight before the POST, behind an explicit operator flag. Properties that make it attractive:
- Committed JSON stays permanently safe and deterministic.
- Enablement is visible in the command that performs it, and leaves no repo artifact.
- Offline-testable as a pure transformation, with the existing `bind_credentials` precedent for how such a function is written and tested here.
- Must **fail closed**: if it does not find exactly the constants it expects to rewrite, it errors rather than deploying a silently-disabled workflow while reporting success. A no-op that looks like a success is the specific failure mode to design against.

The planner should confirm or refute this against the code, and state the tradeoff. Whatever mechanism is chosen, criteria 1–3 in ROADMAP are the contract.
