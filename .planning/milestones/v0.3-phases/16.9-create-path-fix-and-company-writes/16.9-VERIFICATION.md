## Detailed Findings — Checkable-in-the-Repo Items

### 1. `_hs_http_create_node()` exists and both create nodes are correctly-shaped `httpRequest` POSTs — VERIFIED

`scripts/build_cloud_workflows.py:4331-4363` defines `_hs_http_create_node(name, resource, x, y)`: builds `url = "https://api.hubapi.com/crm/v3/objects/" + resource` (collection endpoint, no id), `body = "={{ JSON.stringify({ properties: $json.properties }) }}"`, calls `_http_node(..., auth="hubspot", json_body=body, method="POST", on_error=None)`. `_http_node`'s `auth="hubspot"` branch (`scripts/build_cloud_workflows.py:2776-2777`) sets `authentication: "predefinedCredentialType", nodeCredentialType: "hubspotAppToken"` — the same provisioned credential the native nodes used. `on_error=None` causes the `onError` key to be omitted entirely (`scripts/build_cloud_workflows.py:2785-2786`).

Read `n8n/wf_enrichment_cloud.json` directly (not grepped) for both nodes:

```json
"HubSpot Create":         { "method": "POST", "url": "https://api.hubapi.com/crm/v3/objects/contacts",
                             "jsonBody": "={{ JSON.stringify({ properties: $json.properties }) }}",
                             "authentication": "predefinedCredentialType", "nodeCredentialType": "hubspotAppToken" }
"HubSpot Company Create":  { "method": "POST", "url": "https://api.hubapi.com/crm/v3/objects/companies",
                             "jsonBody": "={{ JSON.stringify({ properties: $json.properties }) }}",
                             "authentication": "predefinedCredentialType", "nodeCredentialType": "hubspotAppToken" }
```

Neither node has an `onError` key (confirmed by reading the full node dict — the key is absent, not merely falsy). Both are `"type": "n8n-nodes-base.httpRequest"`, `typeVersion: 4.2`.
