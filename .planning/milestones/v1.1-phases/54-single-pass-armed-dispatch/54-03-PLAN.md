<objective>
Make approving a flagged contact land in HubSpot, the way approving a flagged company does
(OP-54-03, OP-54-04). Today every contacts approve resolves to a refusal and writes nothing, so
`approve` means two different things depending on the record type — which is exactly what OP-54-03
forbids.

Purpose: the review lane's contacts write path is the phase's operator-added scope. This plan is
the code; 54-04 deploys it; 54-05 proves it live.

Output: a policy-injectable apply engine, a contacts approve branch, and re-pointed pins.

**A finding the executor must carry into the checkpoint, not discover after writing code:** every
contact that can be in the review queue today was flagged by the permissive contact enrichment lane
(`scripts/build_cloud_workflows.py:1569-1593`), which writes the enriched value and the review flag
in the SAME PATCH body and deliberately does not stage a candidate. So those records' enriched
values are already live in HubSpot — the promote branch has no producer feeding it, and the live
proof in 54-05 can only exercise the clear branch. Say that in the SUMMARY. Do not let the phase
claim a live-proven promotion it cannot show (OP-54-05's rule applies to capability claims, not
only to dollars).

**Execution budget: 0 n8n executions** (this plan is offline code plus one read-only HubSpot
properties list). Provider credits: 0. Anthropic calls: 0.
