Create `scripts/zoominfo_company_client.py`, a read-only ZoomInfo GTM company client. Module
docstring states it is read-only, that it must be run from the repo root, and gives the
`load_dotenv()` + `runpy.run_path` operator invocation used by every precedent script. Import
`_mint_zoominfo_token` and `_check_zoominfo` from `scripts.check_provider_credits` rather than

Define `GTM_ENRICH_URL = "https://api.zoominfo.com/gtm/data/v1/companies/enrich"` and
`ZOOM_CO_OUTPUT_FIELDS = ["id", "name", "website", "revenue", "revenueRange", "employeeCount",
"employeeRange", "country", "primaryIndustry", "naicsCodes", "descriptionList", "foundedYear"]`.
Do not add `companyType` — it is not entitled and returns 400 PFAPI0009.

`zoominfo_credentials_present() -> bool` returns True only when both ZoomInfo env vars are
non-empty. `zoominfo_credit_balance() -> int | None` delegates to `_check_zoominfo()` and returns
its `credits` value, or None on any failure — never raises.

`enrich_company(domain: str, token: str) -> dict` POSTs the JSON:API envelope
`{"data": {"type": "CompanyEnrich", "attributes": {"matchCompanyInput": [{"companyWebsite":
domain}], "outputFields": ZOOM_CO_OUTPUT_FIELDS}}}` with `Authorization: Bearer <token>`,
`Content-Type: application/vnd.api+json`, `Accept: application/vnd.api+json`, timeout 30. It
returns `{"matched": bool, "attributes": dict, "reason": str | None}`. Every extraction is
defensively `isinstance`-checked (per ASVS V5 and the `_extract_zoominfo` precedent): a response
whose `data` is not a non-empty list, whose first entry is not a dict, whose `type` is `NoMatch`,
or whose `attributes` is not a dict, returns `matched=False` with a stated reason — never an
exception. Any HTTP or JSON exception is caught and degraded to `matched=False` with the exception
type name as the reason. Never place the token or either credential into any returned dict.

`zoominfo_revenue_to_dollars(raw)` multiplies a numeric GTM `revenue` (which is in THOUSANDS) by
1000 and returns the dollar figure, returning None for a non-numeric input and for any result at
or below zero — mirroring the zero-is-no-data rule in the JS reference, which the existing Python
`normalize_revenue_band` does NOT have (it would band zero as the lowest band, silently scoring a
missing figure as a disqualifying one).

`zoominfo_revenue_range_to_dollars(text)` ports the JS `_revenueToDollars` regex: take the first
magnitude in the string, apply the k/m/b suffix multiplier, and return the LOWER bound in absolute
dollars. The range string is already in dollars — the thousands multiplier must not be applied to
it.

`zoominfo_revenue_band(attributes) -> str | None` implements the precedence the JS reference
already fixed: prefer a non-empty `revenueRange` string via `zoominfo_revenue_range_to_dollars`,
otherwise fall back to `zoominfo_revenue_to_dollars(attributes.get("revenue"))`; if the resulting
dollar figure is None, return None, otherwise delegate to
`src.normalizer.normalize_revenue_band(dollars)` — never re-list the band cut points here.

`zoominfo_country_region(value) -> str | None` mirrors the JS `normalizeCountryRegion` contract:
a falsy or whitespace-only value returns None, `australia`/`au`/`aus` return `"AU"`, `new
zealand`/`nz` return `"NZ"`, and every other real value returns `"Other"`. Do NOT reuse
`src/normalizer.py::normalize_country_region` — its blank-input return value is a truthy string
that `compute_icp_score` reads as a positive non-ANZ determination and fires the hard veto on.

`derive_credit_cap(balance_credits: int, credits_per_match_hundredths: int) -> int` returns
`(balance_credits * 100) // credits_per_match_hundredths` — integer arithmetic only, matching
`estimate_rescore_cost`'s no-float precision rule. Per-match cost is carried in hundredths of a
credit precisely so no float division can round a cap upward past what the balance supports.
`CREDITS_PER_MATCH_HUNDREDTHS_FALLBACK = 108` is the documented pre-v3 1.08 credits/match figure;
callers may supply a larger measured value. Guard a zero or negative balance to a cap of 0.

`count_never_scored_companies() -> int` issues the D-01 population filter
`[{"propertyName": "lv_icp_fit_score", "operator": "NOT_HAS_PROPERTY"}]` with `limit=1` and returns
`result["total"]` — the count needs no pagination.

`select_never_scored_sample(size: int) -> list[dict]` issues the same filter requesting
`["name", "domain"]` with `SAMPLE_SEARCH_LIMIT = 100` and returns the first `size` entries by
ascending id as `{"id":..., "name":..., "domain":...}` dicts. This is a deliberately BOUNDED sample,
not the population — do not copy `select_scored_population`'s total-versus-returned refusal
verbatim, because the never-scored population is far larger than one page and that guard would
raise on every run. Instead: raise a `RuntimeError` naming the page limit when the search returns

pagination is a Phase 52 prerequisite and deliberately out of scope here.

`build_candidate_patch(zi_attributes: dict) -> dict` builds the scoring inputs from the ZoomInfo
attributes: `lv_revenue_band` from `zoominfo_revenue_band`, `lv_country_region_normalized` from
`zoominfo_country_region(attributes.get("country"))`. `lv_org_type`, `lv_produces_content`,
`lv_is_hardware_vendor` and `lv_is_gambling_operator` are left absent by this task — ZoomInfo does
not answer them and plan 02 adds the D-02 gap-fill research lane. Any key whose value is None is
OMITTED from the returned dict entirely: HubSpot must not receive nulls, and an absent
`lv_country_region_normalized` is exactly the input `compute_icp_score`'s blank-region guard reads
as "not yet enriched" rather than as a non-ANZ determination.

`predict_tier(score: int, anti_icp_flag: bool) -> str` replicates the LIVE four-branch
`lv_icp_tier_derived` formula directly from those two values: veto wins and yields `"D"`, else
score at or above 70 yields `"A"`, at or above 40 yields `"B"`, at or above 15 yields `"C"`, else
`"Unscored"`. It must not read the oracle result's tier attribute — that attribute carries a
fifth, Python-only low-confidence label the live calculation has no branch for, which would make
every low-confidence record read as a false mismatch in Phase 52's comparison.

`build_dry_run_row(company_id, candidate_patch) -> dict` makes ONE oracle call —
`compute_icp_score(HubSpotRecord(object_type="companies", id=company_id, properties={}),
candidate_patch)` — then composes the payload as the candidate patch's present keys, plus
`compute_components(candidate_patch)`, plus ONLY the `lv_anti_icp_flag_num` entry from
`anti_icp_flag_properties(result.anti_icp_flag)`. `PERMITTED_PAYLOAD_KEYS` is the frozen set of
those twelve names (`PAYLOAD_INPUT_PROPS` = the six lv_* inputs, plus `COMPONENT_PROPS`, plus
`lv_anti_icp_flag_num`); the function asserts the built payload's keys are a subset of it. The
row also carries `predicted_tier`, `score`, `anti_icp_flag` and `anti_icp_reason` for the artifact.
The remaining key that `anti_icp_flag_properties` returns, and the two calculated properties, are
owned by other producers and must not appear in a payload this script builds.

`run_dry_run(sample_size, ...)` orchestrates the single path: portal guard → balance read → cap →

"skipped": [...], "population_total":..., "credit_cap":..., ...}`. It refuses with a stated message
when `sample_size` exceeds the derived cap, before issuing any enrich request.
