`research_gap_fields(company, zi_attributes, candidate_patch) -> ProviderResult | None` returns
None — issuing no call at all — when every name in `GAP_FILL_FIELDS` is already present in the
candidate patch. Otherwise it builds a `HubSpotRecord` carrying the record's `name`, `domain`,
`website`, `country` and `industry` and calls `src.web_research.claude_web_research(record)`. Note

a false value, so the live invocation in task 3 must set it — a run that forgets produces fixture

recorded on the row, never raised.

`apply_research_to_patch(candidate_patch, research_result) -> dict` merges ONLY the names in
`GAP_FILL_FIELDS` that are still absent from the patch, and only when the research result's value
is not None. It never overwrites a value ZoomInfo already supplied. `lv_org_type` passes through
`src.taxonomy.normalize_org_type` so only live enum values reach the oracle. Boolean fields accept
only real booleans; a null answer leaves the key absent — an absent input is "not yet enriched"
and is exactly what the oracle's blank-input guards are written for, whereas a defaulted false on
`lv_produces_content` would fire the no-content hard veto on a record nobody researched. Record
which fields research actually filled on the row as `research_filled`, and the evidence urls the
result carried, so the artifact shows why each value is there.

`build_skip_entry(company, reason) -> dict` returns `{"id":..., "name":..., "domain":...,
"reason": <non-empty string>}` and nothing else — no payload key, no partial patch, no predicted
tier. The reasons this phase can emit are: no domain on the HubSpot record (skipped before any
provider request, costing zero credits), ZoomInfo reported no match, and the ZoomInfo response was
malformed. D-04 is explicit that a record ZoomInfo cannot match is written with nothing and logged
unenriched — `research_gap_fields` must therefore never be reached on the unmatched branch. Place
the skip-and-continue before the research call site, not after it, so this is a structural
property of the control flow rather than a conditional a later edit can invert.
