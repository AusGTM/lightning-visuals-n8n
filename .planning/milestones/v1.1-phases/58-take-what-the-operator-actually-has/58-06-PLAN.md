## The incident, and the root cause traced to source before planning

**Gap (live, 2026-08-26, execution 11983).** An armed company enrich of Series Futsal Victoria
`283816805830` saw four sources answer the same question differently: ZoomInfo said "United
States" (a wrong-branch match — a known ZoomInfo failure mode, project memory
`zoominfo-gtm-companies-contract.md`), Apollo said "Australia", Lusha said "Australia"/AU, and a
prior claude_web pass had said AU. ZoomInfo won on trust rank (`DEFAULT_TRUST.zoominfo = 0.85`,
`n8n/code/scoreEnrichment.js:21`). `lv_country_region_normalized` was written `"Other"`,
`_regionKey("Other")` returned `"non_anz"`, and the Non-ANZ hard veto fired —
`lv_anti_icp_flag` false→true — with no judge call and no review flag.

CLAUDE.md §21.2 requires Sonnet validation or human review before exactly that transition. The
`Judge Gate` node RAN on this row and correctly decided no judge was needed, because nothing it
looks at had changed. Tracked debt id 19 (country-conflict blind spot) bit live.

**Root cause — one line, verified from source, do not re-derive it but do pin it:**

```
scripts/build_cloud_workflows.py:2825
const CONFLICT_WATCH = ["lv_revenue_band", "lv_employee_band"];
```

`Merge Company` already detects cross-source disagreement and already refuses to promote a
conflicted field (`scripts/build_cloud_workflows.py:2879-2899`): it reads
`scored.sourcesByField[f]` and `scored.best[f].agreedBy`, and the enum candidate loop skips any
field in the `conflicted` set. `lv_country_region_normalized` IS in that candidate loop
(`:2894-2895`) and is NOT in `CONFLICT_WATCH`. The machinery was built, correct, and pointed at
two fields that cannot fire a veto, while the field that can was left outside it.

`CONFLICT_WATCH`'s own header comment (`:2824`) cites CLAUDE.md §17.2 — "NEEDS_REVIEW if providers
materially conflict" — as its authority. It is scoped narrower than the rule it cites.

**Three further findings from the same trace, each of which changes what this plan must do:**

1. **A conflicted field today is silent.** The `continue` at `:2894` drops the candidate before
   `mergeCompanies()` ever sees it, so no `decisions` entry is produced. `ENRICH_DECIDE_CO_CLOUD`
   sets its review properties from `merge.decisions` filtered to `needs_review`
   (`scripts/build_cloud_workflows.py:3141-3147`) and **never reads `row.conflicts` at all** —
   only the LOCAL dry-run echo does (`:3100-3101`). So even the two size conflicts already
   detected have never set `lv_enrichment_needs_review` on the cloud lane. Withholding a value
   without flagging it is a silent absence, which is its own defect; the operator's ruling
   requires the flag.

2. **The suppression template already exists in this same node.** The `juneDisagreements` block
   (`scripts/build_cloud_workflows.py:3039-3062`) does exactly the right thing for a different
   conflict axis: delete the field from `canonicalPatch`, delete its cache key, push a synthetic
   `needs_review` decision naming both values — and it runs AFTER every spread so ordering cannot
   resurrect a suppressed field. Copy that discipline; do not invent a second shape.

3. **58-05 opened a parallel hole yesterday.** Its native-field loop
   (`scripts/build_cloud_workflows.py:2909-2914`) reads `winners[f]` for
   `country`/`city`/`numberofemployees` with **no `conflicted.has(f)` check**, because when it
   was written no material field was watched. Native `country` and `lv_country_region_normalized`
   are two serializations of one disputed fact; leaving the native loop unchecked would write
   "United States" into `country` while the region sits in review.

## Why withholding is sufficient to stop the flip

`ENRICH_DECIDE_CO_CLOUD` derives the veto from `properties.lv_country_region_normalized ??
existing.lv_country_region_normalized` (`scripts/build_cloud_workflows.py:3186`). A suppressed
field is absent from `properties`, so the existing record value governs — and `_regionKey`
(`:3175-3179`) maps a never-enriched blank to `"unknown"`, a third state distinct from
`"non_anz"` (the 2026-08-10 blank-region fix, whose comment cites 17 real companies wrongly
vetoed by exactly this node). Absence therefore produces no veto rather than a wrong veto.

**This is why the veto predicate itself must not be touched.** This plan changes the predicate's
INPUT, never its text. `tests/test_scoring_parity.py` asserts live state against
`src/icp_scoring.py` and must stay green unmodified — that is the check that the predicate did
not drift.

## The RO-2 collision, stated rather than resolved silently

The middle tier, applied to `lv_revenue_band`/`lv_employee_band`, would mean a size disagreement
triggers a model call. **RO-2 forbids exactly that**, deliberately and structurally: the judge
gate is placed physically upstream of the node that computes size disagreement, and
`tests/test_judge_spec.py::test_ro2_judge_gate_cannot_see_size_conflicts` asserts both the jsCode
absence and the graph ancestry.

This plan keeps RO-2. Size conflicts gain the review flag they should always have had (which is
what §17.2 asked for in the first place) and gain no judge call. That is a real behaviour change
— today's silently-absent becomes absent-and-flagged — and it is put to the operator at Task 4
together with the RO-2 question, rather than being decided here.

## Python↔JS parity: what mirrors, and what explicitly does not

The Phase 46 parity rule binds a predicate held in two engines. State which of the three things
this plan touches is which, so a later reader does not look for a missing mirror:

1. **The material-field list MIRRORS, structurally.** It lives once in `config/escalation_policy.yaml`,
   is read by `src/judge.py`, and is emitted into `n8n/code/escalation.generated.js` by
   `scripts/gen_escalation_js.py` — which imports the Python constants rather than re-deriving
   them. There is no second hand-typed copy to drift, and
   `tests/test_judge_spec.py::test_escalation_generated_js_is_current` fails if the generated file
   goes stale. This is the parity surface.
2. **The conflict predicate does NOT mirror, and needs no counterpart.** `n8n/code/providerConflict.js`
   and the suppression block in `ENRICH_MERGE_CO` are n8n-lane-only. They operate on
   `scored.sourcesByField`/`agreedBy`, a structure produced by `scoreCandidates` on the cloud lane
   and nowhere else. The Python oracle's analogous mechanism is a DIFFERENT mechanism on a
   DIFFERENT path — `src/merge_policy.py`'s `has_conflict` (`:107`) feeding
   `deterministic_gate`'s `allow_sonnet_escalation` branch (`:133`) and `build_merge_result`'s
   `needs_sonnet` (`:266`) — which serves the local-MVP multi-candidate path, not this lane. No
   mirror is forced, and none is written.
3. **The hard-veto predicate mirrors already and is NOT touched.** `src/icp_scoring.py` and the
   `Decide Company Action` veto block stay as Phase 40/47.5 left them. This plan changes the
   predicate's input, never its text; `tests/test_scoring_parity.py` staying green and unmodified
   is the check that it did not drift.
