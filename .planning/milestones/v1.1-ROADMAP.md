## Decisions taken before planning (operator, 2026-08-25)

- **D-1.1-01 — the grant is operator-openable in Claude.** The `ALLOW_N8N_ARM` environment
  variable is replaced as the authority for interactive runs: an admin enables the capability
  once, in the settings file, and the operator opens a session grant in conversation. This is
  what removes the terminal dependency that made G-2 a blocker. The env gate is not deleted
  blindly — it stays the authority for headless/cron paths (`scheduled_arm.py`), which have no
  operator to confirm anything.
- **D-1.1-02 — grant first, then a single async pass.** The grant is opened *before* the run,
  so a record is enriched once and written in the same pass (killing G-3's double spend), and
  the run submits and polls rather than blocking on n8n Cloud's ~100 s response window.
- **D-1.1-03 — the first slice is the full pair pipeline.** Ingest → enrich → create →
  associate, unattended, **creates included**. This is the largest blast radius available, so
  the safety phases are not optional tail-end work: Phase 57's ceilings and post-run proof
  ship inside the milestone, not after it.

terminal, and the authorization is bounded, expiring, and revocable.

> **"Expiring" here means event-triggered, not time-triggered.** A grant is scoped to a named
> batch, not to a duration (GRANT-03), and it terminates on one of GRANT-04's five named close
> events (`batch_complete`, `ceiling_breach`, `operator_revocation`, `session_end`,
> `unhandled_error`) — recorded in the grant's `closed_reason` field. A wall-clock `expires_at`
> timestamp was proposed and **declined by the operator on 2026-08-25** (D-53-03,
> `operator-claude-plugin/scripts/write_grant.py:682-688`). Read "expiring" against that
> definition; there is deliberately no expiry timestamp to find.

  the settings file plus an operator-opened session grant. Headless paths keep the env gate.
- The grant object: object types, record set, creates yes/no, ceilings, expiry. Never

### Phase 54 — Single-pass armed dispatch

**Goal:** a record is enriched once. No derive-then-rearm-then-derive-again.

- When a grant is open, the dispatch runs inside the armed window from the start; there is no
  unarmed first pass to throw away.
- **Amendment, 2026-08-27 (54-02):** the `write_blocked`-then-manually-rearm ceremony no

**Goal:** a batch is no longer bounded by the synchronous response window.

- Submit returns a run id immediately; the client polls run state rather than holding a request
  open. Decide and record where run state lives (n8n static data, a HubSpot object, or an
  external store) — each has a different failure mode when n8n restarts mid-run.
- Progress readable while running: records done, held, failed, spend so far against ceiling.
- A run interrupted by a restart resumes or fails loudly; it never silently half-completes.

**Closes:** RUN-01, RUN-03, RUN-04.

### Phase 57 — Ceilings, refusal-before-start, and post-run proof  **[NEXT PHASE]**

> **Not absorbed, and still gating** (D-61-08, 2026-08-30). Phase 56's gate survived the fold into
> Phase 61: **the first live unattended, credit-spending batch cannot run until this phase lands.**
> It is also the missing producer for GRANT-04's `ceiling_breach` close reason and for GRANT-02's
> remaining-allowance half.

**Goal:** an unattended run cannot spend what it does not have, and can prove afterwards that
it wrote only what it was granted.

- Per-run ceilings on provider credits, Anthropic dollars and n8n executions, enforced before
  the first record, with the arithmetic shown at proposal time.
- A run that would exhaust the monthly execution allowance refuses before starting and offers a
  smaller batch. The allowance is sampled, not read — n8n exposes no usage endpoint.
- Post-run proof: an independent re-read showing that every record written was in the grant's
  allowlist and nothing outside it changed. G-4's unreadable balances are resolved or the run
  refuses to treat "unknown" as headroom.
- End-of-run report: per-record outcome, association outcome, held rows named individually,
  spend actuals vs ceiling, disarm verdict, and a clear line between "written" and "would have
  been written".

**Closes:** RUN-05, AFTER-01, AFTER-03, G-4.

### Phase 58 — Take what the operator actually has

**Goal:** every input an operator holds resolves to something the backend can act on, and a
refusal is the last resort rather than the first answer.

- Extend the contact lane's extraction adapters (pasted text, foreign JSON, public URL,
  screenshots — Phase 35) to **companies**, which have never had them.
- When no usable domain is present, research one from the name or the profile page using the
  companies branch's existing `Claude Web Research` node, and **confirm it before writing** —
  a wrong domain poisons the dedupe anchor for everything after it.
- Keep the guard that survives: never silently invent a domain. A profile URL is dropped, not
  passed through. Partially shipped in 0.16.0 (accept-by-name).

**Closes:** INPUT-01..04.
**Risk:** research costs money per company, so it must be priced in the envelope and be
declinable, or a bulk list quietly becomes a research bill.

**Goal (tracer):** an input carrying a strong identity key resolves through match-then-enrich
without the operator being asked for fields the backend does not need.

- A **contact** given only a LinkedIn URL (or only an email) proceeds: match HubSpot on that key,
  and where unmatched, enrich through the licensed waterfall on that same key.
- Propose the result with its provenance for confirmation. **No-invention is untouched** — the
  operator supplies the key, a licensed provider returns sourced fields, the operator confirms.
  A searched-and-sourced value is not an invented one.
- A refusal for missing identity is only correct when **no** strong key is present. Asking the
  operator for a field the backend does not need is the defect.
