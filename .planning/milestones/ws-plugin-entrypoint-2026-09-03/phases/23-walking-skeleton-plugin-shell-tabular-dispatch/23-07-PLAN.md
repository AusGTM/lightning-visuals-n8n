<objective>
`scripts/verify_live_write_safety.py` is the arm/disarm read-back that BOTH remaining armed operator
windows depend on — 23-06 Section B and 30-07. Three defects were found in it on 2026-07-31 by three
independent routes, and two of them make it unfit for either window. This plan fixes it and brings
its two callers back into agreement with it.

Purpose: an armed window in this repo is closed by a read-back, never by a deploy's exit code
(Phase 19's BUG 26). A read-back that inspects two nodes in one workflow, and that reports a failure
for a correctly armed backend, is worse than none — it produces a confident disarmed pass for a lane
it never looked at, and it trains an operator to fire through a failure. Per D-19 this is one
coherent fix: discovery instead of hardcoded scope, and an explicit expected-armed set instead of one
phase's baked-in canary scope.

Output: a read-back whose coverage follows the deployed artifacts, an armed expectation both windows
can express, and two runbooks whose command lines the script accepts.

Ordering: this plan depends on no other plan in the phase (the script predates it; 30-01 last amended
it), so it is wave 1 — but it must LAND BEFORE 23-06's wave-4 operator window resumes Section B.
That is the whole reason it exists.

This plan writes no live state. The script is read-only today and stays read-only. Nothing here arms
a flag, deploys a workflow, activates anything, or touches HubSpot.
</objective>
