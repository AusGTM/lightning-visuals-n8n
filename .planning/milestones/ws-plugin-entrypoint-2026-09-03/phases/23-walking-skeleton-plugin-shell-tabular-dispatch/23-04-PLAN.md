and the arming gate to the exact HTTP request the deployed `hubspot/contact-upload` webhook accepts
— wired end to end, with the disarmed refusal as the behaviour that is actually proven.

plan and every Phase 24 adapter feeds this same choke point, so an architectural mistake here is
cheapest to find now.

stub transport from 23-03 — no live POST anywhere in automated verification.

  <action>
    Write three thin modules under `operator-claude-plugin/scripts/`, each usable as a library by
    the tests and as a CLI by the skill (a `__main__` block printing JSON to stdout — the skill
    parses that, so no module prints prose).

    `config_gate.py`: resolve the config path relative to the plugin root (`parents[1]/config/
    operator.local.json` — a non-dotfile name per D-04, because dotfiles are permission-blocked to
    tooling in this environment). Validate that `n8n_url` and `webhook_secret` are present and
    non-empty and that `n8n_url` is an https URL. Raise a `ConfigError` carrying an
    operator-readable sentence: what is not configured, that the fix is copying
    `config/operator.local.example.json` and filling it in once, and that the values come from the
    n8n admin. Never interpolate a secret value into any message or repr, and catch the JSON decode
    error rather than letting a parser traceback surface (D-06, PLUGIN-03). Expose
    `describe_target(cfg)` returning the endpoint the plugin will POST to, for the skill's
    state-it-up-front line (D-12).

    `tabular.py`: `read_table(path)` returning the header list and row lists for `.csv` and `.xlsx`,
    headers verbatim — no cleaning, no normalization, no mapping (STRUCT-01 is satisfied by leaving
    the file alone and letting the backend's `Map Columns` node map it, per D-07). Use stdlib `csv`
    with `utf-8-sig` for CSV and `openpyxl` with `read_only=True` for XLSX. `to_csv_bytes(path)`
    returns the original bytes for a CSV and a re-serialized CSV for an XLSX — re-serializing
    FORMAT, never remapping columns; `Extract From File` runs `operation: "csv"` and cannot parse an
    XLSX binary (Pitfall 2). Raise a named error for any other extension.

    `dispatch.py`: `dispatch(file_path, armed, config, transport=requests.post)`. `armed` is
    positional-or-keyword with NO default — a caller that forgets it must fail loudly rather than
    default to anything. When `armed` is false, raise `NotArmedError` carrying the plain-language
    sentence the operator sees, before constructing the request or touching the transport (D-13).
    When true, build the multipart POST exactly as the contract requires: url from the config,
    header `X-Enrichment-Secret` (that literal name — the deployed contact-upload webhook shares the
    `LV Enrichment Webhook` credential; Pitfall 1), one file field named `data` carrying the CSV
    bytes with a `text/csv` content type, and an explicit timeout. Return the parsed JSON response
    if the body is JSON, otherwise the status and raw text — do not claim per-record outcomes; the
    response shape question is Phase 26's, and this phase reports only that the POST was accepted.
    Translate a transport exception into a plain-language failure that does not echo request headers
    (a `requests` exception's text can carry them).

    Do not persist the armed flag anywhere: no file, no env read, no cached state. It arrives as an
    argument for exactly one call and dies with the process (D-11).

    Write the two test files against the 23-03 fixtures, covering every behaviour listed above. The
    dispatch tests use `stub_transport`; the autouse network guard is what makes an accidental real
    POST impossible, and one test should assert the unarmed path leaves the stub's call log empty
    rather than merely asserting the raise.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator-supplied file → plugin scripts | Untrusted content (arbitrary headers, arbitrary cell values) crosses here |
| plugin → n8n Cloud webhook | The only network egress in this phase |
| config file → conversation | The secret must never cross this boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-01 | Elevation of Privilege | `dispatch.dispatch()` | critical | mitigate | `armed` has no default; the unarmed path raises before the transport is constructed; nothing about the grant is persisted (D-11); a unit test asserts the stub recorded zero calls |
| T-23-02 | Information Disclosure | `config_gate` error messages | high | mitigate | Refusal messages name keys and files, never values; the JSON decode error is caught rather than surfaced; `describe_target` returns a URL only |
| T-23-03 | Denial of Service / Information Disclosure | unconfigured run | high | mitigate | Config validation runs before the transport exists, so an unconfigured run cannot produce a socket error for the operator to read |
| T-23-09 | Information Disclosure | transport exception text | medium | mitigate | `requests` exception text can echo request headers; dispatch translates transport failures into a plain-language message rather than relaying the exception |
| T-23-10 | Tampering | XLSX→CSV re-serialization | medium | mitigate | Conversion changes format only; a unit test asserts header line and cell values are unchanged, so no client-side remapping can hide in the conversion |
| T-23-SC | Tampering | package installs | low | accept | Dependencies were declared and audited in 23-03; this plan installs nothing new |
</threat_model>
