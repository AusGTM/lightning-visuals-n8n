<objective>
Wave 0 for this phase: the test package, its fixtures, the network stub, the plugin's own dependency
declaration, and the config-file boundary — everything the later plans' `<automated>` verification
commands need to exist before they can be run.

Purpose: 23-VALIDATION.md's critical Wave 0 constraint is that dispatch tests must never perform a
real POST — the arming guard is the thing under test, and a test that accidentally arms and sends is
worse than no test. That guard belongs in shared fixtures, written once, before any dispatch code
exists to tempt it.

Output: `.venv/bin/python -m pytest operator-claude-plugin/tests -q` runs and passes against an
otherwise empty plugin.
</objective>

  <behavior>
    - `sample_csv` fixture: a tmp_path CSV with messy headers, at least one header the alias table
      does not know, and enough rows that the >20-row preview branch can be exercised by a sibling
      fixture.
    - `sample_xlsx` fixture: the same content written with openpyxl into tmp_path.
    - `fake_config` fixture: a dict with a syntactically valid `n8n_url` and a placeholder secret,
      never read from the operator's real config file.
    - `stub_transport` fixture: a callable recording the url, headers, files and timeout it was
      handed, returning a canned JSON-shaped response object — the seam every dispatch test uses in
      place of a real POST.
    - Autouse `no_network` fixture: any attempt to reach `requests.post`, `requests.request` or
      `requests.Session.request` inside a test raises immediately with a message naming the test.
    - `test_transport_guard.py`: calling `requests.post` inside a test raises, and `stub_transport`
      records a call without raising — the guard bites, and the seam still works.
  </behavior>
  <action>
    Write `operator-claude-plugin/tests/conftest.py` providing the six fixtures above. Do not add an
    `__init__.py` to the plugin tests directory; keep the test module basenames distinct from the
    repo's `tests/` package so a full-suite run collecting both directories cannot collide.

    Put `operator-claude-plugin/scripts` on `sys.path` from conftest so plugin tests import flat
    module names (`import config_gate`). Importing them as a package named `scripts` would resolve
    to this repository's own `scripts/` package when pytest runs from the repo root — a collision
    that would silently import backend code into a test suite whose entire point is that the plugin
    does not touch backend code.

    Implement the network guard by monkeypatching at the `requests` module level with autouse scope,
    so a later plan cannot opt out by forgetting to request a fixture. The raised error must say
    which test tried to reach the network, so a failure reads as an accusation rather than a puzzle.

    Generate the XLSX fixture at fixture time with openpyxl rather than committing a binary — the
    file's content is then visible in the test source, which is what a reviewer needs to trust the
    XLSX-to-CSV conversion test written in 23-04.
  </action>
