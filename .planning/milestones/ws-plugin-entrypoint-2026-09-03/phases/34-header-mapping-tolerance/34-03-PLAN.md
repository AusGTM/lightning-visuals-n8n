an operator who has not seen what is in it is being asked to rubber-stamp. Say explicitly that a
single batched yes covering several headers is not a confirmation and must not be accepted as
one, and that declining costs nothing — the header simply stays as it is and the backend drops
it, which is the honest outcome.

`unresolved` — say the backend will drop that column, and that this is a reported outcome rather
than a failure. Do not offer a guess.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| skill instructions → CLI invocation | A hand-written SKILL.md step and a hand-written CLI argument parser are two sides of one contract with no compiler between them |
| corrected file → wire bytes | `to_csv_bytes` re-reads whatever path it is handed; the path and the approved content can silently disagree |
| operator confirmation turn → header rewrite | A batched or implied yes would rewrite headers the operator never individually evaluated |
