<objective>
Stop silence meaning two opposite things. Per CONTEXT § "BUG 30": the review write gate answers
NO body on an allowlist drop, and the client reports the same `unparseable_response` for that and
for a genuine workflow error. In the live RB-9 run the allowlist was correct and the endpoint was
broken, and the runbook's advice pointed the operator away from the real cause.

Make the endpoint answer an explicit refusal on an allowlist drop, teach the client the new word,
and correct the runbook. The write gate itself is NOT touched — it stays the fail-closed authority
and this adds an earlier, louder answer in front of it.

Purpose: an operator meeting this alone can tell "not allowlisted" from "the workflow errored".
Output: one new outcome word, one wrapper pre-check, two new test files, one runbook correction.
</objective>

## Trust Boundaries

| operator conversation -> review decision endpoint | an untrusted record id crosses into a write path |
| pre-check verdict -> write gate | a permissive answer computed early must not become authority for the actual write |
| endpoint response -> operator's understanding | a wrong diagnosis sends the operator to the wrong fix |
