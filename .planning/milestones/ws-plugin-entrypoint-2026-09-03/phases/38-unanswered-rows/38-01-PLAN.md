<objective>
Make the client tell the truth about a row the backend never answered for.

Purpose: in the live nine-directors walk, a two-row enrichment chunk came back carrying only
row 5's item. `merge_enriched` correctly noticed row 6 had no response — but the enriched
preview then ran the email gate over it anyway and reported it HELD, "no usable email". That
reason is fabricated. The row's email may have been sitting in the response that never arrived.
The truth is "no verdict received", and the operator armed the upload having read a claim about
the row's data that was actually a claim about the response.

This is the same honesty rule as `unchecked` vs `unmatched`, one layer down.

Output: an `unanswered` group through merge, preview and manifest, plus one automatic
re-request pass that reuses the existing dispatch path.
</objective>

| client -> operator display | The enriched preview is the evidence on which the irreversible HubSpot write is granted. |
