<objective>
Resolution step 5: the one-time sibling scan. When nothing resolves from the env var, the
durable home, or the current install's own `config/`, look across sibling install directories
under this plugin's cache root, newest version first, and migrate the newest config found up
into the durable home — 0600, atomically, verified, and then remove the dead install's copy.

This is the task that makes the update INTRODUCING durability free. Without it, 0.7.0's install
directory is empty, the durable home is empty because 0.6.2's code never wrote it, and the
operator hand-copies a config for the fourth time.

Purpose: PLUGIN-02 (setup stays one-time across the version boundary that would otherwise
break it) and PLUGIN-03 (a failed migration degrades to the path it read from; it never
refuses).
Output: `_atomic_write_0600`, `_version_key`, `_newest_sibling_holding`, `_migrate_once` in
`durable_paths.py`, wired into both resolvers' step 5.
</objective>

Add to `durable_paths.py`, using only `os`, `re`, `tempfile`, `contextlib` and `pathlib` — no

`_atomic_write_0600(path, content)` follows research pattern B. It calls
`path.parent.mkdir(parents=True, exist_ok=True)` first — the harness creates the durable
directory lazily only when IT resolves the placeholder, which it has never done for this plugin,
so the plugin must create it (this is the same one-line pattern `artifact_store.save()` already
uses). Then `tempfile.mkstemp(dir=str(path.parent), prefix="." + path.name + ".")`, an explicit
`os.chmod(tmp, 0o600)` even though mkstemp already guarantees that on POSIX, write through
`os.fdopen`, `flush()`, `os.fsync(fileno())`, and `os.replace(tmp, path)`. Wrap the body in
`try` / `except BaseException` that unlinks the temp file under `contextlib.suppress(OSError)`
and re-raises. Put a comment on the `dir=` argument stating that it must stay the target's own
parent directory: `os.replace` is atomic only within one filesystem, and moving the temp file to
a system temp directory in a later refactor would silently reintroduce the partial-write window
this whole pattern exists to close.

`_VERSION_DIR_RE = re.compile(r"^\d+(\.\d+)*$")` and `_version_key(name)` returning
`tuple(int(p) for p in name.split("."))`. The key function's docstring records that it is only
ever called on names the regex already accepted, so it cannot raise, and that the filtering must
stay BEFORE the sort — a mixed `int`/`str` tuple comparison raises `TypeError` in Python 3,
which `config_gate`'s ConfigError wrapping does not catch, so one stray directory name in the
cache root would put a raw traceback in front of the operator.

`_newest_sibling_holding(relative)` takes a path relative to an install root — for the config
that is `Path("config") / CONFIG_FILENAME`. It computes `cache_root = PLUGIN_ROOT.parent` and
`here = PLUGIN_ROOT.resolve()`. It iterates `cache_root.iterdir()` inside a
`contextlib.suppress(OSError)`-guarded block (a cache root that does not exist or is unreadable
is a normal "nothing to migrate" outcome, not an error), keeping directories whose name matches
`_VERSION_DIR_RE` and whose `.resolve()` differs from `here`. It sorts the survivors by
`_version_key` descending and returns the first whose `candidate / relative` exists and is
readable, or `None`. Comment the `here` exclusion: it is by resolved-path equality on purpose,
not by version-string comparison, because a name-based check plus any future change to how
`PLUGIN_ROOT` is computed is how the CURRENT install's live credential file ends up deleted by
the sibling branch. Comment also that in a repo checkout `cache_root` is the repository root,
which holds no directories matching the version regex, so the scan is a silent no-op there.

Wire step 5 into both resolvers. In `resolve_config_path`, after step 4 finds no legacy file:
call `_newest_sibling_holding(Path("config") / CONFIG_FILENAME)`; if it returns a directory,
call `_migrate_once` (Task 3 writes it — for now, have step 5 COPY only, via
`_atomic_write_0600(durable_target, source.read_text(encoding="utf-8"))`, returning
`durable_target`). Wrap that whole branch so any `OSError` returns the legacy path instead of
propagating: an unwritable durable home must leave the plugin working from where it read, never
refusing. Do the identical thing in `resolve_state_path` with `Path("state") / STATE_FILENAME`.

Leave a comment at the copy site marking where Task 3 inserts verify-then-delete. Do not delete
anything in this task.

Criterion 3 requires the removal — three stale install directories on this machine currently
hold full credential copies, and every future update adds another unless migration cleans up
behind itself. What is being confirmed is the SHAPE of the removal and the blast radius, not
whether it happens.

The invariants Task 3 will build, stated plainly:
- Only a SIBLING install's copy is ever removed. The current install's own
  `config/operator.local.json` is never touched by this code path, guarded by resolved-path
  equality against `PLUGIN_ROOT` rather than by version-string comparison.
- The removal runs only after the durable copy has been read back from disk and its contents
  matched byte-for-byte against what was written.
- Any `OSError` during removal is swallowed: a config that migrated but whose source could not
  be deleted is a stale-copy problem, not an operator-facing failure.
- No secret value is printed, logged or raised anywhere on this path.

The reversibility rating on this phase overall is `costly` — an operator on 0.7.0 who
downgrades looks in the old place. This task alone is `one-way`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin process → sibling install directories | The scan reads, and then deletes, credential files in directories this process does not own the lifecycle of |
| plugin process → durable home | A new plaintext credential file is created under `$HOME` |
