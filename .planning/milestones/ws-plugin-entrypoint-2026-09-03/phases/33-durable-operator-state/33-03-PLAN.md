visible to the operator — `initialize` stops naming a path inside a directory the next update
abandons.

  <action>
In `artifact_store.py`: add `import durable_paths`, delete the `DEFAULT_STATE_PATH` module-level
constant, and change `state_path()` to return `durable_paths.resolve_state_path()`. Leave
`_resolve()`, `load()`, `save()`, `collect()` and the whole two-field schema alone — the only
thing changing is where the default path comes from.

Update `state_path()`'s docstring, which currently says the pointer lives "inside the plugin".
It now says the pointer lives in the durable home so it survives a plugin update, that the
resolution order is `durable_paths`' single authority shared with the config, and that this is
what makes STATUS-05's cross-session guarantee actually hold across versions rather than only
within one.

Leave `save()` writing through `write_text` rather than `_atomic_write_0600`. That is a
decision, not an omission, and the docstring should say so: the pointer holds an identifier and
a timestamp, no secret, so the 0600 mode window the config's write closes is not a concern here
— and `_read()` already returns `None` for a half-written file, which is the same effect as no
pointer at all, so the atomicity window has no observable consequence either.

Now the three tests under `# --- where the file lives ---` in `test_artifact_store.py`. Each one
asserts something that is about to be false. Retarget each; do not delete any.

`test_the_resolved_state_path_is_not_a_dotfile` currently loops over every part of the path and
rejects any starting with a dot. The durable home is under `~/.claude/`, so the loop now fails.
Narrow the assertion to `path.name` only, and rewrite the docstring: Phase 23 D-04 is about a
file the environment's tooling cannot READ, which is a property of the filename; a dot-prefixed
ANCESTOR was never the concern, and cannot be, because the plugin's own install root already
sits under `~/.claude/plugins/cache/`.

`test_the_resolved_state_path_sits_inside_the_plugin_directory` asserts exactly the thing this
phase exists to stop being true. Replace it with a test asserting `PLUGIN_ROOT` is NOT among
`state_path()`'s parents, docstringed with why: a pointer inside the versioned install directory
is abandoned by every update, which is why STATUS-05's guarantee has been silently false since
the first one.

`test_the_resolved_state_path_is_ignored_by_version_control` shells out to `git check-ignore`,
which returns non-zero for a path outside the working tree — so it now fails for a reason
unrelated to what it was protecting. Replace the assertion with one that `REPO_ROOT` is not
among the resolved path's parents. Keep the T-27-24 reference in the docstring and note that
outside-the-working-tree is strictly stronger than gitignored: a file git cannot see at all
cannot be committed by an untracked-file sweep either.

Leave `test_the_store_exposes_exactly_load_save_and_collect` alone. It filters by
`__module__ == "artifact_store"`, so the imported `durable_paths` functions do not enter the
public set and the assertion still holds.
  </action>
