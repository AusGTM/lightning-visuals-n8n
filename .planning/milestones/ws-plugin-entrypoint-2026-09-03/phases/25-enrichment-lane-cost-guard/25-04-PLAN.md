  <action>
    Write `operator-claude-plugin/scripts/enrichment.py` as a thin module usable as a library by the
    tests and as a CLI by the skill, printing JSON to stdout from its main block the way the Phase 23
    modules do — the skill parses that, so no module prints prose.

    Three public functions plus the module's own error types.

    A provider-selection resolver taking the per-batch override and the loaded config, returning the
    effective selection. Its contract is totality: every input path returns a concrete list, because
    the backend has no default and an omitted field resolves to zero providers enabled. Validate names
    against the known provider set and raise on an unknown one — a dropped name is a batch that burns
    fewer providers than the operator approved, silently. An explicitly empty selection is legal and
    means no providers; it is still sent as an explicit empty value rather than by omission (D-06a).

    An envelope builder taking a record specification and the resolved selection. The record
    specification is one of: explicit record ids with an object type; a list name with an object type;
    or a saved-view name. Record ids expand to the events array the deployed parser consumes, each
    entry carrying the id stringified and the normalized object type. A list name is carried through
    verbatim in the shape the backend's resolution branch expects — the client does not resolve it, does
    not count it, and does not fabricate a count (D-01, D-02). A saved-view name takes exactly the path
    `25-BLOCKERS.md` records; if that record says refuse and redirect, raise a dedicated error carrying
    the recorded operator-facing sentence.

    Send only the id and the object type per event. The deployed parser spreads any additional event
    keys onto the row for a direct-field test payload, which does nothing useful for a record that
    already exists in HubSpot and only widens what crosses the boundary.

    A dispatch entry point taking the envelope, the armed flag, the config and a transport. The armed
    parameter has no default, mirroring Phase 23's dispatch exactly; disarmed raises before the request
    is constructed and before the transport is touched. Armed, it POSTs the envelope as JSON to the
    enrichment webhook path under the configured base URL, with the shared-secret header and an explicit
    timeout, and returns the parsed response body when it is JSON or the status and raw text when it is
    not — never a per-record outcome claim, which is Phase 26's job. Translate transport exceptions into
    plain language rather than relaying them; a transport exception's text can echo request headers.

    Persist nothing. The armed flag arrives as an argument for exactly one call and dies with the
    process, as Phase 23's D-11 requires.

    Write `operator-claude-plugin/tests/test_enrichment_envelope.py` covering every behaviour above
    against the shared fixtures. One test must assert the unarmed path leaves the stub's call log empty
    rather than merely asserting the raise, and one must assert the providers key is present on an
    envelope built from every record-specification form.
