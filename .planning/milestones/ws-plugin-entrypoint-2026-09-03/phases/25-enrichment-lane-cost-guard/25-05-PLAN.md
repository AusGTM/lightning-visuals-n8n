<objective>
The cost guard's arithmetic half: what this batch will cost, what is actually left, and the honest
third answer when the second question cannot be answered.

Purpose: PREVIEW-02 is only worth having if its warning can be trusted. This account has a permanent
unreadable balance (Apollo, non-master key, 403 on every usage read), so the unknown branch is the
common case, not the edge case — and rendering it as zero would produce a standing false alarm that
trains the operator to ignore the warning entirely.

Output: a dated plugin-local rate table, the estimator that reads it, the client for the status
endpoint built in 25-02, and the tri-state comparison with its two failure modes pinned by test.
</objective>

    Write `operator-claude-plugin/scripts/cost_guard.py` with a rate-table loader, an age helper, an
    estimator, a balance client and a comparison, plus a main block printing JSON so the skill can
    consume it.

    The loader resolves the rate table relative to the plugin root, the same way the Phase 23 config
    gate resolves its own file, and raises a plugin-local error naming the missing file if it is absent.
    The age helper takes a reference date argument rather than reading the clock internally, so the
    behaviour is testable and the preview can render the number D-08 asks for.

    The estimator takes the record count, the object type, the resolved provider selection and the loaded
    rates, and returns a structure carrying: a per-provider credit figure keyed by provider, where a
    provider whose rate is unknown yields an unknown figure rather than zero; the Anthropic dollar
    figure from the measured per-record rate; and the rate table's version and measurement date, so the
    caller can display provenance without re-reading the file. When the record count is not knowable —
    the backend-resolved list case from D-02 — the estimator returns a result marked as such rather than
    computing against an invented number.

    The balance client POSTs to the status endpoint path under the configured base URL with the shared
    secret header, a finite timeout, and the injectable transport seam the Phase 23 modules use. Every
    failure path — transport exception, non-2xx, non-JSON body, a body missing a provider — resolves to
    that provider being unreadable with a short reason. There is no numeric fallback anywhere in this
    function; a defaulted number here is indistinguishable from a real balance, which is the whole of
    D-10.

    The comparison walks the estimate's per-provider figures against the balance map and yields one
    verdict per provider. Branch on unreadable first, on unknown-estimate second, and only then compare
    magnitudes. Comparing before the readability check is how an unreadable balance becomes a confident
    wrong answer in either direction — a false insufficiency alarm or a false clearance. A verdict
    carries enough text for the preview to say why it is unknown, so the operator can tell a credential
    problem from an outage.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin → `hubspot/backend-status` | The only path by which the client learns a balance |
| status response → preview text | Untrusted backend content crosses into operator-facing output |
| rate table file → estimate | A stale or edited table silently changes every estimate |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-05 | Tampering | balance comparison | critical | mitigate | The comparison branches on unreadable before magnitude; a numeric fallback is grep-forbidden by an acceptance criterion; zero and unreadable are asserted distinguishable |
| T-25-20 | Repudiation | stale rate table | medium | mitigate | The table carries its measurement date and the age helper makes it displayable, so an estimate from months-old rates is legible as such rather than presented as fact (D-08) |
| T-25-21 | Information Disclosure | balance client error text | high | mitigate | Transport failures resolve to a short reason label rather than a relayed exception whose text can echo request headers; a test asserts the configured secret does not appear in any returned reason |
| T-25-22 | Denial of Service | unreachable status endpoint | medium | mitigate | An unreachable endpoint degrades to unreadable balances rather than raising, so the preview still renders and the operator still sees the estimate and the arming state |
| T-25-23 | Tampering | runtime coupling to a repo document path | medium | mitigate | The rate table is plugin-local; an acceptance criterion greps every plugin module for a docs or planning path read (D-09) |
| T-25-SC | Tampering | package installs | low | accept | This plan installs nothing |
</threat_model>
