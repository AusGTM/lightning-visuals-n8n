<objective>
Build the in-session watch. Per D-05a, **the bounded path is the load-bearing mechanism**, not a
degraded fallback: 29-RESEARCH.md observed genuine unprompted mid-conversation follow-up in the CLI
runtime but could not confirm it in Claude Desktop, which is the actual target. So this plan builds
what is certainly deliverable — a bounded watch that always ends in a report — and layers true
unprompted follow-up on top only if 29-01 Task 2 recorded a YES.

That ordering is the whole point. A phase that architects NOTICE-01 around an unverified platform
primitive fails *silently*: the operator believes something is still watching when nothing is. The
watch's contract is that it always ends by saying something.

NOTICE-02's real requirement, in 29-CONTEXT's own words, is that it never simply stops talking. A
watch that hits its bound and says nothing is worse than no watch at all.

Purpose: after a dispatch, the operator finds out what happened without having to think to ask twice.
Output: `watch.py`, its two report paths, and the config key that bounds it.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| watch → n8n executions API | A polling loop with a bound; unbounded polling is a self-inflicted rate-limit risk |
| watch report → operator | A cost figure the operator will trust for budgeting; understating it is a real harm |
| watch → dispatch path | Must stay uncrossable — a watch that can re-send turns an observation into an unapproved write |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-11 | Denial of Service | `watch.py` poll loop | medium | mitigate | Backoff schedule plus a hard config bound; the loop terminates on the bound regardless of run state, so no invocation polls indefinitely |
| T-29-12 | Spoofing | run-handle correlation | high | mitigate | 26-CONTEXT D-12's correlation is fallible; the still-running report states the correlation basis so a mis-correlated run is visible rather than asserted |
| T-29-13 | Information Disclosure | cost figure | medium | mitigate | Report balances and deltas only, never a credential or a provider response body; unknown propagates rather than collapsing to zero |
| T-29-14 | Elevation of Privilege | watch → dispatch | high | mitigate | The watch has no write or dispatch path; retry stays operator-initiated through Phase 26's armed path, and the plugin suite's autouse network guard prevents any test from proving otherwise by accident |
</threat_model>
