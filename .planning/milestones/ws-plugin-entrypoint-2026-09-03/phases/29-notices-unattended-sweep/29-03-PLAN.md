<objective>
**This is the phase's tracer** (29-01 and 29-02 precede it only because 29-RESEARCH.md makes the
platform probe the first question and the tracer needs fixtures to verify against). It wires the
thinnest possible complete sweep — one condition, end to end — through every layer the phase will
touch: read, classify, attribute, render, entrypoint. Everything 29-05 adds is expansion outward
from a path already proven.

The condition chosen for the slice is the **stuck lock**, because 29-RESEARCH.md grades it the
cleanest of the five: Phase 27 already ships the verdict, it needs no new read, and it requires no
new classification logic. Proving the architecture on the easy condition is the point — if the shape
is wrong, it is wrong after one commit rather than after five.

**What Phase 27 actually shipped (D-14 — corrects this plan's earlier text).** There is no
`is_stuck()` function anywhere in the tree. What exists in
`operator-claude-plugin/scripts/n8n_read.py` is:
- `stuck_threshold_minutes(config)` (line 107) — config key `stuck_execution_minutes`, already
  present in `config/operator.local.example.json`, defaulting to `DEFAULT_STUCK_MINUTES = 15`.
- the **tri-state** `stuck` value computed inside `summarize_execution()` (lines 150–169) and
  surfaced on `last_execution()` and through `status.describe_workflow()` as
  `last_run["stuck"]` / `last_run["stuck_threshold_minutes"]`.

The tri-state is the good news, not an obstacle: `True` is over the threshold, `False` is under, and
**`None` means in flight with a start time we could not read** — which per Phase 27 D-07b(i) must
never be flattened to `False`. This plan's condition contract already asked for a
"boolean-or-unknown outcome", so the shipped shape is the one it wanted.

This is production code, not a prototype. It ships with the same verification any later task
carries, and 29-05 builds on it rather than replacing it.

Alongside the slice, this plan lands **NOTICE-05's enforcement** (D-02, D-02a): a test that walks
the sweep's transitive import graph and fails if anything mutating becomes reachable. D-02 is
explicit that the sweep must have *no code path* to a mutation, not merely avoid calling one — which
a comment cannot deliver and a test can. The repo already has the weaker version of this guarantee
in `scripts/enrichment_cost_ledger.py`'s docstring; this makes it mechanical.

Purpose: prove the sweep's architecture and its safety property on the same commit.
Output: four sweep modules, an end-to-end tracer test, and a read-only import-graph guard.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sweep graph → any mutation surface | The boundary NOTICE-05 exists to make structurally uncrossable |
| session-less sweep → backend | Runs with nobody watching; whatever it can reach, it reaches unattended |
