<objective>
Wave 0 for this phase, plus the one measurement D-06 requires. Two jobs, both prerequisites:

**Fixtures.** Every later plan's `<automated>` verification runs against mocked n8n-execution and
backend-status payloads. The fixtures must include the awkward shapes, not just the happy ones —
29-RESEARCH.md's Pitfall 1 and Pitfall 5 are both cases where the *healthy-looking* payload is the
dangerous one, and a fixture set that omits them makes the sweep's blind spots untestable.

**The measured bound (D-06, D-06a).** D-06 forbids guessing the watch bound. 29-RESEARCH.md found
the data is already being fetched and simply never used: `scripts/enrichment_cost_ledger.py::
_list_executions()` pulls `/api/v1/executions`, whose objects carry both `startedAt` and `stoppedAt`,
and the ledger only ever reads `startedAt`. No new endpoint, no schema change — a computation this
repo has never bothered to do. 25-CONTEXT D-11a needs the same number for chunk sizing, so it is
measured once here and used twice.

Note on PLUGIN-04: `scripts/enrichment_cost_ledger.py` is an **admin** measurement script, not
plugin code. The plugin still touches no backend file — what crosses into the plugin is the
resulting *number*, consumed as a config default in 29-04.

Purpose: 29-03, 29-04 and 29-05 all need something that does not exist yet. This plan is that
something.
Output: sweep fixtures, a `durations` subcommand, and `29-TIMING.md` recording the measured rate.
</objective>
