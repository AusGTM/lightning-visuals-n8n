<objective>
Put the email gate at the choke point, and make it loud.

Purpose: a contact row with firstname + lastname + company but no email dead-ends completely and
silently today. The deployed ingest lane resolves identity by email only, so the row becomes
`ambiguous`, routes to review, and produces no HubSpot write and no object id — which means it
cannot be enriched later either, because both enrichment entry points need an existing id.
Nine Gold Coast Turf Club directors evaporated this way. `config/column_mapping.yaml`'s identity
rule accepts the row and `write_dispatch_csv` guards only against extra keys, so the plain
extraction lane accepts it today. Fixing it at `write_dispatch_csv` fixes every caller at once
and is also the smaller diff.

Output: `hold_emailless` for callers that want to separate and report; a raise inside
`write_dispatch_csv` for callers that forget to.

This plan shares no file with plan 37-01 and runs beside it.
</objective>
