<objective>
The deterministic half of failure-cause translation, plus the guardrail that makes the
non-deterministic half safe: a static table mapping known error signatures to one plain sentence and
an attribution of who can fix it, and an unmatched branch that is honest about not knowing (D-04,
D-05).

Purpose: this is the surface whose job is telling someone whether they can act on a problem. A
confident wrong answer here does more damage than an honest "I don't recognize this" — which is why
D-05 makes the unmatched branch's shape a hard requirement rather than a nicety. The table is
expected to grow: every signature the fallback handles more than once is a candidate for promotion
into it (D-06), so the table's shape has to make adding an entry a one-line data change.

Scope note this plan takes on the chin: research established that of the four causes STATUS-02 names,
only one is directly observable from an execution's own status, because every provider-facing node
in the enrichment workflow is configured to continue on error and therefore reports a run as
successful even when a provider returned 401, 429, or an exhausted quota (D-04a). Plan 27-04 makes
those three visible by reading per-node output rather than run status (D-04b); this plan supplies the
table and the guardrail those readings are translated through, and seeds entries for all four causes
so the deterministic path covers them once 27-04 surfaces them.

Output: one pure Python module in the plugin, with no HTTP and no I/O, and two test files — one for
the matching path and one dedicated to the guardrail, because the guardrail is the behaviour most
likely to be quietly eroded by a later edit.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| n8n error payload → operator conversation | Untrusted, credential-echoing text crosses here |
| translation result → operator decision | A wrong attribution here causes a real-world wrong action |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-06 | Information Disclosure | raw error text relayed to the operator | high | mitigate | Redaction of bearer, key-shaped and authorization-header material before the raw text is returned; asserted per credential shape by unit test |
| T-27-07 | Repudiation / operator harm | unmatched attribution | critical | mitigate | The admin attribution is unconditional on the unmatched branch, has no override parameter, and is proven by a sweep over many unrecognized inputs |
| T-27-08 | Denial of Service | unbounded raw text | low | mitigate | Raw text truncated to a bounded length with an explicit marker |
| T-27-09 | Spoofing | a crafted error string matching a benign signature | low | accept | The table maps to explanations only; no action, permission or write is gated on a match, so a mismatched explanation cannot escalate anything |
| T-27-SC | Tampering | package installs | low | accept | Standard library only; no npm, pip or cargo operation in this plan |
</threat_model>
