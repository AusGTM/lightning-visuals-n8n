<objective>
The full picture: every workflow the key can see, what is in flight, what is wedged, why the last
failure failed, and how many records are waiting on a human — rendered as the conversational text
that is this surface's default form (D-09).

Purpose: criterion 4's real point is that a silently wedged backend becomes visible without anyone
thinking to look. Counts and honest states matter more than presentation here. Two corrections
research forced are implemented in this plan: stuck is an execution-age question read from the
executions API rather than a HubSpot lock property that was never built (D-07a/D-07b), and failure
causes are read from an execution's per-node output rather than its run status, because the pipeline
was deliberately built to keep running when a provider fails and therefore reports those runs as
successful (D-04a/D-04b).

Output: the breadth on top of 27-03's proven slice, the per-node error harvest feeding 27-02's
translation table, and the skill that turns the assembled mapping into plain language.
</objective>
