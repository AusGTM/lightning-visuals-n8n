<objective>
Fix the tier flow, the last of the four. Two defects live here.

F8: WF1's else branch writes D for any score below 15, so a score of 10 and a score of -20 both
grade D with no veto in sight. D-03 settles the target as Unscored, matching `src/icp_scoring.py`
exactly — the operator first preferred keeping D, then confirmed Unscored once the conflict with
ENGINE-07, ROADMAP success criterion 3 and the parity oracle was laid out. Treat Unscored as
settled. D stays veto-only.

F7: WF1 enrolls only on `lv_icp_fit_score` known, so a veto that fires without moving the score
leaves the tier stale until something unrelated pokes the score. Validated live: a US flip set the
flag true and the tier stayed B. Adding `lv_anti_icp_flag` as a second enrollment trigger is what
VETO-03 asks for.

One prerequisite gates both: HubSpot's `lv_icp_tier` dropdown historically carried only A, B, C and
D. If `Unscored` is not a valid enum option, WF1's PUT succeeds and the tier comes back empty. 40-01
already read the live property definition; Task 1 acts on that answer.

Purpose: a low-fit company and a disqualified company are different things, and reps act on the
difference.
Output: one retargeted, rebranched tier flow and, if needed, one enum option.
</objective>
