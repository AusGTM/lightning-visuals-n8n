<objective>
Retarget the two mapper flows that read properties enrichment can never write, and complete the veto
ownership handover D-01 began.

Today the geography flow triggers on native free-text `country` and the revenue flow on native
`annualrevenue`. The pipeline writes neither: `lv_country_region_normalized` and `lv_revenue_band`
are the canonical properties, and `annualrevenue` is on the MVP never-write list. That is F2 and F3,
and it is why enrichment can populate a company perfectly and move no score at all.

One consequence is worth stating up front because it changes this plan's risk profile. 40-RESEARCH.md
flagged F10's inclusive-`IS_BETWEEN` revenue-boundary overlap as the phase's highest-risk single
edit, because reordering numeric bounds inside a branch action is exactly the API-editability
question assumption A1 leaves open. But ENGINE-03's retarget removes the numeric branches
altogether: once the trigger is `lv_revenue_band`, matching is string equality against nine enum
values and overlap is structurally impossible. The boundary contract does not disappear — it moves
upstream to `normalizeRevenueBand`, where exactly 750000000 already bands to `750M-1B`, and where it
can be asserted offline for free. What remains is a branch-type change (numeric range to string
equality), which is its own API-acceptance question and carries D-05's portal-UI fallback.

Purpose: without this, every other fix in the phase is unreachable from the enrichment write path.
Output: two retargeted flows, one deleted veto branch, and the veto now written in exactly one place.
</objective>
