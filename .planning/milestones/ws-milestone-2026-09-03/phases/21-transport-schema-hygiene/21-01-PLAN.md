<objective>
Retire the last native HubSpot search node in the repo. `Dedupe Search (candidate
contacts)` — the single remaining `_hs_http_search_node` holdout, flagged in the codebase
as a known unfixed concern since Phase 17.01 — moves onto the credential-bound httpRequest
envelope that every other search site already uses (the BUG-10/22/23 mechanism), the now-dead
native-search helper is deleted, and the class is closed with a guard predicate plus a live
read-back against the deployed workflow.

Purpose: the native node returns zero items on a zero-hit search, which silently stops the
downstream chain and reports `status: success` — the exact failure mode that hid BUG 10
across six nodes. The dedupe sweep has never been activated, so this is the last chance to
fix it before it can ever run live (Phase 22 arms the pipeline).

Output: a rebuilt `wf_scheduled_maintenance_cloud.json` with zero native search nodes, two
new guard predicates, a live read-back verifier, and a redeployed (disarmed) workflow.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| n8n Cloud → HubSpot CRM API | The dedupe search node crosses this boundary with the `LV HubSpot` private-app token; a transport change risks losing the credential binding and deploying an unbound node that 401s at runtime. |
| Local repo → n8n Cloud (deploy) | The deploy call mutates the live orchestration layer; the write-safety constants baked into the workflow are the only thing standing between a redeploy and live HubSpot writes. |
| Verifier stdout → SUMMARY / git history | Live read-back output is pasted into a committed document; anything the verifier prints is permanently disclosed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-01 | Denial of Service | `Dedupe Search (candidate contacts)` zero-hit behavior | medium | mitigate | The httpRequest transport returns an empty-results envelope instead of zero items, so a zero-hit run no longer silently stops the chain while reporting success (Task 1); the class is closed by the zero-native-search predicate (Task 2). |
| T-21-02 | Spoofing | Credential binding after the transport change | high | mitigate | `NODE_CREDENTIAL_MAP` is node-name-keyed and the binder recognizes the httpRequest+predefinedCredentialType shape; Task 1's acceptance runs `tests/test_deploy_credential_binding.py` unchanged, and Task 3's live read-back shows the served node. An unbound node fails the deploy closed rather than importing silently. |
| T-21-03 | Elevation of Privilege | Redeploy accidentally arming HubSpot writes | high | mitigate | Task 3 changes no write-safety constant; `test_committed_write_safety_constants_are_all_disabled` guards the committed artifact, and the deploy is explicitly disarmed and unactivated. Any classifier block converts to an operator action rather than a workaround. |
| T-21-04 | Information Disclosure | Verifier output pasted into a committed SUMMARY | medium | mitigate | The verifier prints only node names, methods and URLs — never header values — mirroring `verify_live_lusha_urls.py`; Task 3's acceptance requires reading the output before pasting. |
| T-21-05 | Tampering | Dedupe lane gaining an unreviewed write surface | medium | mitigate | Task 2's classify-only predicate pins the lane to exactly one write node with an explicit emitted-property allowlist; a second write fails the suite. |
| T-21-06 | Repudiation | Deploy exit code taken as proof of what is live | medium | mitigate | Task 3 requires an independent read-back (Phase 19 BUG 26's lesson: the live deployment silently predated the committed build while every local check passed). |
</threat_model>
