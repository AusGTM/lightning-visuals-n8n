<objective>
Package the entire operator-only half of this milestone into one document and hand it over. Four
armed actions are outstanding across three phases — the Lusha id staging properties, the org-type
probe ladder, the enum migration, and this phase's canary — and every one of them is blocked for
agents by the environment's permission classifier. Run separately from four different summaries they
would take four windows and four context reloads; sequenced correctly they are one sitting.

Purpose: the canary is the last verification this milestone owes, and its value depends entirely on
what is true before it fires — the deployment being current, the schema being migrated, the target
record still being able to trigger research, and the write state being genuinely disarmed at the
start. A runbook that does not sequence those is a canary that proves whichever subset happened to
hold.

Output: `22-OPERATOR-RUNBOOK.md`, a decision on whether the one-way schema migration runs inside this
window, and a blocking handover to the operator.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator shell → n8n Cloud (armed overlay) | The only path that can enable HubSpot writes in the deployed workflow; the allowlist is the blast radius. |
| Deployed workflow → HubSpot CRM (armed) | Real writes to a production portal for the duration of the window. |
| Operator shell → HubSpot schema (armed) | Sections A and C mutate portal schema, one of them irreversibly. |
| Runbook document → git history | The document is committed; anything pasted into it, including evidence, is permanent. |
| Agent session → the whole window | Structurally blocked; the agent writes the procedure and never runs it. |
