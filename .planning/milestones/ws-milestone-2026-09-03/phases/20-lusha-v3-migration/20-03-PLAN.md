<objective>
Teach `lushaCandidates()` to read the v3 envelope while emitting candidates that are
field-identical to what v2 produced, so the merge, scoring and staging layers see no change at all.

`lushaCandidates()` currently handles three v2 envelope shapes defensively and then runs a body of
field-extraction logic that roughly 53 assertions in `tests/n8n/enrichment.test.mjs` and every
downstream consumer depend on. The safe move, and the pattern this same file already uses for
ZoomInfo, is to confine all v3 handling to the envelope-unwrap block at the top of the function,
normalizing into the SAME intermediate object the extraction logic already consumes, and to leave
the extraction logic untouched.

The v2 branches are then retired rather than left as unreachable code: v2 sunsets 2026-11-18, this
migration ships before then, and after Plan 05's redeploy no v2-shaped response can ever arrive
again. Retirement happens in its own task, after the v3 path is proven green, so each step has an
independent checkpoint and the risky half is a separate reversible commit.

Purpose: satisfy "downstream is untouched" as a tested fact, not an assumption.
Output: three v3 fixtures, a v3 envelope adapter, migrated test coverage, retired v2 branches.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Lusha HTTP response -> `lushaCandidates()` | Untrusted third-party JSON of unpredictable shape enters the pipeline here. |
| candidate stream -> merge and staging layers -> HubSpot | Whatever this function emits becomes a candidate that the merge policy may promote to a canonical CRM field. |
| live provider response -> committed test fixture | Real personal contact details would otherwise be committed to the repository. |
