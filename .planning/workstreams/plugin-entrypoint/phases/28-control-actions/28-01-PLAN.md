<objective>
The tracer for this phase: one mutation pipeline, wired end to end, proven on the thinnest real
capability the phase ships — turning a workflow on or off (CONTROL-02). Every later control action
in Phase 28 is a different payload through this same pipeline.

Purpose: this phase is the only one in the milestone that mutates the backend. Getting the
pipeline's shape wrong — trusting a 200, deactivating before validating, blindly re-activating a
workflow that was deliberately off — is the class of bug that is discovered live, in production,
after ten layers are already committed. Proving the whole path on a no-JSON-write mutation first
converts that risk into one commit.

Output: `operator-claude-plugin/scripts/n8n_control.py` — fetch, four-key PUT body filter, the
structural allowlist diff, the deactivate→PUT→restore-prior-active bracket, the independent
read-back, and one `MutationResult` shape that carries verified/failed plus the reversal statement.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin → n8n Public API (mutating verbs) | The first boundary in this milestone that carries a write; anything crossing it can change production behavior |
| plugin test suite → n8n Cloud | A test that reaches the network can perform a real, unapproved workflow mutation |
| fetched workflow object → outgoing PUT body | n8n replaces `nodes`/`connections`/`settings` wholesale, so anything that drifts between fetch and PUT lands in production |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-28-01 | Tampering | `apply_mutation` outgoing body | critical | mitigate | `assert_only_allowlisted_change` runs before any network call; a diff outside the named nodes raises and the transport call log stays empty (Task 2) |
| T-28-02 | Repudiation | `MutationResult` verdict | high | mitigate | `verified` requires an independently fetched value equal to the requested one; the all-200-but-stale case is a named test (Task 1, Task 3) |
| T-28-03 | Elevation of Privilege | deactivate→PUT→activate bracket | high | mitigate | The bracket restores the PRIOR active state; a workflow that was off is not turned on by a mutation to its content (Task 2) |
| T-28-04 | Tampering | plugin test suite | high | mitigate | The autouse `no_network` guard from 23-03 covers every requests verb; Task 3 asserts PUT and GET explicitly |
| T-28-05 | Tampering (concurrent, non-adversarial) | a concurrent admin `deploy_n8n_workflows.py` run racing a plugin PUT | medium | accept | n8n exposes no optimistic-concurrency field on this endpoint (28-RESEARCH.md §Summary). Mitigation is procedural: always fetch fresh immediately before mutating, keep the window minimal, and report a mismatched read-back loudly |
| T-28-06 | Tampering | stale in-session workflow copy reused for a later mutation | medium | mitigate | `apply_mutation` always fetches fresh; no cached workflow object is accepted as an argument |
</threat_model>
