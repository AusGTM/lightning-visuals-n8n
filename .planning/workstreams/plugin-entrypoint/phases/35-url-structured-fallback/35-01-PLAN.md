<objective>
Build the deterministic half of the URL structured-representation fallback — a pure module that
turns a pasted page URL into an ordered, same-host, capped list of candidate URLs — and wire
`extraction.md`'s URL adapter to it so the "fetched but nothing usable" branch escalates instead
of terminating.

Purpose: `https://gctc.com.au/board-of-directors/` converts to nothing usable as HTML (measured
2026-08-05: truncated after `<title>`, 0 people) while the site's own WordPress REST
representation serves all 9 directors. The plugin behaved correctly against an incomplete
contract; this closes the contract.

Output: `scripts/url_fallback.py` (candidate construction, same-host check, fetch cap, CLI),
its test file, and the rewritten `Adapter: a public URL (INGEST-05)` section of `extraction.md`.
</objective>

<architectural_fact_read_this_before_task_1>
`web_fetch` is a **model-invoked server tool**. `url_fallback.py` does not and cannot call it,
and a python script that shelled out to fetch a URL would be the scraping path this milestone
explicitly excludes (`REQUIREMENTS.md` Out of Scope, unchanged by this phase).

So the phase splits, and every task below respects the split:

- **In python, deterministic and testable:** constructing candidate URLs from a pasted URL, the
  same-host check, the fetch cap, the ordering, and the give-up sentence. No I/O. The autouse
  `no_network` guard in `tests/conftest.py` is satisfied **by construction** — there is nothing to
  stub, because there is nothing that could reach the network. Do not invent a transport seam for
  this module; a seam implies a fetch that does not exist.
- **In `extraction.md`, as instructions to Claude:** when to escalate (only on fetched-but-empty),
  showing the candidates to the operator before fetching, the wording of the give-up, and
  provenance naming the URL actually fetched.

Do NOT write a task that makes python perform a fetch. Do NOT write a mock-`web_fetch`
integration test that pretends otherwise.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fetched page content → next fetch target | The sitemap rung derives candidate URLs from content a remote host served. That content is attacker-influenceable in exactly the way `extraction.md`'s existing Trust note describes for extracted data — but here it selects the *next request*, not just a field value. |
| pasted URL → constructed candidate | The operator's URL is the only authority on which host may be reached. Anything the module builds inherits that host and nothing else. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-35-01 | Tampering | sitemap-derived candidate URLs → `web_fetch` | high | mitigate | `filter_candidates` refuses any URL whose netloc differs from the pasted URL's, before it can be fetched; `extraction.md` instructs that page-derived URLs pass through `--filter` and are never fetched directly (Task 2, Task 3) |
| T-35-02 | Elevation of Privilege | a page-supplied URL pointing at an internal or link-local host (SSRF shape) | high | mitigate | same-host equality against the operator-pasted host; a page cannot nominate a host the operator did not already reach (Task 2) |
| T-35-03 | Denial of Service | an uncapped ladder walking a sitemap of thousands of URLs | medium | mitigate | `MAX_FOLLOWUP_FETCHES = 5`, spent across the whole ladder via `already_fetched`, pinned by test (Task 2) |
| T-35-04 | Information Disclosure | fetched content carrying embedded instructions the model follows | medium | mitigate | `extraction.md`'s existing Trust note stays; Task 3 adds that page-derived URLs are data, not direction, and that the operator approves candidates before any fetch |
