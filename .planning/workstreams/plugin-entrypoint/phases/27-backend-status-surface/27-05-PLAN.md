<objective>
The dashboard half of STATUS-05: the same status data the text answer carries, published as an
Artifact on request, stamped with its fetch time, and re-published to the same URL on refresh —
including a refresh in a session that did not create it (D-09/D-09a).

Purpose: cross-session sameness is what makes the dashboard bookmarkable, and it is the one part of
this that does not come free. Republishing within a single conversation already lands on the same
identifier; a new conversation has no memory of it, so the plugin has to keep one. That makes this
the first plugin-managed state in the design, which is why D-09b bounds it deliberately: exactly an
identifier and a timestamp, an operator-configurable expiry defaulting to thirty days, and garbage
collection on the next open. The bound is enforced here by a test, not by intention — a store that
accepts arbitrary keys becomes a general-purpose store in one commit.

Output: a two-field store with expiry and collection, a dashboard payload proven to carry the same
data as the text answer, the skill wiring, and one human checkpoint for the part no automated harness
can reach.
</objective>

    state. Resolve its path relative to the plugin root, under a state directory, with a plain

    is an environment constraint rather than a naming preference.

    Expose exactly three entry points: load, save, and collect. Save takes an identifier and writes a
    document containing that identifier and a current timestamp, and rejects any additional field
    rather than silently persisting it — this is the guard that stops a two-field store becoming a

    fields, and is within the expiry; every other case returns nothing, because a stale or broken
    pointer is indistinguishable in effect from no pointer and must not produce an error the operator
    has to read. Collect deletes an expired file and leaves a live one alone, and is a no-op when
    there is nothing there.

    secret, no record identifier, no permission state; the conversation-scoped arming grant in
