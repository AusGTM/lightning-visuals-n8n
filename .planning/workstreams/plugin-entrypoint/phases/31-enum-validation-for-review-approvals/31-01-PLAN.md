<objective>
Build the enum spine: one generated source of truth for what HubSpot's company enumeration
properties accept, one hand-written validator over it, and that validator wired into the two
places a value can reach HubSpot — enrichment staging (`mergeCompanies`) and review apply
(`reviewApply`, which the decision endpoint's approve branch and the 15-minute backstop both
call).

This closes BUG 28 (every `industry` approval 400s) and BUG 29 (the preview cannot see it) at
the same seam, because `reviewDecision.js` computes preview and apply through one code path.

Per CONTEXT § "The fix shape": validate-and-refuse, NO mapping layer. The ONLY mapping is an
exact case-insensitive label-to-value match. Raw provider strings survive in the record's
enrichment provenance, so refusing canonical promotion loses nothing.

Purpose: a review approval can never carry a value HubSpot will refuse.
Output: 3 new files, 3 edited n8n modules, regenerated workflow JSON, 2 new test files.
</objective>

(b) `n8n/code/hubspotEnums.generated.js`. Header mirrors `taxonomy.generated.js`: the source

(c) `n8n/code/hubspotEnums.js`, hand-written, requiring `./hubspotEnums.generated`. Exports
three functions:
  - `isEnumBound(property)` — true when the property is a key of `COMPANY_ENUM_PROPERTIES`.
  - `normalizeEnumValue(property, value)` returning `{ ok, value, reason }`. A property that
    is not enum-bound returns ok with the value unchanged. A blank value (null, undefined,
    empty string, empty array) returns ok unchanged. For a single-select property: an exact
    match against `values` returns ok unchanged; otherwise a lowercased lookup in
    `labelToValue` returns ok with the INTERNAL value (this is the `Sports` -> `SPORTS`
    mapping and the only mapping this repo performs); otherwise not-ok with `reason` set from
    `enumRefusalMessage` and `value` left as the ORIGINAL so the caller can report it. For a
    multi-select property: split an array into its elements or a string on `;`, normalize each
    part, and return ok only when EVERY part is ok, preserving the container shape the caller
    passed (array in, array out; string in, semicolon-joined string out). Never throw.
  - `enumRefusalMessage(property, value)` — one plain-language sentence naming the offending
    value and the property, stating how many options the property accepts, and listing up to
    three accepted LABELS that share a token with the offending value. Token hint rule: lowercase
    the offending value, split on non-alphanumerics, drop tokens shorter than four characters
    (this is what stops the live case matching on the word `and`), score each label by how many
    of its own tokens appear in that set, keep the highest three with a score of at least one,
    and omit the hint clause entirely when nothing scores. This is a MESSAGE HINT ONLY and is
    never consulted by `normalizeEnumValue` — fuzzy matching as a mapping mechanism is
    explicitly deferred per CONTEXT § Deferred Ideas.
