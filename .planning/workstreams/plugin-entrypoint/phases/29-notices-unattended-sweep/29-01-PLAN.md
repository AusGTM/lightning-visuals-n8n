<objective>
Answer, by observation rather than inference, the two platform questions this phase's architecture
rests on — before any sweep code is written. 29-RESEARCH.md named these Open Questions 1 and 2 and
graded them the phase's only MEDIUM/LOW-confidence claims; D-04 requires them verified up front,
not discovered mid-implementation.

Question 1 (load-bearing, per D-01/D-01a): a scheduled Claude routine is *enabled* on this machine —
`coworkScheduledTasksEnabled: true` and a working routine at
`~/Documents/Claude/Scheduled/weekday-morning-brief/SKILL.md` both confirm that. What is **not**
confirmed is that a scheduled routine's instruction body can invoke *this plugin's own* skill rather
than only an MCP-connected SaaS connector. If it cannot, D-01's host does not exist and the phase
needs D-01b's fallback instead.

Question 2 (explicitly bonus-only, per D-05a): whether Claude Desktop chat exposes a
background-then-notify primitive. A positive answer is an enhancement layered on in 29-04. A
negative answer changes nothing — 29-04 builds D-07's bounded path either way.

Purpose: a phase that discovers its host is unreachable after the sweep is fully built has wasted
the whole phase. This is the cheapest possible test of the most expensive possible wrong assumption.
Output: `29-HOST-PROBE.md`, a committed record of what was observed, which 29-05 and 29-06 read
rather than re-deriving.
</objective>
