<objective>
Ship the sweep: the skill the routine invokes, the routine template the admin installs, the docs that
make the two-part setup explicit, and the one live end-to-end gate that proves the whole path works
on a real backend.

29-RESEARCH.md flagged the seam this plan closes. The sweep's *logic* lives under
`operator-claude-plugin/` per PLUGIN-04, but its *trigger* is a **cron/launchd job running
`claude -p` headless** (29-HOST-PROBE.md's amended host — the Claude Desktop scheduler's UI is not
visible on the operator's surface, and cloud Routines fail on both repo access and secrets).
Installing the sweep is therefore two steps — install the plugin, then the admin installs the
cron/launchd entry — and a phase that ships the code without documenting the second step ships a
sweep that never fires.

The live gate matters as much as the code. Everything before this point was verified against
fixtures. NOTICE-03's claim is about a notification arriving with nobody watching, and no fixture can
demonstrate that.

Purpose: the sweep exists in the operator's world, not only in the test suite.
Output: the skill, the routine template, the setup documentation, and an observed live notice.
</objective>
