<objective>
Replace the sweep's unattended trigger. The LLM comes out of the path entirely; a shipped
`sh` wrapper runs `sweep_entry.py` directly, posts one banner per notice, logs the full JSON,
and — the half the old design never had — makes its own inability to run LOUD.

Purpose: RB-8 proved NOTICE-03 fails under real cron, silently. The failure was structural to
the LLM in the trigger (expired token with an empty refresh, `node` off cron's PATH), and the
sweep never needed an LLM: `sweep_entry.py` under `env -i` with zero credentials emits the
byte-identical notice JSON, exit 0. This plan ships the fix that was proven live 2026-08-03.

Output: the wrapper, a two-sided test pinning its contract with `sweep_entry.py`, a rewritten
install template, an amended D-01, and the docs/changelog/state trail.

**This plan does not seal NOTICE-03.** The live re-run of RB-8 against the new trigger is the
phase's exit gate and lives in 32-02.
</objective>

Shape: shebang `#!/bin/sh`, `set -u`, three positional arguments in this order — `$1` the plugin
root (the directory containing both `scripts/` and `skills/`), `$2` the python interpreter that
has the plugin's `requirements.txt` installed, `$3` the log path. Guard the arity BEFORE the
first assignment: under `set -u` an unbound `$1` exits with no banner at all, which is exactly
the silent death this phase exists to remove — so if `$#` is not 3, post the failure banner and
exit non-zero.

Two functions:
- `stamp()` — appends `[<timestamp from `date '+%Y-%m-%dT%H:%M:%S%z'`>] <args>` to the log with `>>`.
- `banner()` — a single `/usr/bin/osascript -e` call (absolute path: cron's PATH is minimal)
  posting `display notification "<text>" with title "LV Backend Sweep"`. This is the ONLY
  osascript call site in the file.

Body, in order:
1. `OUT=$(cd "$1" && "$2" scripts/sweep_entry.py 2>&1)` with `RC=$?` captured on the very next
   line. Folding stderr into `OUT` is deliberate — a traceback must reach the log rather than
   vanish into cron's void.
2. `RC` non-zero → stamp the exit code and `OUT`, banner that the sweep could not run and to ask
   the admin, `exit "$RC"`.
3. Count the notices with the SAME interpreter it was handed — `"$2" -c '<program>' "$OUT"` —
   never a second interpreter and never `python3` by name. The program is single-quoted, reads
   `sys.argv[1]`, `json.loads`es it, prints `len(d)` when the result is a list, and prints `-1`
   from a bare `except Exception` otherwise. `-1` is the sentinel for "unreadable", distinct
   from `0`, which means healthy.
4. Count is `-1` → stamp an unreadable-output line with `OUT`, banner that the sweep returned
   something unreadable and to ask the admin, `exit 1`.
5. Count is `0` → exactly one `stamp` line reading `LV sweep ran, backend healthy, no notices.`
   then `exit 0`. No banner, no second line, no all-clear. NOTICE-04's silence is the point:
   the one line is a run stamp, not a report.
6. Otherwise → stamp the count, append `$OUT` (the full JSON, unmodified) to the log, then run a
   second `"$2" -c` program printing each notice's `headline` one per line, piped into a
   `while IFS= read -r` loop posting one banner per non-empty headline; finish with a stamped
   count of notifications posted.

Banner escaping (mitigates T-32-01): before a headline is interpolated into the osascript
string, escape BACKSLASH first and DOUBLE-QUOTE second — `sed 's/\\/\\\\/g; s/"/\\"/g'`. The
live draft escaped quotes only, which leaves a headline containing a backslash able to terminate
the AppleScript string early and lose the banner. Then truncate with `cut -c1-200` to hold the
§A5 one-line budget. Shell parameter expansion is not re-scanned, so there is no command-
substitution path here; the residual risk is a lost banner, not execution.

The schedule invokes this file as `/bin/sh <path> …` (Task 2), so nothing depends on the
executable bit surviving a marketplace clone or an `rsync`; keep the shebang as documentation
anyway.
