<objective>
Build Half B's engine and its operator-facing entrypoint: a module that reads a spreadsheet's
headers, says which ones the backend will not recognise, proposes a canonical prop for the ones
it can honestly propose one for, refuses the ones it cannot, and — only when handed an explicit
per-header confirmation — writes a corrected copy of the file whose header row is the only thing
that changed.

This is the phase's tracer: one header (`Ph.`) travels the whole path end to end — read →
suggest → confirm → corrected file on disk → re-preview showing `phone` — driven as a subprocess
at the layer the operator reaches, and committed, before Half A's alias widening (34-02) or the
skill wiring (34-03) build out from it.

Purpose: STRUCT-04 — an ambiguous header is flagged for confirmation, never resolved by
guessing. INGEST-06 — what cannot be honestly resolved gets a named reason, not a silent drop.
Output: `scripts/header_suggest.py` and `tests/test_header_suggest.py`.
</objective>

so a refused call leaves the filesystem untouched.

First guard: resolve `canonical_props(mapping_path)`; raise `HeaderSuggestError` when it is
`None`. Then compute the set difference of `confirmed`'s VALUES against that list and raise
`HeaderSuggestError` when it is non-empty, with a message naming the offending value(s) and the
accepted props. This mirrors `write_dispatch_csv`'s own `extra` guard exactly: an allowlist
checked before the write, not a filter applied during it. It is also the V5 control — without it
the confirmed set is an arbitrary operator-typed string written straight into a header row the
backend then reads, which is a second mapping authority wearing a canonical-looking label.

Second guard: normalize each KEY of `confirmed` with `preview._normalize_header` and raise
`HeaderSuggestError` when any lands in `REFUSE_NAME_SHAPES`, reusing `NAME_REFUSAL_REASON` in the
message. State in a comment why the writer repeats the suggester's refusal rather than trusting
it: the two are separate entry points, the CLI accepts `--confirm` for any header the operator
