<objective>
Give the operator the decision half of the loop: adjudicate a flagged record conversationally, see
exactly what would be written, and — only behind a review-specific session arm — write it and have
the result verified rather than assumed (REVIEW-03, REVIEW-04, REVIEW-05).

The exact-write display is not a client-side reconstruction of the merge. The endpoint computes the
patch and, unarmed, returns it without writing (D-03, D-05) — so what the operator approves is
literally what the backend would send, and no second copy of the merge rule exists in the plugin
(D-07). Arming is session-scoped and held in memory only, so a triage session of ten records is one
arming step rather than ten (D-04) and nothing survives the session (Phase 23 D-11's discipline).
The arm is its own switch: arming dispatch grants nothing here and arming here grants nothing there
(D-02), which 30-01 already made true at the backend.

**This module is the milestone's second mutating client module, so it carries an env kill switch of
its own: `ALLOW_REVIEW_SUBMIT` (D-16, Phase 28 D-34).** The session arm arrives from the
conversation and the human confirmation happens in the conversation — both live inside the same
process the module is running in, so neither survives an agent, a test harness, or a scheduled
routine reaching `submit_decision` by a path nobody anticipated. The env gate is the one that does.
This is the same asymmetry Phase 28's re-check found and abolished when `n8n_arming` had a human
checkpoint but no variable, and the resolution is identical in every particular including the
near-miss value table.

Output: the decision module, its tests, and the skill that makes the whole loop reachable by asking.
</objective>

    Write `operator-claude-plugin/scripts/review_decision.py` with three functions plus its env gate.

    **The env gate comes first, in every sense (D-16, Phase 28 D-34).** `ALLOW_REVIEW_SUBMIT` is this
    module's kill switch: only the exact string `"true"` proceeds, and it is checked **before any
    transport is constructed**, so an unset variable leaves the recording transport's call log empty
    rather than merely unsent. Its refusal names the variable in plain language and says an admin
    sets it. Three properties, carried over from `ALLOW_N8N_ARM` without variation:
    (a) semantics identical to `ALLOW_N8N_ARM` / `ALLOW_N8N_PROBE` — `""`, `"1"`, `"yes"`, `"TRUE"`
    and `"True"` all refuse; (b) it gates **submitting a decision only** and never any un-doing path,
    the same way `ALLOW_N8N_ARM` gates arming but never disarming — nothing that records a reason,
    re-queues a record, or otherwise walks a decision back may consult it; (c) it is defence in
    depth, not a replacement — the session arm and the per-decision exact-write confirmation both
    stay, and `preview_decision` is unaffected because a dry run writes nothing.

    **`ALLOW_REVIEW_SUBMIT` is NOT `ALLOW_HUBSPOT_REVIEW_WRITES`, and the module docstring must say
    so.** The latter is the backend baked constant from 30-01 — a literal compiled into the workflow
    JSON, overlaid at deploy time, read by `_writeSafetyAllows()` inside n8n. `ALLOW_REVIEW_SUBMIT`
    is a plugin-side operator environment variable read by Python on the operator's machine before a
    request is built. Different layers, different processes, both required. Reusing the backend's
    name would let an operator believe setting one had done the work of both.

    `preview_decision(config, object_type, record_id, decision, reason, transport=requests)` POSTs the
    decision with the dry-run flag true and returns the backend's outcome plus its `would_write` map.
    This is the only source of the exact-write display — the module must not build a patch of its own.

    `submit_decision(config, object_type, record_id, decision, reason, reviewed_by, review_armed,
    transport=requests)` checks `ALLOW_REVIEW_SUBMIT` first, then refuses before any network call when
    `review_armed` is false, returning the preview's `would_write` and a plain-language statement that
    review writeback is off and how to turn it on for this conversation (D-03). When both are open it
    sends the dry-run flag false. The session arm arrives as an argument from the conversation and is
    never read from or written to a file or any cache — nothing about it may outlive the session. The
    env variable is read only as the kill switch above; it is never a source of the session arm, or
    the two would collapse into one gate.

    `verify_decision(intended, response)` compares `response["verified_properties"]` — **30-02's
    independent post-PATCH refetch, not the PATCH's own echo (D-19)** — against the `would_write` map
    the operator approved, and returns verified, failed, or the endpoint's own non-writing outcome
    (stale, no candidate, not flagged, refused, unsupported) with its message. A 2xx alone is never
    reported as success (Phase 28 D-14); a mismatch is reported as failed with the differing keys
    named. The client re-derives the comparison rather than trusting the response's own `verified`
    field, and a **written** decision whose `verified_properties` is absent or null reports **failed**
    — an unverifiable write is not a verified one.

    **Every function's `transport` parameter defaults to the bare `requests` MODULE and every call
    goes through `transport.post(...)` — never `transport=requests.post`, never a direct
    `requests.post(...)` (D-17, Phase 28 D-28/D-33).** `tests/test_retry_reuses_dispatch.py` scans
    every plugin script including ones not yet written; a `requests.post` default here makes these
    functions unexpected send-shaped functions and turns the suite red. **When that happens the
    tempting fix is to append this module to `_EXPECTED_SEND_SHAPED`. Do not.** That list is what
    stands between a client path and the arming gate `dispatch()`'s no-default `armed` parameter
    enforces; widening it to quiet a test is a weakening. If the guard fires, the module is wrong.
    Drive the tests through `conftest.py`'s existing `stub_module_transport_factory`; no new fixture
    and no `conftest.py` edit is needed (D-21).

    `reviewed_by` comes from the operator label in config; when it is unset the module sends a
    neutral placeholder rather than an empty string, so the audit trail always names something.

    Tests: with `ALLOW_REVIEW_SUBMIT` unset, a submit refuses with an empty call log and the refusal
    names the variable; a value table covers each near-miss; the disarm-equivalent — every path that
    records a reason or re-queues a record — proceeds with the variable unset; an unarmed submit
    performs no mutating call; an armed, env-open submit sends the dry-run flag false exactly once; a
    response whose `verified_properties` match reports verified; a response missing one approved key
    reports failed and names that key; a 2xx written decision with null `verified_properties` reports
    failed; each non-writing outcome is surfaced verbatim rather than translated into success; no
    module-level state persists an arm between two calls.
