<objective>
Make `mode: "propose"` real: run the waterfall, return the merged properties and the match
verdict, write nothing — and widen the cloud Lusha request so a name+company row can actually
be enriched.

Purpose: 36-CONTEXT.md §4 decision 1 is explicit that this must NOT be implemented by reading
properties off a `write_blocked` response, because that would make the feature depend on
`ALLOW_HUBSPOT_CREATE` staying false, and this repo arms and disarms that constant for other
reasons. The safety gate must keep doing only its own job. Decision 3 widens `Lusha Enrich` on
cloud to the identity set `lushaContactBody()` already supports and is already tested for —
a recorded decision reversal, not a bug fix.

Output: an `action: "proposed"` path that reads no `ALLOW_*` constant, `row_id`/`mode`/`match`
echoed on both object types, and a Lusha request body that matches its own module.
</objective>
