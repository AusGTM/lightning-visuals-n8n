<objective>
Close 37-07's blocking transport decision with the operator's ruling: **option-b** — the ingest lane's
CREATE payload stamps `lv_enrichment_requested = "true"`, so the already-deployed 15-minute scheduled
poller sweeps freshly created contacts on its own.

Purpose: 37-CONTEXT.md §13(b) — *"at the end of an enrichment cycle there shouldn't be an unenriched
contact or company."* 37-07 shipped `queue_handoff_ids` (the client-side read of which ids landed) and
then paused on how those ids get queued. Option-b wins because it costs nothing at run time, needs no
third arming phrase, adds no new send path, and rides Phase 36's already-scheduled deploy. HubSpot-as-
queue is the intended design for enrichment state, not a fallback.

Output: one line inside an existing create-only branch, the regenerated ingest workflow, and three
structural tests that pin the branch, the negative, and the property name.

**Scope fence.** CREATE only. Not the update/patch path. Not the enrichment lane's create node. Not
companies. Not the local dry-run template. No client-side change — `queue_handoff_ids` stays exactly as
37-07 shipped it; this plan makes the backend do the queuing so nothing has to call it for this purpose.
</objective>

<not_arming>
State this plainly in the summary, because the two look alike and are not:

- `ALLOW_HUBSPOT_CREATE` and its siblings are **write gates** — flipping one lets the backend write to
  HubSpot. The repo's disarmed-artifact grep exists to prove none is on in a committed artifact.
- `lv_enrichment_requested` is a **work-queue flag on a record** — a property the scheduled poller
  searches for. It grants no permission and opens no write path.

The stamp is emitted strictly *inside* the `action === "create"` branch, which is itself only reachable
when the create gate is already armed. So the stamp can only ever appear on a record the backend was
already permitted to create. It cannot widen the blast radius; it can only annotate what was written.
The grep must still report 0 and Task 2 asserts it.
</not_arming>
