<objective>
Make a broken batch resumable without re-spending.

Purpose (37-CONTEXT.md §13a): client-side state today is conversational and evaporates. A batch
that breaks halfway leaves the operator with no record of which rows completed, so re-running
re-spends provider credits on rows already enriched — and the operator's governing rule is that
no contact should end an enrichment cycle unenriched. `row_id` already exists, is already stable,
and is already echoed verbatim by the backend. Persisting it against a verdict is the whole fix.

Output: `scripts/run_manifest.py` — its own artifact, its own schema, its own refusal, beside
the dashboard pointer and never inside it.
</objective>

| unattended sweep -> filesystem | The sweep must remain structurally read-only; a new writing module in its import closure would change that. |
