that turn STRUCT-01/02/03/04 and INGEST-06 into runnable assertions.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| extraction artifact → validator | Untrusted content crosses here: the artifact reflects prose, a foreign JSON blob, a fetched public page, or an image, any of which the operator did not author |
| validated rows → dispatch CSV | The only data that may cross is the 7 canonical props; this is the STRUCT-01 enforcement site |
| provenance → wire | Must never cross (D-04) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-24-01 | Tampering | `write_dispatch_csv()` | high | mitigate | Canonical-prop allowlist derived from `config/column_mapping.yaml`; the function raises on any other key rather than widening the header, so a field injected into the artifact by fetched-page or image content cannot reach n8n |
| T-24-02 | Information Disclosure | provenance sidecar | medium | mitigate | Provenance exists only in the preview structure; `write_dispatch_csv()` cannot emit it; the scratch directory holding artifacts is gitignored so a session's extracted contact data never enters history (D-05) |
| T-24-03 | Spoofing | forged identity values in the artifact | medium | accept | The identity pre-flight checks presence, not truthfulness — a documented ceiling (24-RESEARCH.md question 1); downstream email verification in n8n is the actual integrity check and is out of this phase's scope |
| T-24-04 | Denial of Service | malformed artifact | low | mitigate | Per-record try/except isolation means one bad record cannot crash a batch; a malformed artifact refuses with a named code rather than partially parsing |
| T-24-SC | Tampering | package installs | low | accept | This plan installs nothing. Its dependencies (stdlib `json`/`csv`, PyYAML) were declared and audited in 23-03; 24-RESEARCH.md's Package Legitimacy Audit records that this phase adds no package |
</threat_model>
