<objective>
Give `lv_country_region_normalized` a real field-governance entry so the research/provider
value the pipeline already produces can promote under policy instead of silently falling
through to the generic `fill_blank_only` default (which only writes into a blank and never
refreshes). Close the drift gap the edit exposes: the YAML policy and its hand-mirrored JS
twin have no generator and no conformance guard today.

Purpose: the field is produced by the Lusha company normalizer and by Claude web research,
and it is consumed by ICP scoring as the geography input that drives the non-ANZ hard veto —
so it currently feeds a disqualification decision from a value the merge engine will not
maintain.

Output: one policy entry in each of the two mirrored config surfaces, threshold cases in the
JS unit tests, a yaml-vs-JS conformance test, and a deliberately re-baselined frozen fixture.
</objective>
