<objective>
Settle the two live facts Phase 22 cannot proceed without, using read-only calls only: (1) what
company `9604614548` currently holds in its ICP fields, and therefore whether an armed run would
actually exercise the Haiku-research → Sonnet-judge half of the chain the canary claims to prove;
and (2) whether this n8n Cloud instance's executions API really hands back per-node `runData`
carrying each Anthropic call's `usage`, which is the entire basis of the cost ledger's token half.

Purpose: 22-RESEARCH.md's two lowest-confidence assumptions (A1, A2) are both cheap to settle by
looking and expensive to get wrong. A canary that mechanically passes while the research gate never
fired proves nothing, and a ledger designed against a documented-but-unobserved payload shape gets
rebuilt after the one armed window has already closed.

Output: a read-only snapshot/compare tool that doubles as the neighbour-untouched verifier for the
armed run; a committed pre-canary snapshot with a research-gate prediction; a minimal cost-ledger
script whose token extraction is proven against a real execution; and a redacted fixture of that
real payload for Plan 03 to build on.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Snapshot tool → HubSpot CRM | Read-only, but pointed at live production records; a write path here would be a clobber path. |
| Ledger probe → n8n execution data | Execution payloads can contain request headers and full prompt bodies, i.e. credentials and customer data crossing into a committed fixture. |
| Committed snapshot / fixture → git history | Anything written here is permanent and reviewable by anyone with repo access. |
| Agent session → armed operations | Project policy: agents read and dry-run; arming is operator-only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-01 | Tampering | Snapshot tool acquiring a HubSpot write path | high | mitigate | The module imports only the client's read function; an acceptance grep asserts no patch/create/post call exists in its source; the portal guard refuses before any call. |
| T-22-02 | Information Disclosure | Execution fixture leaking the Anthropic key or prompt bodies into git | high | mitigate | Fixture capture is allow-list-based (node name, model, usage counters, status only), never deny-list; a redaction test reads the committed fixture and asserts the enumerated credential markers are absent. |
| T-22-03 | Information Disclosure | Snapshot artifact disclosing CRM contents beyond what the canary needs | medium | accept | The captured set is the declared enrichment properties on known test fixtures already used throughout Milestones 3-5; the portal guard prevents pointing it at another portal. |
| T-22-04 | Repudiation | A prediction based on a stale copy of the gate's vocabulary | medium | mitigate | The evidence-gated set is imported from the taxonomy module and asserted equal to it by test, so a vocabulary change cannot leave a stale prediction passing. |
| T-22-05 | Denial of Service | Probe paging the executions collection unbounded | low | mitigate | The listing mode uses a small fixed limit and is a single GET; no pagination loop is written. |
| T-22-SC | Tampering | Package-manager installs | n/a | accept | No new packages: the tooling reuses `requests`, already pinned. 22-RESEARCH.md's Package Legitimacy Audit records this as N/A, so no legitimacy checkpoint is required. |
</threat_model>
